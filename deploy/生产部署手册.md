# AIOA 生产部署手册（单机 Docker Compose · 10.0.0.12）

> 目标：把 AIOA 部署到 **10.0.0.12**，复用该机**已有**的 MySQL / Redis / Milvus，
> 由本仓库的 `deploy/docker-compose.yml` 起应用侧（后端 / agent / 前端 / nginx / MinIO / Ollama）。
> 配置模板：`deploy/.env.production`（已按这台机填好地址，只需补密钥）。

---

## 0. 部署后的拓扑与端口占用

| 组件 | 归属 | 端口 | 说明 |
|---|---|---|---|
| MySQL 8 | **复用机器上的** `mysql` 容器 | 3306（已发布） | 库 `aioa`，后端连 `10.0.0.12:3306` |
| Redis | **复用机器上的** `redis` 容器 | 6379 | 后端连 `10.0.0.12:6379` |
| Milvus standalone | **复用机器上的** `milvus-standalone` | 19530（gRPC）/ 9091（healthz·WebUI） | 后端连 `http://10.0.0.12:19530` |
| milvus-etcd / milvus-minio | 随 Milvus 自带 | 内部 / 9000-9001 | **本项目不再起第二套 Milvus** |
| nginx（本项目） | 新建 | **80 = 用户端 H5**<br>**81 = 管理端** | 两个对外入口，均由同一个 nginx 容器监听 |
| server / agent / web | 新建 | 仅容器内网 | 不直接对外 |
| MinIO（本项目，附件与知识库原文） | 新建 | 控制台 **9011**（数据口 9000 仅内网） | 9000/9001 已被 milvus-minio 占用，故用 9011 |
| Ollama（本项目，知识库语义嵌入） | 新建 | 11434 | 镜像小；**不起 vLLM**（那需要 GPU 与大磁盘） |

访问入口（部署完）：

- **用户端 H5**：`http://10.0.0.12/`　→ 租户侧账号口令统一 `User@123`（对外主入口）
- **管理端**：`http://10.0.0.12:81/`　→ 平台管理员 `admin / Admin@123`（**登录后立刻改密码**）
- Milvus WebUI（运维）：`http://10.0.0.12:9091/webui/`

## 1. 开工前：你需要准备的 4 件事

| # | 需要什么 | 用途 | 没有会怎样 |
|---|---|---|---|
| 1 | 机器上 **MySQL root 密码**（或新建专用账号，见 §4.2） | 后端连库 | 后端启动即 `Access denied` |
| 2 | 机器上 **Redis 密码**（若设了 `requirepass`；没设就留空） | 后端连 Redis | 登录/会话相关功能报错 |
| 3 | **模型 Key**（本模板 `MODEL_DEFAULT=minimax` ⇒ 首选 MiniMax；也可改用 DeepSeek / 阿里云百炼） | 真实大模型对话 | **不影响部署**：网关会静默降级为「回声模型」，链路能跑通，回答是回声 |
| 4 | 源码如何上传到服务器（Gitea 克隆 / scp / rsync，见 §3） | 构建镜像 | — |

另外建议准备：**公网 HTTPS 域名**（若要启用 Gitee 仓库联动；内网 IP 无法注册回调，见 §3 说明）。

## 2. 上服务器做一次体检（先做，别跳）

```bash
# 2.1 现有容器与端口
docker ps --format 'table {{.Names}}\t{{.Ports}}'
ss -ltnp | grep -E ':(80|81|3306|6379|9000|9001|9011|9091|11434|19530)\b' || true

# 2.2 Docker 与 compose 版本（需要 compose v2）
docker version --format '{{.Server.Version}}'; docker compose version

# 2.3 资源余量（建议可用内存 ≥ 8G、磁盘 ≥ 20G）
free -g; df -h /var/lib/docker 2>/dev/null || df -h /

# 2.4 MySQL 版本必须 ≥ 8.0
docker exec -it mysql mysql -uroot -p -e "SELECT VERSION(), @@sql_mode\G"

# 2.5 Redis 是否需要密码
docker exec -it redis redis-cli ping      # 回 PONG = 无密码；回 NOAUTH = 有密码，需填进 .env

# 2.6 Milvus：**先确认 19530 在监听**（这是后端真正要连的端口）
ss -ltn | grep ':19530' || echo '19530 未监听 ⇒ 后端会启动失败'
nc -z 10.0.0.12 19530 && echo '19530 可达'

# 2.7 Milvus 版本（原生 BM25 需要 ≥ 2.5）。
#     ⚠️ 若 9091（健康检查 / WebUI）没发布到宿主，下面两条会失败 —— **不影响后端**，跳过即可
curl -s http://10.0.0.12:9091/healthz; echo
docker inspect -f '{{.Config.Image}}' milvus-standalone
```

**体检结论要满足**：**80 与 81** / 9011 / 11434 空闲；MySQL ≥ 8.0；**19530 在监听且可达**。

> Milvus 版本拿不到时，先按默认 `AIOA_MILVUS_ENABLE_BM25=true` 起；若后端日志出现
> 「不支持 BM25 / 退回纯稠密」之类告警，把该键改 `false` 再 `docker compose up -d server`。

> ⚠️ **不要**用 `--profile milvus` 起本项目的 Milvus 栈 —— 这台机已有 `milvus-standalone`，
> 会因 19530/9091 端口与 etcd 冲突而失败。配置里 `AIOA_KB_STORE=milvus` 指的是**复用现成那套**。

## 3. 把源码放到服务器

必须包含这些目录：`server/`、`agent/`、`web/`、`user-client/`（H5 由 nginx 挂载）、`deploy/`。

```bash
# 方式 A：服务器能访问内网 Gitea 时
#   ⚠️ 10.0.0.12 与 172.16.8.249 常不在同一网段，先探通：curl -sI http://172.16.8.249:3000
sudo mkdir -p /opt && cd /opt
git clone http://172.16.8.249:3000/AI-OA/AIOA.git && cd AIOA

# 方式 B（推荐）：从开发机推（在**开发机**上执行）
rsync -av --exclude node_modules --exclude .venv --exclude target \
  ./ root@10.0.0.12:/opt/aioa/

# 方式 C：用 GitHub 克隆（需要该机可出网 + 有仓库权限）
# git clone https://github.com/liujiejie7089/AIOA.git && cd AIOA && mv AIOA /opt/aioa
```

> `.env*` 被 `.gitignore` 忽略 ⇒ **`deploy/.env` 不会随源码过去**，需要在服务器上按 §4 现场生成（推荐）。
> 源码里 `deploy/.env.production` 只有占位值，可以安全入库 / 传输。

**关于 Gitee 仓库联动**：本部署入口是私网 `http://10.0.0.12`，Gitee 无法回调、也无法登记
私网回调地址，所以 `.env.production` 里已把 `AIOA_GITEE_ENABLED` 与 `AIOA_GITEE_SYNC_ENABLED`
置为 `false`（对应功能入口会自动隐藏）。以后有公网 HTTPS 域名时再开，见 §9.3。

## 4. 生成生产配置（`deploy/.env`）

> **★ 你的 MySQL / Redis 就填在这个文件：`/opt/aioa/deploy/.env`**
> （compose **唯一**读取的变量源；该文件被 `.gitignore` 忽略，不会进 git、不会随源码传输）
>
> `deploy/.env.production` 只是模板 —— **真实口令不要写回模板**（它是入库文件）。

**具体改哪几行**（键名必须逐字符一致）：

| 你要填什么 | 生效键（改这些） | 所在小节 | 说明 |
|---|---|---|---|
| MySQL 主机 / 端口 / 库 / 账号 / 口令 | `MYSQL_HOST` `MYSQL_PORT` `MYSQL_DB` `MYSQL_USER` `MYSQL_PASSWORD` | **§1** | **compose 用这 5 个键现拼**出后端要用的 `SPRING_DATASOURCE_*` |
| Redis 主机 / 端口 / 口令 / 库号 | `REDIS_HOST` `REDIS_PORT` `SPRING_REDIS_PASSWORD` `SPRING_REDIS_DATABASE` | **§2** | 口令留空 = 该 Redis 没有 `requirepass` |
| Milvus（已按 `10.0.0.12:19530`、**无鉴权**填好，无需你改） | `AIOA_MILVUS_URI` + `AIOA_MILVUS_TOKEN`（**留空**） | §7.1 | 填了 Token 反而认证失败 |

**这些键看起来像、但对本 compose 不起作用（别浪费时间）**：

| 无效键 | 原因 |
|---|---|
| `SPRING_DATASOURCE_URL` / `_USERNAME` / `_PASSWORD`（§1） | compose 里 server 服务的同名变量被 `${MYSQL_*}` **现拼覆盖**。仅当你**不走 compose、直接 `java -jar`** 跑后端时才有效 |
| `MYSQL_ROOT_PASSWORD` / `MYSQL_DATABASE`（§1） | 本 compose **不含 mysql 服务**（MySQL 是复用的），没有任何服务读这两个键；`MYSQL_ROOT_PASSWORD` 只在 §8 备份命令里出现，而那条命令是在**外部 mysql 容器内**执行的，读的是那个容器自己的变量 |

### 4.1 复制模板 + 自动生成随机密钥

```bash
cd /opt/aioa/deploy
cp .env.production .env        # .env 已被 .gitignore 忽略

# 生成 4 类随机密钥并就地写入（JWT / 服务间密钥 / 令牌加密键 / MinIO 与 Grafana 口令）
J=$(openssl rand -base64 48)
S=$(openssl rand -base64 48)
G=$(openssl rand -base64 48)
M=$(openssl rand -base64 24)
sed -i \
 -e "s|^JWT_SECRET=.*|JWT_SECRET=${J}|" \
 -e "s|^AIOA_JWT_SECRET=.*|AIOA_JWT_SECRET=${J}|" \
 -e "s|^SERVICE_JWT_SECRET=.*|SERVICE_JWT_SECRET=${S}|" \
 -e "s|^AIOA_SERVICE_JWT_SECRET=.*|AIOA_SERVICE_JWT_SECRET=${S}|" \
 -e "s|^AIOA_GITEE_TOKEN_ENC_KEY=.*|AIOA_GITEE_TOKEN_ENC_KEY=${G}|" \
 -e "s|^AIOA_GITEA_TOKEN_ENC_KEY=.*|AIOA_GITEA_TOKEN_ENC_KEY=${G}|" \
 -e "s|^MINIO_ROOT_PASSWORD=.*|MINIO_ROOT_PASSWORD=${M}|" \
 -e "s|^MINIO_SECRET_KEY=.*|MINIO_SECRET_KEY=${M}|" \
 -e "s|^GRAFANA_ADMIN_PASSWORD=.*|GRAFANA_ADMIN_PASSWORD=${M}|" \
 .env
```

### 4.2 填 MySQL（改 `deploy/.env` 的 §1 小节）

把这 5 行改成这台机器的真实值：

```ini
MYSQL_HOST=10.0.0.12      # MySQL 所在主机：必须与后端容器**可达**（不能写 localhost/127.0.0.1）
MYSQL_PORT=3306
MYSQL_DB=aioa             # 库不存在时后端会尝试自动建（账号需有 CREATE 权限）
MYSQL_USER=root           # 建议换专用账号，见下
MYSQL_PASSWORD=真实口令     # ★唯一真正生效的口令键
```

一键写入 + 回显核对：

```bash
cd /opt/aioa/deploy
read -rsp "MySQL 口令: " DBP; echo
sed -i -e 's|^MYSQL_HOST=.*|MYSQL_HOST=10.0.0.12|' \
       -e 's|^MYSQL_PORT=.*|MYSQL_PORT=3306|' \
       -e 's|^MYSQL_DB=.*|MYSQL_DB=aioa|' \
       -e 's|^MYSQL_USER=.*|MYSQL_USER=root|' \
       -e "s|^MYSQL_PASSWORD=.*|MYSQL_PASSWORD=${DBP}|" \
       -e "s|^SPRING_DATASOURCE_PASSWORD=.*|SPRING_DATASOURCE_PASSWORD=${DBP}|" \
       -e "s|^MYSQL_ROOT_PASSWORD=.*|MYSQL_ROOT_PASSWORD=${DBP}|" .env
grep -nE '^(MYSQL_(HOST|PORT|DB|USER|PASSWORD)|SPRING_DATASOURCE_PASSWORD)=' .env   # 核对
```

> 后两个口令键（`SPRING_DATASOURCE_PASSWORD` / `MYSQL_ROOT_PASSWORD`）本 compose **不读**，
> 一起填同一个值是为了：① §4.5 自检不留占位符 ② 日后不经 compose 直接 `java -jar`、或跑 §8 备份脚本时也有值。
> 口令里若含 `|` 或 `&`，`sed` 会被它打断 —— 改用 `vim .env` 手工填。

**（推荐，可选）改用专用数据库账号**，避免后端用 root：

```bash
docker exec -it mysql mysql -uroot -p <<'SQL'
CREATE DATABASE IF NOT EXISTS aioa DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'aioa'@'%' IDENTIFIED BY '换成强密码';
GRANT ALL PRIVILEGES ON aioa.* TO 'aioa'@'%';
FLUSH PRIVILEGES;
SQL
# 然后把 .env 的 §1 改成专用账号 —— **只改这两个键**：
#   MYSQL_USER=aioa
#   MYSQL_PASSWORD=换成强密码
# 注意：专用账号没有建库权限 ⇒ 上面那条 CREATE DATABASE 必须先执行
#       （否则 URL 里的 createDatabaseIfNotExist=true 对它无效）
```

### 4.3 填 Redis（改 `deploy/.env` 的 §2 小节）

```ini
REDIS_HOST=10.0.0.12          # Redis 所在主机（同样**不能**写 localhost）
REDIS_PORT=6379
SPRING_REDIS_PASSWORD=         # ★没设 requirepass 就**留空**；设了才填
SPRING_REDIS_DATABASE=0
```

```bash
cd /opt/aioa/deploy
sed -i -e 's|^REDIS_HOST=.*|REDIS_HOST=10.0.0.12|' \
       -e 's|^REDIS_PORT=.*|REDIS_PORT=6379|' .env
# 仅当体检 2.5 回 NOAUTH（= 该 Redis 有密码）时，才执行下面这行：
sed -i 's|^SPRING_REDIS_PASSWORD=.*|SPRING_REDIS_PASSWORD=换成密码|' .env
grep -nE '^(REDIS_HOST|REDIS_PORT|SPRING_REDIS_(PASSWORD|DATABASE))=' .env   # 核对
```

### 4.4 填模型 Key（可跳过，跳过就是回声模型）

```bash
# ★ 本模板 MODEL_DEFAULT=minimax，所以**首选填 MiniMax**（在管理端「模型管理」里配过的那把 Key）
sed -i "s|^MINIMAX_API_KEY=.*|MINIMAX_API_KEY=你的key|" .env
# 改用 DeepSeek：填 DEEPSEEK_API_KEY，并把 MODEL_DEFAULT 改成 deepseek
sed -i "s|^DEEPSEEK_API_KEY=.*|DEEPSEEK_API_KEY=sk-你的key|" .env   # 仅在改用 deepseek 时执行
# 改用通义千问：填 DASHSCOPE_API_KEY，并把 MODEL_DEFAULT 改成 dashscope
# 注意：Key 与 MODEL_DEFAULT 必须成对改，只改一个 ⇒ 默认模型读不到 Key ⇒ 静默降级 echo（不报错）
```

### 4.5 自检：还有哪些没填

```bash
# 只列「真占位」；文件顶部说明注释里也含 CHANGE_ME__ 字样，用 grep -v ':#' 排掉
grep -n 'CHANGE_ME__' .env | grep -v ':#'     # 走完 §4.1+§4.2 后应当**无输出**
bash -c 'set -a; . ./.env; set +a; echo "加载 OK，键数=$(env | grep -cE "^(AIOA_|MYSQL_|SPRING_|REDIS_|MINIO_|JWT_|MODEL_|VLLM_|OLLAMA_|GRAFANA_)")"'
```

> 本模板共有 **12 处真占位**：9 处随机密钥（§4.1 一次 sed 全部替换）+ 3 处同一个数据库口令
> （`MYSQL_PASSWORD` / `SPRING_DATASOURCE_PASSWORD` / `MYSQL_ROOT_PASSWORD`，§4.2 一次 sed 全部替换）。
> 文件顶部注释里另有若干行提到 `CHANGE_ME__`，那是说明文字，不是待填项。

## 5. 启动

```bash
cd /opt/aioa/deploy

# ① 应用侧（minio + server + agent + web + nginx）
docker compose up -d --build

# ② 知识库语义嵌入要用的 Ollama（单独一个 profile，不会连带拉 vLLM 的大镜像）
docker compose --profile ollama up -d
docker exec aioa-ollama ollama pull quentinz/bge-small-zh-v1.5   # 512 维，约 48MB
```

启动顺序说明：**Milvus 必须在 server 之前在线**（`AIOA_KB_STORE=milvus` 时连不上 Milvus，
后端会**直接启动失败**，这是刻意设计：宁可起不来，也不要静默返回空结果）。

等待后端就绪（首次要跑 Flyway V1–V61 共 61 个迁移，约 1–3 分钟）：

```bash
docker compose ps                       # 期望 server 变成 healthy
docker compose logs -f server           # 看到 Started AioaApplication 即成功
```

## 6. 验收（8 条，全过就是部署成功）

```bash
# 1) 容器状态
cd /opt/aioa/deploy && docker compose ps

# 2) 后端健康（server 不发布端口，从容器健康检查读，不依赖镜像里有没有 curl）
docker inspect --format '{{.State.Health.Status}}' aioa-server   # 期望 healthy

# 3) 用户端 H5（80 端口，对外主入口）
curl -s -o /dev/null -w 'h5        %{http_code}\n' http://127.0.0.1/
curl -s http://127.0.0.1/ | grep -q 'aioa_session' && echo 'h5 内容 OK（含 aioa_session）' || echo 'h5 内容异常'
# 4) 管理端（81 端口）
curl -s -o /dev/null -w 'admin-ui  %{http_code}\n' http://127.0.0.1:81/
# ⚠️ 别用 200 当「页面正常」的判据：80 的 location / 是 try_files 回退到 H5，
#    任意路径都会回 200。判断是否真的是那套页面，要看内容（第 3 条那句 grep）。
# 5) 平台管理员登录（返回里应含 accessToken）
curl -s http://127.0.0.1/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123"}' | head -c 200; echo
# 6) 知识库档位（应为 milvus + http + 512）
TOKEN=$(curl -s http://127.0.0.1/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123"}' | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1/api/v1/kb/store
# 7) 容器 → 宿主服务连通性（MySQL / Redis / Milvus）
docker compose exec server bash -c '
  for hp in 10.0.0.12:3306 10.0.0.12:6379 10.0.0.12:19530; do
    h=${hp%:*}; p=${hp#*:}
    timeout 3 bash -c "cat < /dev/null > /dev/tcp/$h/$p" && echo "$hp OK" || echo "$hp FAIL"
  done'
# 8) 浏览器：用户端 http://10.0.0.12/ 与管理端 http://10.0.0.12:81/
#    管理端用 admin/Admin@123 登录，能进工作台、菜单完整
```

### 6.1 部署后系统自带的账号（Flyway 首启播种，口令见下表）

首次启动只会播种 **3 个租户**：平台基线租户 + 两个示例租户（迁移 `V2__seed.sql` / `V24__enterprise_org_and_workflow.sql`）。
其余租户请用平台管理员在管理端自助开通（开通时会自动触发假种 / 审批流播种器）。

| 入口 | 租户名称（H5 登录必填） | 账号 | 口令 | 角色 |
|---|---|---|---|---|
| 管理端 **`:81`** `/` | 平台管理员**不填**租户 | `admin` | `Admin@123` | 平台管理员（**登录后立刻改密**） |
| H5 **`:80`** `/` | 默认租户 | `admin` | `Admin@123` | 平台管理员 |
| H5 **`:80`** `/` | 默认租户 | `zhangsan` | `User@123` | 普通成员（无管理权限） |
| H5 **`:80`** `/` | 某某市某某区大数据管理局 | `dsj_admin` | `User@123` | 租户管理员 |
| H5 **`:80`** `/` | 某某市某某区大数据管理局 | `fagai_admin` | `User@123` | 机构管理员 |
| H5 **`:80`** `/` | 某某市某某区大数据管理局 | `fagai_liu` | `User@123` | 部门负责人（可审批） |
| H5 **`:80`** `/` | 某某市某某区卫生健康局 | `wjj_admin` | `User@123` | 租户管理员 |

> 租户侧口令统一 `User@123`。H5 登录时**租户名称必须与上表逐字一致**（如「某某市某某区大数据管理局」），
> 填错或留空会返回「租户不存在」，不是密码错误。

知识库端到端（可选）：管理端 → 知识库 → 上传一个 `.txt` → 等切片完成 → 在检索框搜其中关键词，
应返回命中片段（说明 embedding + Milvus 混合检索都通了）。

## 7. 常见故障对照

| 现象 | 根因 | 处置 |
|---|---|---|
| `server` 容器反复重启，日志有 **`Milvus 不可用，应用拒绝启动`** | Milvus 不可达/URI 错 | `curl http://10.0.0.12:9091/healthz`；确认 `.env` 的 `AIOA_MILVUS_URI`（容器内访问宿主要用 **IP**，不能用 `localhost`） |
| 日志 `Access denied for user` | DB 密码错/账号无权限 | 重填 §4.2；确认 `SPRING_DATASOURCE_USERNAME` 与密码对应 |
| 日志 `Communications link failure` | 3306 不可达 | `docker compose exec server bash -c 'cat < /dev/null > /dev/tcp/10.0.0.12/3306'`，失败则查宿主防火墙/iptables |
| 页面能开但所有接口报 502 | server 未 healthy | 看 `docker compose logs server`，先修后端 |
| **对话一直回「回声」** | 模型 Key 没填（或 Key 与 `MODEL_DEFAULT` 不配对）⇒ 网关**静默降级 echo**（不是报错） | 按 §4.4 填**与 `MODEL_DEFAULT` 同名**的 Key（本模板默认 `MINIMAX_API_KEY`），再 `docker compose up -d agent`（**不是 restart**，见 §8） |
| 上传/检索报 embedding 错误 | Ollama 没起 / 模型没 pull | `docker compose --profile ollama up -d` + `docker exec aioa-ollama ollama pull quentinz/bge-small-zh-v1.5` |
| 上传报 `fetch failed`/超时 | 嵌入服务地址错 | `.env` 里 `AIOA_KB_EMBEDDING_URL=http://ollama:11434/api/embeddings`（容器内服务名） |
| `port is already allocated` | 端口被占 | 本项目已避开 19530/9091/9000/9001；若 **80 或 81** 被占，改 compose 里 nginx 的 `"80:80"` / `"81:81"`（冒号左边是宿主端口，右边必须保持 80/81，否则容器内 nginx 没有对应监听） |
| 管理端菜单里没有「仓库/项目」模块 | `AIOA_GITEE_ENABLED=false`（内网预期） | 见 §9.3 |
| 换嵌入模型后检索命中异常 | 集合维度不可改 | 必须换新集合名（`kb_chunk_v2`）+ 开 `REEMBED`/`BACKFILL`，见 §9.2 |

## 8. 日常运维

```bash
cd /opt/aioa/deploy

docker compose ps                       # 状态
docker compose logs -f --tail=100 server agent
docker compose down                     # 停（数据在卷里，不会丢）
git pull && docker compose up -d --build   # 升级
```

### 8.1 ⚠️ 改了 `.env` 之后：用 `up -d`，不要用 `restart`

```bash
docker compose up -d server agent       # ✅ 会按新变量**重建**容器
docker compose restart server           # ❌ 无效：只重启进程，环境变量还是旧的
```

原因：`docker compose restart` 是「把同一个容器停掉再启动」，**不重新读取 `.env`、也不重新渲染服务定义**，
容器里的环境变量保持原样。而 `docker compose up -d` 会把渲染后的服务配置与运行中容器做哈希比对，
**发现变化就自动重建**（这才是你要的效果）。

- **不需要** `--force-recreate`：上面的哈希比对已经能识别 `.env` 变化；`--force-recreate` 只是在
  「配置哈希没变但你想强制换一个容器」时用（例如容器内文件被手工改脏了）。
- 判断是否真的生效：`docker exec aioa-server printenv <变量名>`，或直接看 `docker inspect` 的
  `Config.Env`。**只看「容器重启成功了」不算生效。**
- 换了 DB / Redis / Milvus 地址、模型 Key、`AIOA_KB_*` 档位等**任何环境变量**都走这条。

```bash
# 备份（三件套：库 + 对象存储 + 配置）
docker exec mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" aioa' > /root/aioa-$(date +%F).sql
tar czf /root/aioa-env-$(date +%F).tgz -C /opt/aioa deploy/.env
# MinIO 数据在命名卷 aioa_miniodata（附件/知识库原文）；Milvus 索引**不必备份**，可重建
```

**回滚向量库**：把 `.env` 里 `AIOA_KB_STORE` 改回 `mysql` 再 `docker compose up -d server`
（MySQL 始终保存文档与切片，Milvus 只是可重建的索引副本）。

## 9. 这次没做 / 以后怎么做

### 9.1 本地大模型（可选，需要 GPU）
`docker compose --profile model up -d` 会额外起 vLLM（镜像大、需 GPU）。没有 GPU 就别开，
用云端 Key（DeepSeek/通义）即可。

### 9.2 从「哈希向量」升级为「语义向量」（这套配置已经是语义档）
当前 `.env` 是 `AIOA_KB_EMBEDDING_PROVIDER=http` + `quentinz/bge-small-zh-v1.5`(512 维)，
已经是语义向量。**只有**当你换模型（维度也变）时才需要：

```bash
# 例：换成 1024 维的 bge-m3
docker exec aioa-ollama ollama pull bge-m3
sed -i -e 's|^AIOA_KB_EMBEDDING_MODEL=.*|AIOA_KB_EMBEDDING_MODEL=bge-m3|' \
       -e 's|^AIOA_KB_EMBEDDING_DIMS=.*|AIOA_KB_EMBEDDING_DIMS=1024|' \
       -e 's|^AIOA_MILVUS_DIMS=.*|AIOA_MILVUS_DIMS=1024|' \
       -e 's|^AIOA_MILVUS_COLLECTION=.*|AIOA_MILVUS_COLLECTION=kb_chunk_v2|' \
       -e 's|^AIOA_KB_REEMBED_ON_START=.*|AIOA_KB_REEMBED_ON_START=true|' \
       -e 's|^AIOA_MILVUS_BACKFILL=.*|AIOA_MILVUS_BACKFILL=true|' .env
docker compose up -d server      # 启动时先重算向量、再回填新集合
# ⚠️ 跑完后把这两个开关改回 false 并重启（否则每次启动都全量重算）
```

### 9.3 启用 Gitee / Gitea 仓库联动（需要公网 HTTPS 域名）
1. 准备公网域名（如 `aioa.example.com`）并解析到网关，配好 HTTPS（可在前面再放一层 nginx / 宝塔）。
2. 在托管方（Gitee「设置→第三方应用」/ 自建 Gitea）创建 OAuth 应用，回调地址填
   `https://<域名>/api/v1/gitee/bind/callback`。
3. `.env` 里改：`PUBLIC_BASE_URL` / `AIOA_GITEE_REDIRECT_URI` / `AIOA_GITEE_WEBHOOK_BASE_URL` /
   `AIOA_GITEE_BIND_RETURN_URL` 四处改成新域名，填 `CLIENT_ID`、`CLIENT_SECRET`，
   再把 `AIOA_GITEE_ENABLED=true`、`AIOA_GITEE_SYNC_ENABLED=true`。
4. `docker compose up -d server`。⚠️ Webhook 地址必须**托管方能访问到**，否则回调静默失效。

### 9.4 HTTPS
本 compose 只暴露 80。生产建议前置一层 nginx/宝塔终止 TLS，或把证书挂进
`deploy/nginx/` 的容器并加 `listen 443`。
