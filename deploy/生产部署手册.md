# AIOA 生产部署手册（单机 Docker Compose · 应用机 10.0.0.12）

> 目标：把 AIOA 的**应用侧**部署到 **10.0.0.12**，由本仓库的 `deploy/docker-compose.yml`  
> 起 server / agent / web / nginx / MinIO / Ollama。  
> **MySQL / Redis / Milvus 都不在这台机上、也不由本 compose 托管**，全部按外部地址直连。  
> 配置模板：`deploy/.env.production`（地址已按本次环境填好，只需补口令 / Key，见 §4.0）。

> ### ★ 2026-09-21 现场复核结论（照下文执行前先读这四行）
>
> ① **应用机拉不到 Docker Hub**（`failed to resolve reference "docker.io/minio/minio:latest" … i/o timeout`、
>    `ping baidu.com` 100% 丢包）⇒ 镜像**不能直接 pull**，按 **§5.0** 在「国内加速器」与「离线搬运包」之间二选一。
>
> ② 上一轮 `.env` 里 **MySQL / Redis 口令根本没写进去**：自检打印的 `22` / `25` 是**占位符本身的长度**
>    （`CHANGE_ME__db-password` = 22 字符、`CHANGE_ME__redis-password` = 25 字符），**不是你的口令长度**；
>    `MINIMAX_API_KEY` 也仍是空 —— 旧检查 `grep -c '^MINIMAX_API_KEY=.\+'` 把该行 `=` 后面的**填充空格**
>    当成了值，是**假通过**（本次已换成会真报错的自检）。
>
> ③ **写口令不要再用 `sed -i "s|^KEY=.*|KEY='${P}'|"`**：值里含 `|` 会让整条命令失败
>    （`sed: -e expression #1, char NN: unknown option to 's'`，屏幕上只有一行报错、值**静默没写**）；
>    值里含 `&` 更糟 —— sed 会把 `&` 展开成「匹配到的整段原文」，**不报错但值被改坏**。
>    统一改用 `deploy/ops/set-secrets.py`（按行整体重写，`$ | & # ! ' " \` 与空格、中文全都安全）。
>
> ④ **三台机器的角色**：本地（改代码 / 推代码）→ **隧道机 `219.151.186.24`**（唯一能碰到真实服务器的跳板）
>    → **真实服务器 `10.0.0.12`（无外网）**。公网直连 `10.0.0.12:22` 不通，下面的命令都在**真实服务器自己的 shell** 里跑。
>
> ⑤ **真实服务器上已有 5 个容器，但一个都不是本项目要的**（2026-09-21 `docker ps` 实测）：
>    `milvus:v2.6.14` / `etcd:v3.5.25` / `mongo:latest` / `apache/rocketmq:4.9.6` ×2。
>    其中只有 **Milvus 有用**（外挂复用，`AIOA_MILVUS_URI=http://10.0.0.12:19530`；`v2.6.14 ≥ 2.5` ⇒
>    `AIOA_MILVUS_ENABLE_BM25=true` 可保留）；`etcd` 是 Milvus 的配套；
>    **`mongo` 与 `rocketmq` 属别的系统** —— 本项目源码里搜不到任何 mongo/rocketmq/kafka 依赖，别去动它们。
>    这些容器占的是 10909/10911/9876/19530/2379/2380/27017，**与我们要的 80/81/9011/11434 不冲突**。
>
>    ⚠️ **`docker ps` 只列「运行中的容器」，不是「镜像清单」** —— 机器上可能有没在跑的 `nginx`/`minio` 镜像。
>    判断够不够**只能**看 `docker images`（见下方清单 A 的 ① 与 ⑤）。

## 全流程执行清单（照顺序打勾）

镜像怎么进来是唯一的不确定项，所以**先做 A，再按 A 的结果决定走 A1 / A2 / C**。

### A · 真实服务器：先体检（**只读**，整段粘贴，不依赖仓库是新是旧）

```bash
echo "=== ① 已有镜像 ==="; docker images --format '{{.Repository}}:{{.Tag}}  {{.Size}}' | sort
echo "=== ② docker 实际生效的 registry 镜像源 ==="; docker info 2>/dev/null | sed -n '/Registry Mirrors/,/^[A-Z]/p' | head -8
echo "=== ③ daemon.json ==="; cat /etc/docker/daemon.json 2>/dev/null || echo '(无)'
echo "=== ④ 出口通断（200/301/302 = 通；000 = 不通）==="
for u in https://www.baidu.com https://mirrors.aliyun.com https://registry-1.docker.io/v2/ \
         https://docker.m.daocloud.io/v2/ http://172.16.8.249:3000; do
  printf '  %-44s %s\n' "$u" "$(curl -sS -m 6 -o /dev/null -w '%{http_code}' "$u" 2>/dev/null || echo 000)"
done
echo "=== ⑤ 缺哪些镜像 ==="
for i in minio/minio:latest nginx:1.27-alpine aioa-server aioa-agent aioa-web ollama/ollama:latest; do
  docker image inspect "$i" >/dev/null 2>&1 && echo "  ✅ $i" || echo "  ❌ $i"
done
echo "=== ⑥ .env 占位符残留（这一行应无输出）==="
grep -nE 'CHANGE_ME__' /opt/aioa/deploy/.env 2>/dev/null | grep -v ':#' || echo "  (无残留)"
echo "=== ⑦ 我们要的端口是否空闲（80/81/9011/11434）==="
ss -lntp 2>/dev/null | grep -E ':(80|81|9011|11434)\b' || echo "  (全空闲 ✅)"
```

> ⚠️ **① 与 ⑤ 看的是 `docker images`（镜像），不是 `docker ps`（容器）** —— 机器上可能有没在跑的
> `nginx` / `minio` 镜像，用 `docker ps` 判断会误判成「什么都没有」，白搬一个包。
> `aioa-server` / `aioa-agent` / `aioa-web` 这三个是本项目代码构建出来的，**任何机器上都不会现成存在**。

仓库若已是最新，等价于跑 `bash deploy/ops/host-check.sh`（更全：git 版本、加速器逐个通断、镜像齐备度）。

**按 ②③④ 的结果定路**：

| 情况 | 走法 |
| --- | --- |
| ②③ 里有**内网 registry**（harbor / nexus / `registry-mirrors` 指向 `172.x`/`10.x`），且探得通 | **最省事**：能直接 pull 基础镜像 ⇒ 直接 `docker compose --profile ollama up -d --build`，跳过 C 与 D1–D2 |
| ④ 里 `baidu.com` / `aliyun` 返回 200/301，只有 Docker Hub 不通 | 配国内加速器 ⇒ **A2 / §5.0-A** |
| ④ 全部 000 且无内网 registry | 离线搬运 ⇒ **C → D** |

## 2. 上服务器做一次体检（先做，别跳）

> **一条命令代替本节全部**（只读，不改任何东西，含外网/加速器通断与镜像齐备度）：
>
> ```bash
> cd /opt/aioa && bash deploy/ops/host-check.sh
> ```
>
> 下面是它覆盖的逐项手工版本，想单独看某一项时用。

```bash
# 2.1 应用机现有容器与端口（MySQL / Redis 不在本机，这里看不到它们）
docker ps --format 'table {{.Names}}\t{{.Ports}}'
ss -ltnp | grep -E ':(80|81|9000|9001|9011|11434|19530)\b' || true

# 2.2 Docker 与 compose 版本（需要 compose v2）
docker version --format '{{.Server.Version}}'; docker compose version

# 2.3 资源余量（建议可用内存 ≥ 8G、磁盘 ≥ 20G）
free -g; df -h /var/lib/docker 2>/dev/null || df -h /

# 2.4 ★ 外部 MySQL：连通性 + 版本必须 ≥ 8.0
#     ⚠️ 本机没有 mysql 容器，**别用 `docker exec -it mysql`**（会报 no such container）
mysql -h 10.0.0.5 -P 13049 -u aioa -p -e "SELECT VERSION(), @@sql_mode\G"
# 只看端口通不通（不需要客户端）：nc -z 10.0.0.5 13049 && echo 'MySQL 13049 可达'

# 2.5 ★ 外部 Redis：**本次有口令**，-a 后面填你的口令
redis-cli -h 10.0.0.7 -p 6379 -a '<你的Redis口令>' ping        # 期望 PONG
# 只看端口：nc -z 10.0.0.7 6379 && echo 'Redis 6379 可达'

# 2.6 ★ Milvus：先确认 19530 可达（这是后端真正要连的端口）
nc -z 10.0.0.12 19530 && echo 'Milvus 19530 可达'

# 2.7 Milvus 版本（原生 BM25 需要 ≥ 2.5）。
#     ⚠️ 若 9091（健康检查 / WebUI）没发布出来，下面这条会失败 —— **不影响后端**，跳过即可
curl -s --max-time 3 http://10.0.0.12:9091/healthz; echo
```

> 应用机若没装 `mysql` / `redis-cli`，可以借一次性容器探（**不会**在应用机起服务）：
>
> ```bash
> docker run --rm mysql:8.0 mysql -h10.0.0.5 -P13049 -uaioa -p -e 'SELECT 1'
> docker run --rm redis:7 redis-cli -h 10.0.0.7 -a '<你的Redis口令>' ping
> ```
>
> ⚠️ **但本机拉不到 Docker Hub 时这两条会挂住**（卡在 `Unable to find image … locally` 然后超时，正是本次现场遇到的）。
> 这种情况下**不要**用容器探，改用纯 socket 探，不依赖任何镜像：
>
> ```bash
> for hp in 10.0.0.5:13049 10.0.0.7:6379 10.0.0.12:19530; do
>   h=${hp%:*}; p=${hp#*:}
>   timeout 3 bash -c "cat < /dev/null > /dev/tcp/$h/$p" 2>/dev/null \
>     && echo "✅ $hp 可达" || echo "❌ $hp 不通"
> done
> ping -c2 10.0.0.5 >/dev/null 2>&1 && echo 'ICMP 10.0.0.5 通' || echo 'ICMP 不通（不代表 TCP 不通）'
> ```

**体检结论要满足**：**80 与 81** / 9011 / 11434 空闲；MySQL `10.0.0.5:13049` 连得上且 ≥ 8.0；  
Redis `10.0.0.7:6379` 回 `PONG`；Milvus `19530` 可达。

> Milvus 版本拿不到时，先按默认 `AIOA_MILVUS_ENABLE_BM25=true` 起；若后端日志出现  
> 「不支持 BM25 / 退回纯稠密」之类告警，把该键改 `false` 再 `docker compose up -d server`。

> ⚠️ **不要**用 `--profile milvus` 起本项目的 Milvus 栈 —— 本环境用的是**外部现成的 Milvus**，  
> `AIOA_KB_STORE=milvus` 指的是「连过去」，不是「在本机起一套」。起了会白拉镜像、并与外部实例混淆。

## 3. 把源码放到服务器

必须包含这些目录：`server/`、`agent/`、`web/`、`user-client/`（H5 由 nginx 挂载）、`deploy/`。

```bash
# 方式 A：服务器能访问内网 Gitea 时
#   ⚠️ 10.0.0.12 与 172.16.8.249 常不在同一网段，先探通：curl -sI http://172.16.8.249:3000
sudo mkdir -p /opt && cd /opt
git clone http://172.16.8.249:3000/AI-OA/AIOA.git && cd AIOA

# 方式 B（推荐）：从开发机推（在**开发机**上执行）
rsync -av --exclude node_modules --exclude .venv --exclude target \
  ./ root@10.0.0.12:/opt/aioa/

# 方式 C：用 GitHub 克隆（需要该机可出网 + 有仓库权限）
# git clone https://github.com/liujiejie7089/AIOA.git && cd AIOA && mv AIOA /opt/aioa
```

> ⚠️ **传法与 `.env` 的关系**（`.env` 被 `.gitignore` 忽略，里面是真实口令）：
>
> - **方式 B（rsync）会连 `deploy/.env` 一起带上** —— 你本机这份**已填好**（10.0.0.5:13049 的库、  
>   10.0.0.7 的 Redis、MiniMax Key、以及已生成的随机密钥）⇒ 传上去**直接可用**，  
>   §4.1~§4.4 全部可跳过，只做 §4.5 自检即可。
> - **方式 A / C（git clone）不会带 `.env`** ⇒ 必须在服务器上按 §4 现场填一遍。
>
> 源码里的 `deploy/.env.production` 只有占位值，可以安全入库 / 传输。

**关于 Gitee 仓库联动**：本部署入口是私网 `http://10.0.0.12`，Gitee 无法回调、也无法登记  
私网回调地址，所以 `.env.production` 里已把 `AIOA_GITEE_ENABLED` 与 `AIOA_GITEE_SYNC_ENABLED`  
置为 `false`（对应功能入口会自动隐藏）。以后有公网 HTTPS 域名时再开，见 §9.3。

| Redis 主机 / 端口 | `10.0.0.7` / `6379`                    | §2                         |
| Redis 口令      | 你提供的那串（含 `!` ⇒ 建议单引号）                  | §2 `SPRING_REDIS_PASSWORD` |
| 模型 Key        | MiniMax（`MODEL_DEFAULT=minimax`）       | §5 `MINIMAX_API_KEY`       |
| Milvus        | `10.0.0.12:19530`、**无鉴权** ⇒ Token 留空   | §7.1                       |

**两条路径，二选一**：

- **路径 1（推荐，零手填）**：直接用它已填好的 `deploy/.env` —— rsync（方式 B）会自动带上，  
  或 `scp deploy/.env root@10.0.0.12:/opt/aioa/deploy/.env`。⇒ **跳过 §4.1~§4.4**，只跑 §4.5 自检。
- **路径 2（在服务器上从模板手填）**：`cp .env.production .env`，再按 §4.1 → §4.2 → §4.3 → §4.4 逐节填。

**生效键 vs 无效键**（分不清会白改）：

| 你要填什么               | 生效键（改这些）                                                                  | 所在节    | 说明                                                |
| ------------------- | ------------------------------------------------------------------------- | ------ | ------------------------------------------------- |
| MySQL 主机/端口/库/账号/口令 | `MYSQL_HOST` `MYSQL_PORT` `MYSQL_DB` `MYSQL_USER` `MYSQL_PASSWORD`        | **§1** | compose 用这 5 个键**现拼**出后端要用的 `SPRING_DATASOURCE_*` |
| Redis 主机/端口/口令/库号   | `REDIS_HOST` `REDIS_PORT` `SPRING_REDIS_PASSWORD` `SPRING_REDIS_DATABASE` | **§2** | 本次**有口令**，必须填                                     |
| Milvus（已填好，无需你改）    | `AIOA_MILVUS_URI` + `AIOA_MILVUS_TOKEN`（**留空**）                           | §7.1   | 填了 Token 反而认证失败                                   |

| 看起来像、但本 compose **不读**（别浪费时间）                           | 原因                                                                                       |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `SPRING_DATASOURCE_URL` / `_USERNAME` / `_PASSWORD`（§1） | server 服务的同名变量被 `${MYSQL_*}` **现拼覆盖**；仅当**不走 compose、直接 `java -jar`** 时才有效               |
| `MYSQL_ROOT_PASSWORD` / `MYSQL_DATABASE`（§1）            | 本 compose **不含 mysql 服务**（MySQL 在外部主机），没有服务读它们；本次也没拿到 root 口令 ⇒ `MYSQL_ROOT_PASSWORD` 留空 |
| `SPRING_REDIS_HOST` / `_PORT`（§2）                       | 同样被 `${REDIS_*}` 现拼覆盖                                                                    |

> ⚠️ **值里的特殊字符**：含 `$` **必须加单引号**（`$` 是 compose 的插值符，裸写或双引号会把口令吃掉）；  
> 含 `!` 建议也单引号（交互式 bash 会做历史展开）；含空格 / `&` / `<` `>` / `|` / `*` 用双引号。

### 4.1 复制模板 + 自动生成随机密钥

```bash
cd /opt/aioa/deploy
cp .env.production .env        # .env 已被 .gitignore 忽略

# 生成 4 类随机密钥并就地写入（JWT / 服务间密钥 / 令牌加密键 / MinIO 与 Grafana 口令）
J=$(openssl rand -base64 48)

M=$(openssl rand -base64 24)

 -e "s|^AIOA_JWT_SECRET=.*|AIOA_JWT_SECRET=${J}|" \
 -e "s|^SERVICE_JWT_SECRET=.*|SERVICE_JWT_SECRET=${S}|" \
 -e "s|^AIOA_SERVICE_JWT_SECRET=.*|AIOA_SERVICE_JWT_SECRET=${S}|" \
 -e "s|^AIOA_GITEE_TOKEN_ENC_KEY=.*|AIOA_GITEE_TOKEN_ENC_KEY=${G}|" \
 -e "s|^AIOA_GITEA_TOKEN_ENC_KEY=.*|AIOA_GITEA_TOKEN_ENC_KEY=${G}|" \
 -e "s|^MINIO_ROOT_PASSWORD=.*|MINIO_ROOT_PASSWORD=${M}|" \
 -e "s|^MINIO_SECRET_KEY=.*|MINIO_SECRET_KEY=${M}|" \
 -e "s|^GRAFANA_ADMIN_PASSWORD=.*|GRAFANA_ADMIN_PASSWORD=${M}|" \

```


### 4.2 填 MySQL（`deploy/.env` 的 §1 小节）

要点（**端口 13049**、账号 `aioa`）：

```ini
MYSQL_HOST=10.0.0.5
MYSQL_PORT=13049            # ★非默认端口，最容易漏
MYSQL_DB=aioa
MYSQL_USER=aioa             # 非 root ⇒ 需对 aioa 库有 DDL 权限
MYSQL_PASSWORD='你的口令'    # ★唯一真正生效的口令键；含 $ 必须单引号
```

一键写入 + 回读校验（**用脚本，别用 sed** —— 原因见文首现场结论 ③）：

```bash
cd /opt/aioa

# 方式一：交互式，逐项输入（输入不回显，两次确认）
python3 deploy/ops/set-secrets.py --only mysql

# 方式二：先把口令读进环境变量（不进 shell 历史、不进 ps），再由脚本写入
read -rsp 'MySQL 口令: ' MYSQL_PASSWORD; echo
export MYSQL_PASSWORD
python3 deploy/ops/set-secrets.py --only mysql --from-env
```

脚本会：按行整体重写 `MYSQL_PASSWORD` 与 `SPRING_DATASOURCE_PASSWORD`（同名值一并改，避免残留占位符）、
自动加最稳的引号、**回读校验长度是否与输入一致**，最后用 `docker compose config` 核对**容器真正会收到的值**：

```
  MYSQL_PASSWORD               写入 len=17   读回 len=17   ✅ 一致
  MYSQL_PASSWORD               ✅ 容器将收到 len=17（服务 server）
```

地址三项（`MYSQL_HOST/PORT/DB/USER`）模板里**已经是对的**（`10.0.0.5` / `13049` / `aioa` / `aioa`），
不用改；想核对一眼：

```bash
grep -nE '^MYSQL_(HOST|PORT|DB|USER)=' deploy/.env
```

顺带把 §1 里**不生效**的那三行也改成一致值（可选；只为「日后不经 compose 直接 `java -jar`」时也对）：  
`SPRING_DATASOURCE_USERNAME="aioa"` / `SPRING_DATASOURCE_PASSWORD='你的口令'` /  
`SPRING_DATASOURCE_URL` 里的 `IP:端口` 改为 `10.0.0.5:13049`  
（URL 含 `&`，用 sed 要写成 `\&`，嫌麻烦就 `vim .env` 手改这两处）。

> `MYSQL_ROOT_PASSWORD` / `MYSQL_DATABASE` 本 compose **不读**（无 mysql 服务）⇒ 留空即可。

**账号权限自检**（本次 `aioa` 非 root，Flyway 首启要建表 DDL）：

```bash
docker run --rm mysql:8.0 mysql -h10.0.0.5 -P13049 -uaioa -p -e "SHOW DATABASES LIKE 'aioa';"
docker run --rm mysql:8.0 mysql -h10.0.0.5 -P13049 -uaioa -p -e "SHOW GRANTS FOR CURRENT_USER();"
```



> 库不存在且账号无建库权限时，先在 MySQL 侧建库：  
> `CREATE DATABASE aioa DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`

### 4.4 填模型 Key（**必填**；留空 ⇒ 静默降级「回声」，不报错）

```bash
cd /opt/aioa
read -rsp 'MiniMax API Key: ' MINIMAX_API_KEY; echo
export MINIMAX_API_KEY
python3 deploy/ops/set-secrets.py --only minimax --from-env
```

> ⚠️ **别再用 `grep -c '^MINIMAX_API_KEY=.\+' .env` 判断是否填好** —— 模板该行 `=` 后面有一串**对齐空格**
> 和行尾注释，`.\+` 会匹配到那些空格，**永远返回 1**（假通过）。要判断就只看「值是否为空」：
> `grep -nE '^MINIMAX_API_KEY=[^[:space:]]' deploy/.env`（**应当有输出**），或直接用
> `python3 deploy/ops/set-secrets.py --check`（它会告诉你容器实际会收到多长的值）。

> `MODEL_DEFAULT=minimax`（§5）必须与所填 Key **成对**：若改用 DeepSeek，就要同时填  
> `DEEPSEEK_API_KEY` 并把 `MODEL_DEFAULT` 改成 `deepseek`。只改一个 ⇒ 默认模型读不到 Key  
> ⇒ **静默降级 echo**（不报错，现象是「回答一直是回声」）。

### 4.5 自检：还有哪些没填（**一条命令**）

```bash
cd /opt/aioa
python3 deploy/ops/set-secrets.py --check      # 退出码 0 = 全就绪，1 = 还有没填的
```

它会打印三张表，一眼看出问题：

```
【体检】文件里的值
  MYSQL_PASSWORD               ✗ 仍是占位符（len=22，占位符本身就是这个长度，别当成已填）
  SPRING_DATASOURCE_PASSWORD   ✗ 仍是占位符（len=22，占位符本身就是这个长度，别当成已填）
  SPRING_REDIS_PASSWORD        ✗ 仍是占位符（len=25，占位符本身就是这个长度，别当成已填）
  MINIMAX_API_KEY              ✗ 空（此项必填）

【体检】compose 渲染后容器真正会收到的值
  MYSQL_PASSWORD               ✅ 容器将收到 len=17（服务 server）
  ...
```

> **长度对照速查**：`22` = 占位符 `CHANGE_ME__db-password`；`25` = 占位符 `CHANGE_ME__redis-password`。  
> 看到这两个数就说明**这一项压根没写进去**，不是「口令短了」。
>
> ⚠️ **不要用 `bash -c 'set -a; . ./.env; …'` 去校验含单引号的项** —— 那种值只能写成双引号 + `$$`，
> compose 会还原成 `$`，而 **bash 会把 `$$` 当成 PID**，两边结论不同。以 `set-secrets.py`
> 或 `docker compose config` 的渲染结果为准。

需要更全的机器侧事实（镜像齐不齐、外网通不通、git 到哪个提交）时，再跑一次总体检：

```bash
bash deploy/ops/host-check.sh          # 只读，不改任何东西
```

> 模板共 **12 处真占位**：9 处随机密钥（§4.1 一次 sed 全替换）+ 3 处口令  
> （`MYSQL_PASSWORD` ★生效 / `SPRING_DATASOURCE_PASSWORD` / `SPRING_REDIS_PASSWORD`）。  
> `MYSQL_ROOT_PASSWORD` 本部署**留空**（compose 不读，且本次也没拿到 root 口令）。  
> 用**路径 1**（已填好的 `.env`）时，本节应当直接全绿。

## 5. 镜像怎么进来（先解决这个，否则 §5.1 必然失败）

应用机拉不到 Docker Hub，而 compose 需要 **5 个镜像**：

| 镜像 | 来源 | 用途 |
| --- | --- | --- |
| `minio/minio:latest` | 外部 | 附件 / 知识库原文 |
| `nginx:1.27-alpine` | 外部 | 80=H5、81=管理端 的边缘网关 |
| `aioa-server` | **本地构建** | 后端（版本由 `name: aioa` 决定，两台机同名） |
| `aioa-agent` | **本地构建** | FastAPI agent |
| `aioa-web` | **本地构建** | 管理端静态站 |
| `ollama/ollama:latest` | 外部（可选但**知识库语义嵌入要用**） | 512 维嵌入 |

先跑 `bash deploy/ops/host-check.sh`，看 §⑤ 的通断结果，再按下面二选一：

### 5.0-A 应用机能上国内网（`baidu.com`/`mirrors.aliyun.com` 返回 200/301）→ 配加速器

说明只是 Docker Hub 被挡 / DNS 被污染，**这是最省事的一条**：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.net",
    "https://hub-mirror.c.163.com",
    "https://mirror.ccs.tencentyun.com"
  ]
}
EOF
systemctl daemon-reload && systemctl restart docker
docker pull nginx:1.27-alpine          # 试拉一个最小的验证
```

若仍超时，再把 DNS 换成公共 DNS（`/etc/resolv.conf` 里加 `nameserver 223.5.5.5` /
`nameserver 119.29.29.29`）后重启 docker 再试。**注意：这些加速器本身也可能不通** ——
`host-check.sh` §⑤ 会给每个加速器单独打一个通断，哪个是 200 就用哪个。

⚠️ 这条路上**应用镜像仍要在这台机上构建**（`docker compose build`），构建期还要 Maven Central /
npm registry；若这两个也不通，就直接走 5.0-B。

### 5.0-B 应用机完全出不去（全部 000）→ 离线搬运包

思路：在**能上外网 + 有 Docker** 的机器上把 5 个镜像（含构建结果）打成一个包，搬过来导入。

```bash
# ── 在能上外网的机器上 ─────────────────────────────
git clone <你的仓库> && cd aioa
bash deploy/ops/offline-images.sh export --with-ollama
#   产出 aioa-images.tar.gz（应用侧，先搬）+ ollama-image.tar.gz + ollama-models.tar.gz

# 传输（隧道机 → 真实服务器，用你平时那条通道）
scp aioa-images.tar.gz ollama-image.tar.gz ollama-models.tar.gz root@10.0.0.12:/opt/aioa/

# ── 在真实服务器 10.0.0.12 上 ─────────────────────
cd /opt/aioa
bash deploy/ops/offline-images.sh import aioa-images.tar.gz            # 先只导应用侧
cd deploy && docker compose --profile ollama up -d                     # 先起应用侧，跑 §6 验收
# 验收过了再补语义嵌入：
cd /opt/aioa
bash deploy/ops/offline-images.sh import ollama-image.tar.gz
bash deploy/ops/offline-images.sh import-ollama ollama-models.tar.gz
cd deploy && docker compose --profile ollama up -d
bash deploy/ops/offline-images.sh list                                 # 核对镜像齐备
```

> **导出机首选「隧道机 219.151.186.24」** —— 它是唯一能碰到真实服务器的机器，搬包只需一跳。
> 它没装 Docker 的话：`curl -fsSL https://get.docker.com | sh && systemctl enable --now docker`。
>
> `deploy/docker-compose.yml` 顶层有 `name: aioa` ⇒ 两边构建出的镜像名**完全一致**
> （`aioa-server` / `aioa-agent` / `aioa-web`），所以导进去就能被 compose 命中，**不需要 `--build`**。
>
> 打包顺序有意做成「应用侧先、Ollama 后」：Ollama 镜像约 1.5G，比应用侧整包还大，而后端
> **缺 Ollama 也能启动**（`EmbeddingConfig` 只装配 provider、不做连通性校验；`HttpEmbeddingProvider`
> 只在**调用时**抛 `IllegalStateException`，而 `KbService.embedAll` 对单切片 try/catch「失败只告警、
> 不阻断入库」）。⇒ 先把应用侧跑起来验收，再花时间搬 Ollama。**注意此时知识库上传会成功但没有向量**，
> 检索不会命中 —— 属于预期，不是缺陷。

**没有第二台装 Docker 的机器时**：把 `aioa` 仓库放到任意一台能上外网的 Linux 上装好 Docker 再跑导出，
或在本机装 Docker Desktop。另外，如果宿主已有 `minio/minio:RELEASE-*`（跑 milvus 时常见），
可以先 `docker tag minio/minio:RELEASE-xxx minio/minio:latest` 少搬一份。

## 6. 验收（8 条，全过就是部署成功）

```bash
# 1) 容器状态
cd /opt/aioa/deploy && docker compose ps

# 2) 后端健康（server 不发布端口，从容器健康检查读，不依赖镜像里有没有 curl）
docker inspect --format '{{.State.Health.Status}}' aioa-server   # 期望 healthy

# 3) 用户端 H5（80 端口，对外主入口）
curl -s -o /dev/null -w 'h5        %{http_code}\n' http://127.0.0.1/
curl -s http://127.0.0.1/ | grep -q 'aioa_session' && echo 'h5 内容 OK（含 aioa_session）' || echo 'h5 内容异常'
# 4) 管理端（81 端口）
curl -s -o /dev/null -w 'admin-ui  %{http_code}\n' http://127.0.0.1:81/
# ⚠️ 别用 200 当「页面正常」的判据：80 的 location / 是 try_files 回退到 H5，
#    任意路径都会回 200。判断是否真的是那套页面，要看内容（第 3 条那句 grep）。
# 5) 平台管理员登录（返回里应含 accessToken）
curl -s http://127.0.0.1/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123"}' | head -c 200; echo
# 6) 知识库档位（应为 milvus + http + 512）
TOKEN=$(curl -s http://127.0.0.1/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123"}' | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1/api/v1/kb/store
# 7) 容器 → **外部服务**连通性（MySQL 10.0.0.5:13049 / Redis 10.0.0.7:6379 / Milvus 19530）
#    ← 这三处任一不通，后端必然起不来（fail-fast）。注意 MySQL 端口是 13049
docker compose exec server bash -c '
  for hp in 10.0.0.5:13049 10.0.0.7:6379 10.0.0.12:19530; do
    h=${hp%:*}; p=${hp#*:}
    timeout 3 bash -c "cat < /dev/null > /dev/tcp/$h/$p" && echo "$hp OK" || echo "$hp FAIL"
  done'
# 8) 浏览器：用户端 http://10.0.0.12/ 与管理端 http://10.0.0.12:81/
#    管理端用 admin/Admin@123 登录，能进工作台、菜单完整
```

### 6.1 部署后系统自带的账号（Flyway 首启播种，口令见下表）

| 管理端 **`:81`** `/` | 平台管理员**不填**租户 | `admin`       | `Admin@123` | 平台管理员（**登录后立刻改密**） |

## 8. 日常运维

```bash
cd /opt/aioa/deploy

docker compose ps                       # 状态
docker compose logs -f --tail=100 server agent
docker compose down                     # 停（数据在卷里，不会丢）

# 升级：**先判断这台机能不能 pull**（见 §5.0）
git pull && docker compose --profile ollama up -d --build   # 能上外网/已配加速器
git pull && docker compose --profile ollama up -d           # 离线机：镜像靠离线包更新，别加 --build
```


### 8.1 ⚠️ 改了 `.env` 之后：用 `up -d`，不要用 `restart`

```bash
docker compose up -d server agent       # ✅ 会按新变量**重建**容器
docker compose restart server           # ❌ 无效：只重启进程，环境变量还是旧的
```

原因：`docker compose restart` 是「把同一个容器停掉再启动」，**不重新读取 `.env`、也不重新渲染服务定义**，  
容器里的环境变量保持原样。而 `docker compose up -d` 会把渲染后的服务配置与运行中容器做哈希比对，  
**发现变化就自动重建**（这才是你要的效果）。

- **不需要** `--force-recreate`：上面的哈希比对已经能识别 `.env` 变化；`--force-recreate` 只是在  
  「配置哈希没变但你想强制换一个容器」时用（例如容器内文件被手工改脏了）。
- 判断是否真的生效：`docker exec aioa-server printenv <变量名>`，或直接看 `docker inspect` 的  
  `Config.Env`。**只看「容器重启成功了」不算生效。**
- 换了 DB / Redis / Milvus 地址、模型 Key、`AIOA_KB_*` 档位等**任何环境变量**都走这条。

```bash
# 备份（三件套：库 + 对象存储 + 配置）
# MySQL 在**外部主机** ⇒ 用远端 mysqldump；口令从 .env 读，避免落到 shell 历史里
set -a; . /opt/aioa/deploy/.env; set +a
mysqldump -h "$MYSQL_HOST" -P "$MYSQL_PORT" -u "$MYSQL_USER" -p"$MYSQL_PASSWORD" \
  --single-transaction --routines "$MYSQL_DB" > /root/aioa-$(date +%F).sql
# 应用机没装 mysqldump 时，借用一次性容器（口令用 -e 传入，不写进命令行）：
# docker run --rm -e PW="$MYSQL_PASSWORD" mysql:8.0 \
#   sh -c 'exec mysqldump -h10.0.0.5 -P13049 -uaioa -p"$PW" --single-transaction aioa' > /root/aioa-$(date +%F).sql

tar czf /root/aioa-env-$(date +%F).tgz -C /opt/aioa deploy/.env
# MinIO 数据在命名卷 aioa_miniodata（附件/知识库原文）；Milvus 索引**不必备份**，可重建
```

**回滚向量库**：把 `.env` 里 `AIOA_KB_STORE` 改回 `mysql` 再 `docker compose up -d server`  
（MySQL 始终保存文档与切片，Milvus 只是可重建的索引副本）。

## 9. 这次没做 / 以后怎么做

### 9.1 本地大模型（可选，需要 GPU）

`docker compose --profile model up -d` 会额外起 vLLM（镜像大、需 GPU）。没有 GPU 就别开，  
用云端 Key（DeepSeek/通义）即可。

### 9.2 从「哈希向量」升级为「语义向量」（这套配置已经是语义档）

当前 `.env` 是 `AIOA_KB_EMBEDDING_PROVIDER=http` + `quentinz/bge-small-zh-v1.5`(512 维)，  
已经是语义向量。**只有**当你换模型（维度也变）时才需要：

```bash
# 例：换成 1024 维的 bge-m3
docker exec aioa-ollama ollama pull bge-m3
sed -i -e 's|^AIOA_KB_EMBEDDING_MODEL=.*|AIOA_KB_EMBEDDING_MODEL=bge-m3|' \
       -e 's|^AIOA_KB_EMBEDDING_DIMS=.*|AIOA_KB_EMBEDDING_DIMS=1024|' \
       -e 's|^AIOA_MILVUS_DIMS=.*|AIOA_MILVUS_DIMS=1024|' \
       -e 's|^AIOA_MILVUS_COLLECTION=.*|AIOA_MILVUS_COLLECTION=kb_chunk_v2|' \
       -e 's|^AIOA_KB_REEMBED_ON_START=.*|AIOA_KB_REEMBED_ON_START=true|' \
       -e 's|^AIOA_MILVUS_BACKFILL=.*|AIOA_MILVUS_BACKFILL=true|' .env
docker compose up -d server      # 启动时先重算向量、再回填新集合
# ⚠️ 跑完后把这两个开关改回 false 并重启（否则每次启动都全量重算）
```

### 9.3 启用 Gitee / Gitea 仓库联动（需要公网 HTTPS 域名）

1. 准备公网域名（如 `aioa.example.com`）并解析到网关，配好 HTTPS（可在前面再放一层 nginx / 宝塔）。
2. 在托管方（Gitee「设置→第三方应用」/ 自建 Gitea）创建 OAuth 应用，回调地址填  
   `https://<域名>/api/v1/gitee/bind/callback`。
3. `.env` 里改：`PUBLIC_BASE_URL` / `AIOA_GITEE_REDIRECT_URI` / `AIOA_GITEE_WEBHOOK_BASE_URL` /  
   `AIOA_GITEE_BIND_RETURN_URL` 四处改成新域名，填 `CLIENT_ID`、`CLIENT_SECRET`，  
   再把 `AIOA_GITEE_ENABLED=true`、`AIOA_GITEE_SYNC_ENABLED=true`。
4. `docker compose up -d server`。⚠️ Webhook 地址必须**托管方能访问到**，否则回调静默失效。

### 9.4 HTTPS

本 compose 只暴露 80。生产建议前置一层 nginx/宝塔终止 TLS，或把证书挂进  
`deploy/nginx/` 的容器并加 `listen 443`。
