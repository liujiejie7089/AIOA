### OA 基座侧结论（接入设计依据）

- 工具契约：`@AioaTool` + `@AioaToolParam` 注解即契约，`ToolSpec.inputSchema()` 由注解**自动推导**（手写 JSON 会漂移）
- 治理骨架已齐：`LocalToolRegistry` / `ToolDispatcher` / `ToolPermissionService` / `ToolApprovalGateway` / `ToolInvocationLog`（审计）
- 外部系统注册：`ToolSystem`（baseUrl/healthUrl/authType/authRef/timeoutMs/circuitBreaker）+ `ToolDefinition`
  （endpoint/httpMethod/inputSchema/paramMapping/responseJmespath/maxBytes/retryPolicy/rateLimit）
- **关键约束**：`ToolDispatcher` 出网鉴权只支持 `BASIC` / `Bearer`。
  而 scfy 用**自定义 Header `token: <jwt>`** + 密码 AES(ECB/PKCS5, key=`8bd32eeed3d0e0ea`)+ **每次从响应头 `token` 续期**
  ⇒ 这三件事基座不支持，正是**必须自写适配器**的唯一理由。其余可配置化，不改基座代码。

## 第二阶段：scfy 只读接入基础设施（用户拍板后）

用户拍板四条约束：**只能查询（禁增删改）/ 不确定内容的都废弃 / 等级枚举含联合国级 / 先搭基础设施，
后台测试服务后续再开**。据此落地新模块 `server/aioa-integration-scfy`。

### 结构（17 个源文件 + 3 个测试类）

| 层 | 类 | 职责 |
|---|---|---|
| 契约 | `ScfyParam` / `ScfyEndpoint` / `ScfyCatalog` | 56 可用 + 11 废弃，唯一事实源 |
| 事实源 | `core/ScfyEnums` | 等级/市州枚举，取值全部来自实测 |
| 适配器 | `adapter/ScfyClient`（+`ScfyResponse`/`JsonNodes`） | JDK HttpClient，**只发 GET，无写方法** |
| 校验器 | `validate/ScfyParamValidator` | 未知参数/必填/枚举/范围 + 缺参追问话术 |
| 工具层 | `tools/Scfy{Inheritor,Project,Shop,Ecology,Travel}Tools` | 56 个 `@AioaTool`（9+8+13+12+14） |
| 装配 | `ScfyAutoConfiguration` | 开关 + 启动一致性自检 |

### 关键设计决策（后续别推翻）

1. **`enabled` 默认 false**：不给配置 = 不注册任何工具、模型能力清单里不出现。可插拔落在这里。
2. **适配器只提供 GET，没有写方法** —— 把「只读」落成类型系统里「不存在」，比落成「记得别调」可靠。
3. **一致性自检**：`@AioaTool` 是编译期注解、无法引用运行时 `ScfyCatalog`，
   两处文本必然重复 ⇒ 启动时用反射对账，工具引用了不存在/已废弃接口**直接抛异常阻止启动**，
   契约有接口但没工具只告警（分阶段接入的正常态）。
4. **校验器的目标是「拦住会静默出错的调用」**，不是「校验合不合法」：
   市州全称（返回 0 条）、未知参数名（shopId 而非 id）、level≠country（传了等于没传）三类必须拦。

### 实测新增的枚举/参数事实（比第一轮更细）
