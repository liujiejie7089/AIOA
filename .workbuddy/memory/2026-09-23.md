### 已定性的缺陷（不要重复排查）

**D1 生产缺陷（被接入系统，非文档问题）**：`/show/data/*` 全系 8 个接口 `code=500`，
`relation "t_shop" does not exist`（Kingbase8 人大金仓）。用真实工坊 ID=140 复测仍 500 ⇒ 与参数无关。
对照 `/show/shop/shopTable` 正常返回 52 条 ⇒ 工坊数据存在，是 data 这套 Controller 查的老表不在当前 schema。

**D2 文档参数错误 8 处**（实测确认）：
- `/show/shop/{shopDetail, shopInheritor, shopSales}` 文档写 `shopId`，实际必填 `id`
- `/show/shop/{shopProjectTypePieChart, shopSalesAndNumPieChart}` 文档漏标 `id`
- `/show/travel/{getTravelRoadTypeCount, getTravelRoadDistributeData}` 文档标「必填：—」，实际必填 `travelId`
- `/show/travel/getTravelRoadDataByType` 文档只标 `type`，实际还必填 `travelId`
- `/show/project/getProjectListByArea` 文档标 area 必填，实测不传返回全省 1411 条

**D3 文档返回结构与实测不符 20 处**（典型）：
`getInheritorTypeData` 实际返回**项目类别**分布而非传承人等级；`getAreasNum` 实际 `{country,province}` 而非 `{total:18}`；
`getGenderNumDataByLevel` 实际 `{manCount,womanCount,totalCount}`；多处多一层包裹（areasTopFewList / routesTopFewList / touristCounty / nmchBaseDataList）；
`viewVideo` 实际 `{exist,viewUrl}`；分页实际是 `{pageCount,pageNumber,dataList,pageSize,totalCount}`（文档写 `{list,total}`）。

**D4 等级枚举不全**：实测出现 `project_level=联合国级`（id `2-UN-1`），文档枚举只有 country/province/city/county。
⇒ 校验器按 4 枚举会误判合法请求。

### OA 基座侧结论（接入设计依据）

- 工具契约：`@AioaTool` + `@AioaToolParam` 注解即契约，`ToolSpec.inputSchema()` 由注解**自动推导**（手写 JSON 会漂移）
- 治理骨架已齐：`LocalToolRegistry` / `ToolDispatcher` / `ToolPermissionService` / `ToolApprovalGateway` / `ToolInvocationLog`（审计）
- 外部系统注册：`ToolSystem`（baseUrl/healthUrl/authType/authRef/timeoutMs/circuitBreaker）+ `ToolDefinition`
  （endpoint/httpMethod/inputSchema/paramMapping/responseJmespath/maxBytes/retryPolicy/rateLimit）
- **关键约束**：`ToolDispatcher` 出网鉴权只支持 `BASIC` / `Bearer`。
  而 scfy 用**自定义 Header `token: <jwt>`** + 密码 AES(ECB/PKCS5, key=`8bd32eeed3d0e0ea`)+ **每次从响应头 `token` 续期**
  ⇒ 这三件事基座不支持，正是**必须自写适配器**的唯一理由。其余可配置化，不改基座代码。
