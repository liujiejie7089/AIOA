## 二、坑：本机用 HTTP 码探活会骗人（本轮差点据此误判）
- 本机环境有 `http_proxy=http://127.0.0.1:63414`（沙箱代理，`HTTP_PROXY`/`HTTPS_PROXY`/小写同名都在）。
  它**时好时坏**：
  - 经代理：同一 URL 一会儿 200、一会儿 **502**（代理连不上上游就回 502）；
  - `--noproxy '*'` 直连：也可能拿到 **HTTP 000**（连接失败）。
- ⇒ **判定「服务在不在跑」只用两样 OS 级证据**：`netstat -ano | grep LISTENING | grep ":<port> "`
  + **服务自身日志**；HTTP 码只作辅助。
  **尤其：502 不等于服务没起**（很可能只是代理坏了）；000 也不等于没起。
- 本轮实证：`:8000` 先看到 502（代理返回），若据此下结论会得出「agent 起着但异常」的**错误**结论；
  实际是当时**没起**。反过来，第二轮所有端口都回 502，实际两个服务都好好在跑，
  是代理自身退化 —— 只有 netstat（23576 / 25032 均在监听）和 agent 日志里的
  `GET /health HTTP/1.1" 200 OK` 才是可信判据。

### ★ 教训（下次别再犯）
**「应用已可访问」≠「dev server 已在跑」。** `:8080` 提供的是**已构建产物**（`/aioa/web/`、`/aioa/h5/`），

## 五、编写《Gitee 两套环境配置指南》（`deploy/GITEE-两套环境配置指南.md`）

用户要求：为「本地测试 / 生产」两套环境给出完整 Gitee 配置参数（仓库地址、分支、认证方式、用户信息…），
并指导在 Gitee 上建两个仓库 + 配置步骤。**先把代码里的真实口径挖清再写**，没凭通用 Gitee 常识编。

### 挖到的关键事实（都可回代码复核）
- **平台不用 SSH 调 Gitee**：走 HTTPS REST（`https://gitee.com/api/v5`）。
  SSH 只存在于 `GiteeProject.giteeSshUrl`（与 `giteeHttpsUrl`/`giteeHtmlUrl` 并列，取自建仓接口返回），
  **是给开发者用的展示字段**。⇒ 平台侧认证只有两条路：OAuth 个人绑定 / 租户级访问令牌。
- **仓库由平台自动创建**，不要手建：`support/GiteeNaming.repoPath()` 清洗成 `[A-Za-z0-9._-]`，
  纯中文/符号名退化为 `proj-<6 位确定性哈希>`（刻意不用随机名，保证同名→同仓、可追溯）。
  建在 `AIOA_GITEE_ORG` 组织下；`ORG` 留空则建在授权用户名下。
- **默认分支 Gitee=`master`**：权威值取建仓接口 `default_branch`（`RepoProviderClient.defaultBranch()` 只是兜底）。
  写错的症状是读写文件/目录浏览**全 404**，不报「配置错」。
- **两条认证路径的差异**：①个人 OAuth 需 `client-id`/`client-secret`，令牌存 `gitee_account`（AES-256，可自动刷新）；
  ②租户令牌存 `gitee_tenant_config.accessToken`（`GiteeTenantInitService.verify(actor,tenantId,accessToken,orgName)`
  —— **只要令牌 + 组织名**，不需要 OAuth 应用；令牌格式校验：长度 8~512、仅 `[A-Za-z0-9._-]`）。
  取值优先级：先个人绑定，解不开才回落租户令牌。只用②时 `/gitee/bind/authorize` 会报
  「Gitee OAuth 应用未配置」⇒ 个人绑定入口不可用，但建仓/同步照常。
- **本地测试项目里本来就有两条现成路线**（别另造）：
  - 桩：`python scripts/gitee_stub.py`（`PORT=int(sys.argv[1])` 默认 **8090**，内存态）
    + `AIOA_GITEE_E2E=1 bash start-all.sh`（内部 source `scripts/gitee-e2e-env.sh`）⇒ 零外部依赖全链路。
  - 真实：`scripts/gitee-real-env.sh.example` → `cp` 成 `.env.gitee-real` 填值再 source。
- 两套环境差异**只有 6 处**：`CLIENT_ID/SECRET`（回调地址不同⇒必须两个第三方应用）、`REDIRECT_URI`、
  `WEBHOOK_BASE_URL`、`ORG`、`TOKEN_ENC_KEY`、`SYNC_ENABLED`。其余 8 键相同（都指向同一个真实 Gitee）。
- ⚠️ **发现一处口径不一致（只登记未改）**：`scripts/gitee-real-env.sh.example` 注释要求本地回调用
  **`localhost` 不要用 `127.0.0.1`**，而 `deploy/.env.development` 里写的是 `127.0.0.1`。
  指南里按「登记页与配置必须逐字符一致」处理。**没擅自改 `.env.development`** —— 若用户已按 127.0.0.1
  登记过应用，改配置反而会打断现有接线。
