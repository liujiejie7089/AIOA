1. **后端启动方式错误**（之前 `spring-boot:run` 跑在父 pom `aioa-server` 上，"Unable to find a suitable main class" 全部模块 SKIPPED）：Maven 聚合根在 `server/pom.xml`（仓库根无 pom）。正确做法是在 `server/` 下 `-pl aioa-boot -am` 构建 fat jar 后 `java -jar` 启动。注意 `-pl aioa-boot` 只能从 `server/` 目录解析，仓库根无 pom 会报"Could not find the selected project"。

### 登录跳转 bug 根治（上一阶段 D2/D3 阻塞解除）
- 上一阶段只解决了"登录页不可达"（IPv6 绑定）与点击级事件卡顿；本次用 agent-browser 注入 XHR/fetch 网络探针（落 localStorage）抓到确切链路：`POST /auth/login 200` → `GET /apps 401` → 响应拦截器清 token + `router.replace('/login')`，故一直停在 `/login?redirect=/home`。
- 根因 = 前端 `web/apps/shell/src/api/index.ts` 的 `unwrap` 只剥 axios 信封，返回 `ApiResponse` 包装体 `{code,message,data}`，store 却按内层读 `result.accessToken`（得 undefined）→ 写 `localStorage['aioa.token']="undefined"` → `Authorization: Bearer undefined` → `/apps` 401。修复：unwrap 在 `body` 同时含 `code`+`data` 时再剥一层取 `body.data`（含 `'code' in body && 'data' in body` 守卫，兼容非包装响应）。
- 改后浏览器 E2E 实测：登录 → 跳转 `/home`，菜单（首页/我的应用/审批中心/知识库/系统管理）正常渲染。影响 login/me/apps/conversations/runs 等所有 unwrapped 接口（一并修正）。
- 证据：`e2e_browser_batch.json` / `e2e_verify.json` / `ab_home.png`。
