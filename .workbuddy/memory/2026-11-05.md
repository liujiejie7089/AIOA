## 三、定位调用申请 + 打卡（docs/74，V107）

- 表：`location_consent`（PENDING→GRANTED→USED / DENIED / EXPIRED，token 一次性、5 分钟）、
  `attendance_record`（一天一类型一条，`consent_id` 钉住「凭什么能有坐标」）。
- 接口：`POST /attendance/location-consent`、`GET .../pending`、`POST .../{id}/deny`、
  `POST /attendance/clock`（必须带 token + 坐标）、`GET /attendance/today|recent`。
- **「必须用户同意」是服务端约束**：没有 token、token 不是本人（403）、过期、已用、被拒，
  五种情形都写不进考勤 —— 改前端 JS 或直接 curl 都绕不过。
- H5：OA 宫格**首个磁贴「打卡」**（固定磁贴，不挂数字人，无模块数字人也出现）→ 居中「定位调用申请」卡
  （写明用途 / 5 分钟 / 只用一次 / 拒绝无副作用）→ 点「允许并打卡」**才**调 `getCurrentPosition`
  → 带坐标打同一个接口。每轮对话收口后 `GET pending`，数字人刚发起的申请会自动弹卡。
- 数字人路径：`attendance_clock` → 建单 → 模型只能说「已发起定位申请，请点允许」→ 页面弹卡 → 落库。

## 五、新坑（补 pitfalls）

- **`SERVER__PORT` 会劫持 Spring 的 `server.port`**：agent 的 shell 里带着 `SERVER__PORT=62166`，
  宽松绑定把它当成 `server.port` ⇒ 「Port 62166 already in use」。起后端必须
  `unset SERVER__PORT` 并显式 `--server.port=8080`。
- **常驻 DOM 的弹窗每次打开都要复位按钮**：定位卡第一次打卡成功后没复位 `disabled`，
  第二次弹卡两个按钮都点不动（截图看着正常、就是没反应）。测试用例（L15）抓到的就是这个。
- **pymysql 默认不 autocommit**：验收脚本里的 `DELETE` 不 `commit()` 会在 close 时回滚，
  表现为「清了库但下一轮还是 duplicated」。
- 后端 `8080` 由 agent 后台任务直起，**会随会话回收**；长期跑请用户自己 `start-backend.bat`。

## 六、按租户彻底清库（WJJ-DEMO）

- 需求：最初建租户时没建管理员，要「删掉这个租户下面的所有数据，且不影响其他租户」。
- `scripts/_purge_tenant.py`（dry-run 默认，`--apply` 才删）：

  ③ 带 `tenant_id` 的 111 张表按租户删；8 张无 `tenant_id` 的表逐个判性质
  （`form_template_version` 按 template_id、`revoked_token` 按 user_id；四张平台级配置不碰），
  ④ 子表先删、`sys_tenant` 最后删，⑤ 删前删后各做一次「全表 × 全租户行数快照」逐表比对，
  有任何差异整体回滚。
- 实测：41 张表 / **6872 行**，租户行删除；其它 8 个租户逐表行数**完全一致**；
