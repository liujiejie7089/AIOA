## 语音模块手机端报错 —— 根因与修复（部署面缺陷 + 报错外泄）

**症状**：手机端点麦克风 → `语音识别失败：模型 small 未就绪（模型目录 /app/.models）：…`；电脑端正常。

**根因（已确证，**不是**前端/手机兼容性问题）**：
- `/app/.models` 是**容器内路径** ⇒ 手机请求打到**生产容器**，电脑打到**本地 agent** —— 两端根本是不同的后端；
  移动端特有的那些嫌疑（安全上下文、iOS mp4 录制）**全部排除**，因为报错发生在「模型加载」阶段，早于音频解码。
- `deploy/Dockerfile.agent` 只 `COPY app ./app` + `pip install .`；`deploy/docker-compose.yml` 的 agent 服务**无 volumes**
  ⇒ 容器内 `/app/.models` 为空。`agent/.models` 被 `.gitignore:41` 忽略（~483MB），故也不能靠 COPY。
- `agent/app/asr/engine.py` `_resolve_model_ref()`（:35-47）落到「裸名字 `small`」；`AIOA_ASR_ALLOW_DOWNLOAD=0`
  ⇒ `HF_HUB_OFFLINE=1` ⇒ 离线加载失败 ⇒ `AsrUnavailable`（engine.py:104，文案含 `/app/.models`）。
- **第二个独立故障**：本机 `:8000` 的 agent 用的是**缺 faster-whisper 的解释器**
  （正确解释器 = `agent/.venv/Scripts/python.exe`，已确认含 faster_whisper+uvicorn+fastapi）⇒ 本地也报 `未安装 faster-whisper`。
- **UX 缺陷**：`agent/app/asr/router.py` 的 503 原样回 `str(exc)`（含内部路径），
  `server/.../AsrController.java` 的 `callAgent` 非 200 时又 `asText(root.message)` 原样透传 ⇒ 内部路径泄漏到用户手机。

**修复（7 文件）**：
1. `deploy/docker-compose.yml`（agent 服务）：`volumes: - ${AIOA_ASR_MODELS_DIR:-../agent/.models}:/app/.models:ro`
   + 透传 `AIOA_ASR_MODEL_DIR=/app/.models` / `AIOA_ASR_MODEL` / `AIOA_ASR_ALLOW_DOWNLOAD`（三键名与 engine.py:28-32 一致）。
2. `agent/app/asr/router.py`：503 message 改为 `语音识别服务暂不可用，请稍后再试`（完整原因**只进日志**）；
   `/status` 的 `error` **保留**详情供运维排障。
3. `user-client/_backup_index_pre_oa.html`（按基线重建 `index.html`）：
   - 新增 `API.asrStatus()`（`GET /v1/asr/status`）；
   - `bindVoice` 加**严格 fail-open** 的可用性探测 —— 仅当 `d.available===false && d.enabled!==true` 才置灰麦克风；
     探测报错/未登录/环境无该方法一律不拦（否则「探测本身失败」会误伤可用功能）；
   - 录音期在 window 补 `pointerup/pointercancel` 兜底（部分机型 `setPointerCapture` 失效 ⇒ 录音停不下来），靠 `isLive()` 保证只结束一次。
4. `deploy/生产部署手册.md` §5.3 + `deploy/.env.production` 5b 段：ASR 模型前置说明（含「宿主目录不存在时 Docker **静默建空目录**、容器照常 healthy」这个最隐蔽的坑）。
5. `scripts/_check_voice_gesture.py`：`--selftest` 原取 `HEAD` 当「修复前版本」，而修复提交后 HEAD 已是修好的版本
   ⇒ 会假报「旧版竟然全绿 ⇒ 哨兵没有判别力」。已钉 `PREFIX_REV = "10d26bc"`（= `66f8c24` 的父提交）。
6. `start-all.sh`：agent 改用 `agent/.venv/Scripts/python.exe`。原用通用 `PY`（= `envs/default`），
   而该环境**没有 faster-whisper**，可它却是 `agent/pyproject.toml` 的**必装**依赖
   ⇒ 本地语音一直 503「未安装 faster-whisper」。**这条才是「电脑端也不正常」的本地根因。**
   已实测 `agent/.venv` 同时具备 faster_whisper + httptools（故 `--http httptools` 仍成立）；
   解释器缺失时在启动前 warn，不静默退化。通用 `PY` 不动（`user-client/serve.py` 还在用）。
7. **另两条部署路径也补了模型**（compose 只是其中一条）：
   - `deploy/k8s/20-agent.yaml`：加 `asr-models` 卷（`hostPath /opt/aioa/asr-models`，`DirectoryOrCreate`）
     只读挂 `/app/.models`；`00-namespace-config.yaml` 补 `AIOA_ASR_MODEL_DIR/MODEL/ALLOW_DOWNLOAD`；
     `k8s/README.md` 加第 5 个易踩点。**刻意不用 `type: Directory`** —— 那会让模型缺失时整个 agent 起不来，
     连普通对话一起挂；ASR 可用性改由 `/status` + H5 置灰两个信号显式暴露。
   - `deploy/ops/offline-images.sh`：模型**不在镜像里**，离线搬到目标机拿不到 ⇒
     新增 `--with-asr-model`（只打 `<模型名>/`，不连带 HF 缓存那份重复数据），
     `export`/`list` 打印模型就绪度，并在导出结束打印目标机放置命令。
     tar 布局实测：解到 `<仓库>/agent/.models` 下得到 `agent/.models/small/model.bin`（与 compose 期望一致）。

  - 指向不存在目录：`503 {"code":"ASR_UNAVAILABLE","message":"语音识别服务暂不可用，请稍后再试"}` —— 无 `模型目录`/`未就绪`/`C:`/`/app` 泄漏；
