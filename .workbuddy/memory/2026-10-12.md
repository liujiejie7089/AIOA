### 5.5 本轮修掉的两处缺陷（都在 `app/asr/`）

1. **归因错误 + 泄漏内部路径**：原实现任何异常都回 `500 识别失败：{exc}`，把
   `Invalid data found ... 'C:\\Users\\...\\tmp_xxx.wav'` 原样回给前端。⇒ 新增 `AsrBadAudio`/`AsrTooLong`
   分类异常，路由分别翻 **400 / 422**；500 只回「语音识别失败，请稍后重试」，细节只进日志。
   `_is_decode_error()` 按 `av.*` 模块名 + 消息特征判，**已负向验证**不会把「CUDA out of memory」误判成坏音频。
2. **时长上限判得太晚**：原先生成完整转写再比 `durationMs` ⇒ 提前为 `engine.transcribe(path, lang, max_seconds)`。

   ⚠️ **但不要宣称「解码前拦截」**：`faster_whisper/transcribe.py` 里 `duration = audio.shape[0] / sampling_rate`，
   duration 取自**已解码的 PCM**，且 `model.transcribe()` 是**普通函数**（进函数体就解码）。实测 5.35s 音频两种路径**都 ~1.8s**
   ⇒ 省掉的是 whisper 的**推理那几趟**（长音频的大头），**解码本身省不掉**。此条已在代码注释里改正（首版注释写错了）。

### 12.3 哨兵为什么必须**两侧**都立断言（本轮最重要的方法论点）
只验「权限场景要给提醒」是不够的 —— **那半边收窄前后都成立**，凭什么证明口径真的收窄了？
故 3b「非权限『做不了』**不得**出现办理指引」才是这次的**判别性**那一半：

- 3b 禁止词 = `管理员 / 权限申请 / 转述 / 放行` + `权限码 / 开通权限 / 申请权限 / 审批权限 / 办理权限`。
- **首版只拦前四个，实测漏网**：连跑 2 轮里有 1 轮在「帮我交水电费」这种**非权限**问题上回了
  「如果您需要**开通系统审批权限**…我可以为您**申请**」—— 典型的「没问权限却自己把话题拐到权限上」。
  遂**收紧提示词**（规则 4 末句加「不要在用户没提权限时主动提议『要不要帮你申请/开通权限』」）
  并**同时**把后五项加进 3b 禁止词。**先收紧断言、再改提示词，两者一起动**，不留「断言故意留缝」的口子。
- 3b 的前提守卫：该轮必须确实表现为「答不了」（命中 `无法/不能/不支持/办不到/无权限…`），否则**如实 SKIP**，
  不硬凑 PASS（避免把「模型没答不了」误记成「口径合格」）。

## 13. 美化「上传项目文档」弹窗：根因是**选择器作用域错配**（提交 `c02014a`）

### 13.1 用户诉求与现象
用户给了截图：「上传项目文档」对话框里 `选择文件` 是**系统灰按钮**、`存放位置` 是原生下拉、标签与控制挤在一行 —— 一句话「美化一下」。**注意：这不是「没写样式」，是写了永不匹配的样式。**

### 13.2 根因（两层，缺一不可）
1. **作用域错配**：`oaOpenUploadForm` / `oaOpenExpenseForm` 都是
   `document.createElement('div')` → `document.body.appendChild(mask)`，**挂在 body 上，不在 `.oa`（#oaRoot）之内**。
   而 `_oa_extra.css` 把表单规则写成 `.oa .oa-ef-row{…}` / `.oa .oa-ef-row select{…}` ⇒ **选择器永不匹配**
   ⇒ 表单等于零样式，浏览器原生控件直出（截图里那枚灰按钮就是它）。
2. **令牌取不到**：`--brand/--brand-soft/--brand-ink/--brand-line`（以及 `--ab-h`/`--tab-h`/`--red-ink`）
   **只定义在 `.oa{}` 里**（`_oa_extra.css:14-21`）⇒ 弹层在 `.oa` 外，`var(--brand-ink)` 解析失败，
   `::file-selector-button` 的颜色成了无效值 —— 这也是 10-11 那次「只把文件控件调成品牌色」没生效的原因。

**判据**：`getComputedStyle(el).flexDirection` 在旧版是 `row`（说明 `.oa-ef-row` 的 `column` 没生效）。
**别再靠肉眼猜「样式没生效」** —— 一条计算样式就能定位是「规则没匹配」还是「匹配了但被覆盖」。

### 13.3 修法（两处，各有取舍）
- **不能**再带 `.oa` 前缀（会继续永不匹配）→ 改为 `.notif-modal.oa-dlg …`。
- **也不能**裸写 `.notif-modal` / `.note-err` / `.notif-foot .btn`：这三个被**经典形态 10 处弹层**共用
  （资料详情 / 我的申请 / 通过审批 / 驳回审批 / 新消息提醒…），裸写会把它们一并改掉（越界）。
  ⇒ 新增标记类 **`oa-dlg`**，规则一律 `.notif-modal.oa-dlg …`，**改动面恰好等于这两个弹层**。
  验证手段是**负向对照**：造一个没有 `oa-dlg` 的 `.notif-modal`，其 `.note-err` 必须仍是 transparent/无圆角、
  `.notif-foot .btn` 必须仍不是 38px（实测 34px）—— 证明没外溢。
- 品牌令牌**补挂在 `.notif-modal.oa-dlg` 自己身上**（取值同 `.oa`），弹层与 OA 同肤色。
- 观感重做：标题带图标砖；`存放位置` 用 `<span class="oa-sel">` + 自绘箭头（`appearance:none`）；
  `文件` 改为虚线**投放区**（图标 + 「点击选择文件」+ 格式提示）；说明/报错成条；底部按钮统一胶囊（38px）。

### 13.4 ★最危险的一处：把 file input 藏起来会毁掉哨兵契约
想让投放区好看，最直觉的做法是 `input[type=file]{display:none}` + `<label>` 代理点击 ——
**但那会直接打断哨兵 G9c**（它做**真实** `page.locator('#upFile').click()` 并断言 `filechooser` 事件；
Playwright 对 `display:none`/`visibility:hidden` 的元素点击会失败）。
采用的折中：`#upFile` **保持真实可见**，用 `position:absolute;inset:0;opacity:0` **透明铺满整块投放区**
（`opacity:0` 仍有 bounding box ⇒ Playwright 判定 visible、命中测试落在它身上）——
既让整块可点、观感干净，又让「点击即唤起系统选择器」的契约原样成立。**实测 G9c 仍通过。**

同理：`.notif-head` 的文本被两个哨兵按 `textContent` 断言为**恰好**「上传项目文档」，
故图标**放在 `.notif-head` 之外**（外层 `.oa-up-hd`），绝不放进标题里（放进去就变成「上传项目文档×」而断言失败）。
