## 企微 MCP OAuth 连接器（独立交付物）

在 `mcp-wecom-oauth/` 完整实现「H5 移动端 + MCP HTTP+SSE 架构下的企业微信自建应用 OAuth 授权连接器」，复刻 WorkBuddy 跳转授权体验。

- 授权模式：企微**移动网页授权** `scope=snsapi_privateinfo`（固定，非 snsapi_base），拿 user_ticket → getuserdetail 拉 biz_mail。端点 `open.weixin.qq.com/connect/oauth2/authorize`（与既有 Java `WeComOAuthService` 的 PC 扫码 `qrConnect` 不同）。
- 架构：H5 作 MCP Client（`frontend/index.html` 原生 EventSource+fetch，无需库）；后端 FastAPI + FastMCP SSE（`/mcp/sse`+`/mcp/messages/`）。未授权时后端 `ctx.elicit` 把授权 URL 交给 H5 跳转（elicitUrl 模式）。
- 安全：corpid/agentid/corpsecret 仅后端 env；user_ticket/access_token 用 `SecretCodec`（AES-256-GCM，`enc:`+Base64(IV‖CT)，SHA-256 派生）加密落盘，与 Java 同口径；state 一次性+10min TTL 防 CSRF；回调必须 HTTPS+可信域名 txt 校验。
- 11 步链路已文档化（README §3）。

交付物（6）：①README 后台配置+架构+11步 ②02-oauth-url-template.md ③后端（config/secret/store/wecom_auth/server/main）④frontend/index.html ⑤05-tools-schema.md（wecom_send_message/get_profile/read_mail/send_mail）⑥06-errors.md。

- 关键修正：`build_authorize_url` 原用 `urlencode(params)` 会二次编码已 quote 的 redirect_uri（%253A），改为逐值 `quote(v, safe='')` 手工拼接。
- 测试：agent venv 跑通 secret 加解密/store 一次性 state+binding 往返/授权 URL 单编码（`ALL FUNCTIONAL TESTS PASSED`）。**注意**：本仓库 `agent/.venv` 的 beartype 与 `fastmcp[server]` 冲突（`ImportError: BeartypeConf`），无法在此 venv 启动服务；需在能 `import fastmcp` 的环境运行（README §4 已注明）。

## 企微连接器 · 离线 E2E 实测通过（langgraph-wecom-oauth）
