## 联调最终结论（已跑通）

运行方式（两步）：
1. 起后端：`java -jar server/aioa-boot/target/aioa-boot-0.1.0-SNAPSHOT.jar`（:8080，勿用 mvn）
2. 起联调代理：`python user-client/serve.py 5181`（静态托管 + /api 反代 :8080）

实测全链路打通（经 :5181 代理）：
- `POST /api/v1/auth/login` → `code:0`，取 `data.accessToken`（203 字符 JWT）
- `POST /api/v1/conversations` → `data.id`
- `POST /api/v1/conversations/{id}/runs` → `data.runId`
- `GET /api/v1/runs/{runId}/events` → **200 + 819 字节 SSE 流**，逐字 `message.delta` 到达

SSE 真实帧格式（后端直连/经代理一致）：
```
id:1
event:run.started
data:{"run_id":"...","conversation_id":8}

id:2
event:message.delta
data:{"text":"通"}

id:12
event:message.completed
data:{"content":"...","citations":[],"tool_calls":[],"usage":{"prompt_tokens":0,"completion_tokens":10}}
```

### 本轮修复的三个真实缺陷
1. **代理 SSE 缓冲**：`http.client` 的 `resp.read(amt)` 会累积到 amt 字节才返回，
   导致 SSE 被"攒住"（表现为 http=200 但 0 字节）。改为 `resp.read(1)` 逐字节转发后恢复流式。
2. **前端消息重复**：`message.completed` 帧携带完整 `content`，若在 deltas 之后再追加一次会文本翻倍；
   改为该帧只取 `usage`，不再追加正文。
3. **Windows SO_REUSEADDR 陷阱**：同端口允许多次绑定，旧代理进程未真正退出时，
   新代码虽"启动成功"但流量仍打到旧进程（曾表现为 401 / 0 字节）。
   改完代理务必用 `netstat -ano | grep LISTENING` 确认旧监听已消失。

前端 JS 已用 `node --check` 校验语法通过（21557 字符）。
用户端在线预览：`http://127.0.0.1:5181`（需后端 :8080 与代理同时在运行）。

## Bugfix：会话层永久盖在页面上

**现象**：只要进入过"会话"页，该层就一直显示在页面上，切到首页/专家/我的都被它遮挡。

**根因（CSS 优先级）**：
- `.page{display:none}` 特异性 (0,1,0)；`.page.chat-active{display:flex}` 特异性 (0,2,0) 且位置更靠后。
- `go()` 切页时只用 `classList.remove('active')`，**从未移除 `chat-active`**。
- 结果：离开会话页后 chat-active 仍在，其 `display:flex` 覆盖了 `display:none`，会话层永久可见
  （页面是 `position:absolute;inset:0`，所以是整层盖住）。

**修复（双保险）**：
1. CSS 收紧为 `.page.active.chat-active{...}` —— 必须同时有 active 才生效。
2. `go()` 切页时 `p.classList.remove('active','chat-active')` 一并清理。

**教训**：用"附加 class 改布局"的写法时，附加类的选择器要带上 `.active` 前缀，
否则它的显示属性会反过来压过基础隐藏规则；切页/切状态函数必须把附加类一起清掉。
