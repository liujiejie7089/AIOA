
## 企微工具 5 → 23 + 三处根修（docs/64 §9.10）

- **`_since()` 7 天边界是真 bug**：`begin=now-7d` 截秒 + 子进程/网络延迟 ⇒ 必然比服务端 168h
  下界老 1~3 秒 ⇒ `850016 begin_time不能早于7天前`。修：`_BEGIN_MARGIN=1h`。
  二分实测：now=11-02 17:55 时，`10-26 15:55`/`17:55` 失败、`18:10` 通过。
- **`40073 非法的 chat_id` = 模型拿群名当句柄**。修两层：agent `_tool_digest` →
  `tool_calls_log[].digest`（600 字符）→ Java `RunService.formatToolDigest`（240）随历史回灌；
  `session_messages`/`message_send` 允许传群名，内部用最近 7 天会话解析。
- **CLI 业务错误是 exit 0 + `{"error":...}`**，不是非零退出 ⇒ 必须 `_call()` 拦，否则
  「成功返回 0 条」。这条坑很容易复现。
- **会话丢失**：`conversationId` 只在内存。H5 加了 `aios_oa_last_conv` / `aios_last_conv`
  两套记忆（按 账号+项目+对象，7 天），三样对上才恢复。
- **`agent_run_step` 终于有写入方**：`RunService.persistToolSteps`，凭据键打码。
- **日历/会议不能用 `_since()`**（它夹 7 天）⇒ 新增 `_range_forward()`（现在 → +30 天）。
- **`_ok()` 剔除 `security_notice` / `extra_identity_context`**：CLI 每包都带，官方禁止外传。
- **工具数快照在 `mcp_server_tool`（不是 mcp_tool）**，需 hub 重启后重新 trust 才会从 5 变 23；
  `scripts/_verify_mcp_registry.py` 的 EXPECT_TOOL_COUNT 已同步。
- 验收：argv 哨兵 47 项全绿 · agent pytest 232 passed · aios-chat 编译通过 ·
  真实凭据离线实测 session_messages("成都易构") 7 条。

## 模糊实体澄清：做成连接器无关 + 截图/真机验证（第二轮）

用户要求「用截图测，且对所有连接器都适用，改完再测 QQ 邮箱」。第一轮只写了提示词，

## 第三轮：一次交互交齐（选完不终止 + 动态文本框 + 单次提交）

用户现场：点「小亮」→ 落款「已选择：小亮」→ 气泡再无下文。要求「参考 loop harness
的循环机制，让流程始终通过选项推进，缺内容就动态出文本框，一次交互里交完」。

**根因**：回填只给标量（`{"answer": "wob…"}`）⇒ tool 消息是模型唯一输入，它拿不到
「要发什么」，只能再问一句 ⇒ 选人/内容/执行被拆成三轮。**不是渲染问题**。

**改动（四处）**：
- `tools/ask_user.py`：选项级 `needs_text/text_label/text_placeholder` + 卡级 `text_input`；
  `_as_options` 只在显式给出时才带新键（老载荷形状不变）。
- `tools/entity_clarify.py`：`content_hint()` 按**最先出现的动作词**判缺什么内容
  （「发消息说下午三点开会」要的是内容，不是时间）；`with_content_hint()` 被
  `build_clarify_call` 与 `build_block` 共用 ⇒ 代码合成路径与模型自调路径同形状。
- `graph/nodes.py`：`_clarify_answer()` 归一 `{value,label,text}` + tool 消息带 `next`
  （「直接执行，别再确认一次」）。⚠️ 归一**只对 clarify 链**，否则 confirm 的
  `{decision:true}` 被吃掉 → 写工具永不执行（`test_request_confirm` 当场红）。
- `user-client/index.html`：`clarCardHtml` 渲染 `.clar-text-wrap[hidden]`；
  `mountClarCard` 的 `textGate/syncText/syncOk`（选中即展开+必填、切走即清空、
  必填未填时确认禁用）；`clarAnswerPayload()` 两形态共用；`liftTextBelowCard()`
  把空的 `.tx` 挪到卡片之后（否则续跑的回答飘在问句上方，阅读顺序反）。

**验证**：pytest 274 项全绿；`_check_entity_clarify_flow.py` 65 项全绿；
`_shots_clar_once.py` 19 项全绿（直接读浏览器发出的 POST body：
`{"answer":{"value":"wob_LiuYang","label":"刘洋","text":"下午三点开会"}}`）；
真机 `_e2e_clar_once.py` 9 项全绿：一次 resume 后 `tool.call→tool.result→正文`。
真机**真的发了一条企微消息**给「阿修bot.」（内容「下午三点开会」）。

**环境坑**：手工起 agent 必须带 `AIOS_MCP_HUB=true`，否则无 mcp 工具 ⇒
`模糊实体预取 0 个候选` + 模型弹空选项卡（看着像澄清链坏了）。

## 第四轮：动态交互控件协议（菜单/候选框/文本框 + 依赖 + 校验 + 一次提交）

用户要求「按语义动态生成菜单、候选框、文本框，并据输入驱动流程」，并明确要写清
触发判据 / 输入类型 / 依赖与状态 / 流转 / 异常处理。

**分工**：语义判断给模型（决定问哪几样、用什么控件），合法性与状态给代码。

- `ask_user`：新增 `fields[]`（id/label/type/required/options/searchable/hint/default/
  max_len/min/max/visible_when）+ `FIELD_TYPES`（select/multi/text/textarea/date/datetime/
  number，**封闭枚举**）+ `COND_OPS`（eq/neq/in/empty/truthy）+ `MAX_FIELDS=6`。
  `_as_fields` 三道收敛：未知 type 降级 text、select 无候选也降级、
  悬挂/自指/成环的 `visible_when` **只剪条件不剪字段**。有 fields 时丢弃 options/text_input。
- `nodes._clarify_answer`：多认 `{values}` 形状，value 缺失时取第一个非空字段。
- H5：`clarFieldsHtml` + `mountClarFields`（values/condOk/clearField/errOf/paint/
  refresh/collect/summaryHtml）。可见性迭代到不动点（步数 = 字段数+2，环在服务端剪掉）。
  隐藏⇒清空+不校验+不提交；红框只在 touched 后出现；**字段卡的确认键不置灰**，
  点了校验并点亮问题字段（灰掉只会让用户猜漏了哪项）。
- 泛动作闸 `needs_action_clarify`：人称 + 泛动作（说个事/联系/沟通…）+ 无具体渠道词
  ⇒ `build_action_fields_call` 直接合成「做什么/对谁/三支依赖/其它出口」字段卡。
  `build_call` 统一两条合成路径（两处 nodes 调用点都改它）。

**真机发现（重要）**：先只给模型 schema 时，它**根本不调工具**，写散文反问
（「请告诉我您要传达的具体内容…」）—— 和 docs/68 §7.5 同一类失效。加闸后才变成
`run.started → need_clarification`（零正文），字段卡带真实通讯录 3 人。
结论：模型能给语义假设，给不了交互保证；要保证的交互必须有代码闸。

**验证**：pytest 291 通过（1 项沙箱超时，干净工作区同样失败）；契约校验 85 项全绿；
`_shots_clar_fields` 30 项全绿（直读 POST body：values 只含可见字段）；
真机泛动作 8 项全绿；真机明确动作 7 项全绿（零回归）。
