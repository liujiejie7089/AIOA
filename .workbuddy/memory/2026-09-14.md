## V37 系统管理「人员管理」按权限自动分类 + 管理端登录租户名称（2026-09-14 下午）

### 用户报障
用机构管理员 `znkjsc_admin`（简宁，tenant 9 / inst 30 / dept 0）登录管理端后，
「系统管理 → 人员管理」**全部空白、没有任何数据**。

### 根因（四层叠加，不是单点 bug）
1. **菜单**：`MainLayout` 的「系统管理」`v-if="isPlatformAdmin"` → 机构管理员根本看不到入口；
2. **路由**：`meta.minTier='platform'` + `tierOf()`（只认 ADMIN=2 / TENANT_ADMIN=1 / 其余=0）→ 强闯被静默重定向 `/home`；
3. **接口**：`AdminController.requireAdmin()` 只认 `ROLE_ADMIN` → `/admin/users` 403「系统管理仅租户管理员可访问」；
4. **前端**：`AdminView.reload()` 用 `Promise.allSettled`，403 时把 `users=[]` 并只读 `error.message`
   （得到 `Request failed with status code 403` 而非后端中文原因），于是「空白且无任何提示」。
   另：`/admin/users` 原本是 `selectPage(page, null)` **全表无过滤**——作用域缺失，任何平台令牌都能翻到全部租户账号。

### 修复
- **后端**：新增 `PersonnelService`（aioa-admin，用 `JdbcTemplate` 读组织域表，**不引 aioa-org**）。
  四级作用域：ADMIN=全平台 / TENANT_ADMIN=本租户 / ORG_ADMIN=本机构 / DEPT_LEADER=本部门；其余 403。
  自动分类 `scopeClass`：PLATFORM/TENANT/ORG/DEPT/MEMBER；分组维度 `groupBy`：平台→租户、租户→机构、机构/部门→档位。
  新端点 `GET /api/v1/admin/personnel`（分组 + `classCounts` + `capability` + `hint`）；
  `/admin/users` 改为复用同一内核（消除全表泄漏，保留分页形态）。平台级配置与写操作仍 `requireAdmin()`。
  档位判定以**角色码为准**，`org_member.is_org_admin` / `org_department.leader_user_id` 作补充信号
  （演示数据里存在「花名册标了管理者、角色仍是 ROLE_MEMBER」的账号）。
- **登录租户名称**：`AuthService.login(username, password, tenantName, ip, ua)`。
  规则「**声明即校验**」：`null`（旧客户端）跳过；空白且 tenantId≥2 → 1004「请输入租户名称」；
  非空则与 `sys_tenant.name` 归一化比对（去全部空白含全角 + 小写），不一致 → 1004；
  **平台侧账号（tenantId 0/1）不参与校验**（否则 `tenantNameOf(0)=null` 会把 admin 挡在门外）。
  前端 `LoginView` 增加必填「租户名称」+ 纯空白校验 + `localStorage['aioa.lastTenant']` 记忆。
- **前端**：`AdminView` 重写为「人员管理」——按 `groups` 渲染分组表格（含档位/角色/机构/部门/职务列），
  错误走 `el-alert` 显示后端真实文案；平台级卡片（角色/功能管理/模型管理/权限点）`v-if="isPlatformAdmin"`；
  操作列按 `capability` 显隐。`constants/permissions.ts` 新增 `PERSONNEL_VIEW_ROLES`，
  菜单/路由/接口三层共用，避免再次口径打架。

### 顺带修掉的更严重缺陷：`unwrap` 吞掉业务错误
`api/index.ts` 的 `unwrap` 原来只在 body **同时含 `code` 与 `data`** 时剥壳。后端
`default-property-inclusion: non_null` + `ApiResponse.fail(code,msg)`（data=null）→ 失败响应**没有 `data` 键**
→ 返回整个信封当业务数据 → 调用方读到 `undefined` 继续跑（登录态存成 `"undefined"`、列表空白），**既不报错也无提示**。
这就是「页面空白」这一类缺陷的共同根因（也是我第一轮 E2E 里「错误租户名竟然登录成功」假象的来源）。
现改为：body 含数字型 `code` + `message` 即按信封处理，`code≠0` 抛 `ApiError(code, message)`。
