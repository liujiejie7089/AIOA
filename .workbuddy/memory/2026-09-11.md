## 收尾：会话职责套件「回归」实为额度数据漂移（2026-09-11 晚）
**现象**：全量回归里 `e2e_worker_chat_scope.py` 由 13/13 掉到 10/12，失败 2 项（越界拒答、发放请假表单），返回内容都是
「额度已用完。你可以：① 等待下月额度发放 ② 购买词元包 ③ 联系管理员扩容」。看着像批次三改坏了 `setChatWorker/chatModel/applyKbChip`。

**结论：不是代码回归，是演示数据漂移。** 该套件用 **admin** 登录；admin 没有独立额度行，
`BillingService.getOrCreate` 回落到**租户共享行**（`tenant_id=0, user_id=0`）。反复跑真实 LLM 的 E2E 把该行耗到 `left=0`，
前端额度闸门拦下请求 → 职责边界类断言全部落空。
- 判据：`GET /api/v1/quota` 对 admin = `quota=100000, used=102522, free=2000, left=0, exhausted=true`；
  对 zhangsan（V6 给了独立额度行）= `left=1075498`。**只有 admin 路径失败，所以看起来像回归。**
- 复位：新增 **`scripts/reset_demo_quota.py`**（只加 `free_tokens`，保留 `used_tokens` 与账本一致；
  `--dry-run/--target/--threshold`；改前写 `quota_backup_<ts>.json` 含 `rollback_sql`）。复位后 **13/13**。

**顺带修掉的真缺陷（值得记住）**：`user-client` 会话额度闸门原为
`if(state.left != null && state.left <= 0)`，而 `state.left` **初值是 0** —— 只要 `/quota` 接口失败或还没返回，
用户就被判「额度已用完」且**完全无法对话**。已改为以服务端权威标记为唯一判据
`if(state.quotaInfo && state.quotaInfo.exhausted === true)`，`state.left` 初值改 `null`。
真耗尽时后端 `createRun` 已有 403 兜底，前端 fail-open 不漏放。
**通用教训：UI 闸门不要用「数字型 state 的默认值」表达「未知」，默认值会在数据没到位时被当成业务事实。**
