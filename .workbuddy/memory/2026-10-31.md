### 本轮真机抓到并修掉的缺陷（★ 三个必须记住）
29. **业务校验失败落 500 而不是 400**：`GlobalExceptionHandler` 只把 `BizException` 与
    Spring 参数类异常映射成 4xx，**其余全落 `@ExceptionHandler(Exception.class)` ⇒ 500**。
    ⇒ 服务层**禁止**用 `IllegalArgumentException` 表达业务校验，必须 `BizException.badRequest`。
    现象极具误导性：「标题为空」看起来像「后端崩了」。
30. **本项目业务失败的正确判据是信封 `code`，不是 HTTP 状态码**：约定为
    **HTTP 200 + `code=400`**（只有 BizException 的 401/403/404 才映射 HTTP 状态，
    见 docs/36 §、docs/38 §）。e2e 按 `http_status==400` 断言 ⇒ 6 条假红。
    ⇒ 写断言先问「这个仓库的信封约定是什么」，别按 REST 直觉。
31. **e2e 写死 uid 会把组织者算成受邀人**：`zhangsan` 真实 uid=2，首版 `attendeeIds=[2,3]`
    恰含组织者本人（createMeeting 会跳过 organizer）⇒ `invited` 期望 2 实际 1。
    **这不是产品缺陷**。⇒ 期望值必须按登录返回的真实 uid 动态算。
32. **起后端必须带 `-Dspring.flyway.validate-on-migrate=false`**：本机库 V89–V95 的
    checksum 是 NULL、V100 已应用但本地文件被 revert（`d5974af` revert `cd79d79`）
    ⇒ 直接 `java -jar` 会 Validate failed 起不来。`start-all.sh` 本就带这个参数
    （application.yml 的 `validate-on-migrate: true` 只是默认，可被 -D 覆盖）。
    另：`nohup &` 起的 Java 进程会被回收，必须用受管后台任务或让用户在自己终端起。
