### ① 连接器「关闭」改为**本次对话不调用**，不解绑（核心）
- 用户口径：「关闭时**不解绑**连接器，只是本次对话不调用对应的应用」。
  原实现点关闭调 `POST /v1/connectors/{code}/disconnect` ⇒ 企微扫码类连接器**连本机凭据一起删**，
  下次开启要重扫。
- 方案 = **对话级工具屏蔽**（与 `kb_on` 完全同构）：
  `前端集合 → disabled_connectors → Java context 快照（落库+回读）→ agent prepare 过滤
  + tools 节点执行前二次拦截`。后端连接状态/授权/trusted **全部不动** ⇒ 重开免重扫。
  真解绑保留在连接器面板「断开」按钮（确认框写明会删凭据）。
- 两形态**共用**一组函数（`mutedConnectorCodes/setConnectorMuted`），不各写一套防漂移。
- **被拦下的调用必须回注 ok=False 的 tool 消息**：丢弃会让 tool_call_id 找不到对应 tool 消息，
  上游判协议错误。回注入 agent 的 `messages`（**不在事件帧里** ⇒ 断言要直接看节点返回值）。

## 18:2x 生产连接器不可用的真凶：FastMCP 的 Host 白名单（提交 148c5c4）

用户补的 hub 日志被 `-A 20` 截断，只有 `starlette/middleware/errors.py` 几帧。
但栈里的 `/usr/local/.../uvicorn/protocols/http/h11_impl.py` 提示了生产用 h11
（本地 venv 装了 httptools，默认不是它）。按这条线索逐项排除：

1. **h11 不是原因**：本地强制 `--http h11` 仍是 200。
2. **真实客户端不是原因**：`langchain-mcp-adapters 0.3.2` 连本地 hub 拿到 6 个工具。
3. **`Host` 头是原因**：本地把 `Host` 改成 `mcp-hub:8099` ⇒ **421 Invalid Host header**。

机制：`mcp/server/fastmcp/server.py:191` —— 只有 `transport_security is None` 且
FastMCP 自身 `host` ∈ {127.0.0.1, localhost, ::1} 时才自动装「只信 localhost」白名单。
hub 是 uvicorn 拉起来的，那个 host 参数恒为默认 127.0.0.1 ⇒ 白名单恒生效 ⇒
`Host: mcp-hub:8099` 落不进 ⇒ 421，卡在所有业务逻辑之前。

**为什么一直没发现**：本地全部用 `127.0.0.1` 测，白名单恰好放行。这与坑 44 是同一类
——「本地过、生产不过」的表面相似，但根因完全不同（一个是数据分支，一个是 Host 白名单）。

修法：`mcp_hub/transport.py` 作唯一构造点，保留 DNS-rebinding 防护、只加白名单
（localhost 三件套 + `mcp-hub:*`，可用 `AIOS_MCP_ALLOWED_HOSTS` 追加）；
`builtin.py` 与 `wecom_cli/server.py` 两处构造都显式传。

本地实证（h11）：`Host: mcp-hub:8099` → 200（修前 421）；`Host: unknown:8099` → 421
（防护未被关掉）；真实客户端 → 6 工具。哨兵 `_check_mcp_hub_host_allowlist.py` 9/9。
回归：`_verify_mcp_hub` 全过、`_verify_mcp_registry` 14/14、`_verify_mcp_e2e` 11/11。

**踩到的复现坑**：httpx 默认读系统代理，打本机端口会拿到代理的
`502 upstream connect failed`（不是 hub 的错）；必须 `trust_env=False`。
另外 `&` 起的 uvicorn 会被回收，验证实例必须用后台任务跑。

**保留的判断**：hub 日志里那个 500 到底是 421 被上游包一层，还是另一处独立异常，
在没有完整栈之前不下定论。重建后新代码会把真实原因写进 `message`
（`mcp_server_failed` / `mcp_server_unavailable`），H5 上直接可见。

### 三、H5「澄清卡选了没下文」+ 报错被兜底吃掉（commit 6930af2）

用户现场：澄清卡点「确认」→ 卡片变「已选择：策划书.docx」→ 整条气泡再无下文。
根因不是网络失败，是**收口逻辑静默**：`resume` 完全可能零正文产出，
此时 `text` 长度不变 ⇒ `if(!text)` 不成立（上一轮已有正文）⇒ else 用**同一段旧正文**
重渲染 ⇒ 观感「按钮没反应」。

同处更隐蔽的坑：`onError` 把 `run.failed` 真实原因写进 `tx`，但收口处
`tx` 会**整套重渲染**（有正文 ⇒ `formatAnswer(text)`；无正文 ⇒ 空输出兜底），
写进去必被冲掉 ⇒ 用户永远看不到真实报错。

改法（`send` / `oaSend` 两形态同口径）：
1. `beforeClar` 快照 + 零新增时 `appendSysNote('已提交你的选择…')` —— 必须有回音。
2. `onError` **只记账**（`errored`/`errMsg`）不写 `tx`；收口按有/无正文分两种位置呈现。
3. 判断必须写成 `if(!text){ if(errored){…} else {…} }`。
   **退化写法 `if(!text && !errored)` 会让 errored 掉进 else 被 `formatAnswer('')` 冲成空** ——
   这一版我第一次就写错了，靠哨兵 S1 抓出来。
4. 空输出兜底改成三类可执行原因（连接器未连接/已关闭、调用超时、无匹配数据）。

哨兵 `scripts/_check_clar_no_silent_deadend.py` **28/28**：`page.route` 只替换网络层、
**真跑 `send()`**；判据 R1 零正文必须有回音 / R2 负向（有正文时不许乱加提示）/
R3 有正文时中断挂正文下方 / R3b 无正文时报错进 tx / R4 三类原因 / S1 静态契约。
**写哨兵时踩的两个坑**：
- 只预先塞 `state.conversationId` 不够 —— `send()` 内的 `ensureChatPage()` /
  `ensureDefaultChatTarget()` 会重置会话态，**必须能应答 `POST /v1/conversations`**。
- `page.goto` 后 `wait_for_timeout(500)` 不够，`boot()` 会盖掉先渲染的气泡；
  要 `wait_for_function(typeof state!=='undefined')` + 2s。
负向自检三组全红（`AIOS_INDEX` 指向改坏的副本）：删兜底 ⇒ R1×3+S1×2；
兜底覆盖 ⇒ R3b×2；退化判断式 ⇒ R3b+S1。

## 修了什么（4 个真 bug，全部先证后用）

1. **数据脚本遇撇号必炸**（`tools/sandbox.py`）。旧实现 data 拼进源码

## 八、企微「未读邮件」必失败：布尔开关被拼成带值（2026-10-31 夜，实测定位）

现象：问「我企业微信里有什么未读消息」→ 助手回「调用企业微信邮箱搜索工具时出现了参数错误」→

真因（用本机真 CLI 跑出来的，`~/.workbuddy/binaries/node/cli-connector-packages/wecom-cli` 1.3.4）：

`--only-unread` 是**布尔开关不带值**（同 `--has-attachments` / `--only-subject` / `--has-star`），
而 `server.py` 拼成 `["--only-unread", "true"]`。只有 `onlyUnread=True` 才触发 ⇒ 问「未读」必炸、
问别的全好；help 里那句「true-仅未读 false-都返回」是文档通用措辞，误导。

修法：参数向量抽成纯函数 `mcp_hub/wecom_cli/argv.py`（零依赖、可离线测）；
`server.py` 全走它；**顺带给工具失败加日志**（原来 `_err()` 返回后什么都不记，
生产上只能靠模型转述猜原因 —— 这是这次能拖两轮的直接原因）。
哨兵 `scripts/_check_wecom_cli_argv.py` **24/24**：拿真 CLI `--help` 当事实源核对 4 个命令的
flag 表（该带值的带了没 / 布尔开关有没有多塞值 / flag 拼错），再加 `--dry-run` 端到端；
C1 把带值版本喂给真 CLI ⇒ 立刻 `unexpected argument`（判据非恒真）。
顺带人工核对 `auth show --status`、`auth init --noninteractive --no-browser --output-qrcode <PATH>` 均正确。

**教训**：模型转述的「参数错误」不是证据，得去 CLI 层复现；而 **工具错误必须进日志**，
否则每次都要靠猜。这类 bug 本地不报错（运行期才知道），只能拿 CLI 自己的 help 当判据。

**四个踩到的坑（会重犯，记牢）**：
1. **`line: { width: 0 }` 不等于无描边** —— pptxgenjs 会写成 `<a:ln w="12700">` + `333333`
   的 1pt 深灰实线，所有"纯色块"直接变黑框。正确做法：`line: { color: <与填充同色>, width: 0.25 }`。
   判据：`grep 333333 ppt/slides/*.xml` 必须为 0。
2. **`addTable` 会就地改写 options** —— `x/y/w/colW` 被转成 EMU（且是 96 倍），
   若在调用**之后**才 `{...o}` 快照，记录就是废的（预览里表格飞到 65836800px）。
   `addShape/addText/addImage` 不会。⇒ TB 必须先快照再调用。
3. **HTML 预览里字体名不能带双引号** —— `font-family:"SimSun"` 会截断 `style="..."` 属性，
   后面的 `font-size` 全部失效（现象：整页字号/颜色/加粗全丢，像没读到样式）。
4. **`charSpacing` 单位是 pt** —— 预览换算不能走"inch→px"的 `px()` 助手，否则字距放大 96 倍。
