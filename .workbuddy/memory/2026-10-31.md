### 本轮真机抓到并修掉的缺陷（★ 三个必须记住）
29. **业务校验失败落 500 而不是 400**：`GlobalExceptionHandler` 只把 `BizException` 与
    Spring 参数类异常映射成 4xx，**其余全落 `@ExceptionHandler(Exception.class)` ⇒ 500**。
    ⇒ 服务层**禁止**用 `IllegalArgumentException` 表达业务校验，必须 `BizException.badRequest`。
    现象极具误导性：「标题为空」看起来像「后端崩了」。
30. **本项目业务失败的正确判据是信封 `code`，不是 HTTP 状态码**：约定为
    **HTTP 200 + `code=400`**（只有 BizException 的 401/403/404 才映射 HTTP 状态，
    见 docs/36 §、docs/38 §）。e2e 按 `http_status==400` 断言 ⇒ 6 条假红。
    ⇒ 写断言先问「这个仓库的信封约定是什么」，别按 REST 直觉。
31. **e2e 写死 uid 会把组织者算成受邀人**：`zhangsan` 真实 uid=2，首版 `attendeeIds=[2,3]`
    恰含组织者本人（createMeeting 会跳过 organizer）⇒ `invited` 期望 2 实际 1。
    **这不是产品缺陷**。⇒ 期望值必须按登录返回的真实 uid 动态算。
32. **起后端必须带 `-Dspring.flyway.validate-on-migrate=false`**：本机库 V89–V95 的
    checksum 是 NULL、V100 已应用但本地文件被 revert（`d5974af` revert `cd79d79`）
    ⇒ 直接 `java -jar` 会 Validate failed 起不来。`start-all.sh` 本就带这个参数
    （application.yml 的 `validate-on-migrate: true` 只是默认，可被 -D 覆盖）。
    另：`nohup &` 起的 Java 进程会被回收，必须用受管后台任务或让用户在自己终端起。

## 第七轮：五条界面/语义反馈一次收口（已提交 `5fae151`，已推 GitHub）

### ① 连接器「关闭」改为**本次对话不调用**，不解绑（核心）
- 用户口径：「关闭时**不解绑**连接器，只是本次对话不调用对应的应用」。
  原实现点关闭调 `POST /v1/connectors/{code}/disconnect` ⇒ 企微扫码类连接器**连本机凭据一起删**，
  下次开启要重扫。
- 方案 = **对话级工具屏蔽**（与 `kb_on` 完全同构）：
  `前端集合 → disabled_connectors → Java context 快照（落库+回读）→ agent prepare 过滤
  + tools 节点执行前二次拦截`。后端连接状态/授权/trusted **全部不动** ⇒ 重开免重扫。
  真解绑保留在连接器面板「断开」按钮（确认框写明会删凭据）。
- 两形态**共用**一组函数（`mutedConnectorCodes/setConnectorMuted`），不各写一套防漂移。
- **被拦下的调用必须回注 ok=False 的 tool 消息**：丢弃会让 tool_call_id 找不到对应 tool 消息，
  上游判协议错误。回注入 agent 的 `messages`（**不在事件帧里** ⇒ 断言要直接看节点返回值）。

### ② 录音按钮被撑成大椭圆
- **根因（CSS 覆盖链）**：通用 `.cbtn`（确认卡的文字按钮）设 `flex:1 1 0px; min-width:0;
  min-height:36px`；`.oa .cbtn` 只覆盖 `flex-shrink:0` **未覆盖 flex-grow** ⇒ flex-grow 仍是 1
  ⇒ 输入栏里的麦克风被撑到 **89px 宽的椭圆**。
- 修：`.oa .cbtn` 显式写 `flex:0 0 auto` + `min-height:0`；`.oa .tl-act .cbtn` 补 `width:auto`
  （否则「接受/谢绝」文字按钮被 34px 压成方块）。
- 实测 `#oaMicBtn` **89×44 → 44×44**。⚠️ 目标值是 44×44 不是 34×34：
  后面还有全局命中区规则 `.oa .cbtn{width:44px;height:44px}`（移动端 ≥44px 标准）。

### ④ 「提供的 chat_id 无效」
- 根因：`recent_group_sessions` 返回字段叫 **`ref`**，而 `session_messages` 入参叫 **`chat_id`**，
  且 `ref` 的描述写着「不要向用户展示」⇒ 模型拿到 ref 却不填 chat_id。
- 修：返回字段统一为 `chat_id`（**保留 `ref` 兼容别名**），两处工具描述改写
  （「原样取自…不要自己拼、不要用群名替代」）。
- 真机已闭环：chat_id `wrbVcoRgAAzrx2_jz2N8UG5blijiax_Q` 原样喂回 session_messages ⇒ 取到 5 条真实消息。

### ⑤ 顶部机器人区随滚动渐隐
- 沿用既有 `--hd` 连续插值机制扩展到 `.stage`（**只在 `.chatting` 下**）：
  scrollTop 0/30/60/90/120 ⇒ opacity 1/0.75/0.5/0.25/0、translateY 0/-6/-12/-18/-24。

### 新增坑（33–38）
33. **对话级开关的通用做法**：凡「只影响本次对话、不改持久状态」的开关
    （KB 开关 `kb_on`、本轮 `disabled_connectors`），统一走
    `顶层字段 → Java context 快照（落库+回读）→ agent 顶层字段`。
34. **`.cbtn` 这类通用类必须显式写全 `flex`**：只写 `flex-shrink` 等于没写
    （flex-grow 默认 1 仍在生效）。
35. **事件帧里没有 tool_call_id**：tool_call_id 只在图状态的 `messages` 里
    ⇒ 断言「被拦下的调用有回注」必须直接调节点看返回值，在 SSE 帧里找会假红。
36. **`patch.object(类, 方法, 假函数)` 会变成绑定方法**：多传一个 `self`
    ⇒ 假函数签名要写 `async def f(self, name, arguments=None)`。
37. **`--hd` 是写在 scroll 事件监听器里的**（`oaSyncDockFade` 是 IIFE 内函数、不挂 window）：
    设 `scrollTop` 后**必须等一拍**再读；scrollTop=0 且从未滚过时 `--hd` 是**空串**
    （靠 `var(--hd, 0)` 兜底，语义上就是 0，别判成 None）。
38. **「我看到 46 个插件」要核到接口与来源**：实测 64 条全是 `tool_definition` 里的系统内置工具
    ⇒ 问题不在数字，在**命名与来源未交代**。
