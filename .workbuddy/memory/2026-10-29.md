## 调研：企微接入 MCP 的完整步骤 + WorkBuddy 式连接器实现机制（12:3x）

交付：两部分说明（企微侧 6 步配置 / MCP 侧 5 步实现 + 连接器 7 个关键机制），全部标注文档来源。
关键事实（已核官方文档）：
- 企微**没有**「接入 MCP」的官方能力；MCP 是 Agent 宿主侧协议 ⇒ 接入 = 写 MCP Server 包住企微 API。
- 凭证三件套 corpid/agentid/secret 位置见 90665；可见范围**同时是权限范围**（含「能为哪些成员调接口」）。
- gettoken：7200s、**按应用隔离**、必须缓存（频繁调会被限频）、可被提前失效 ⇒ 需重取逻辑（91039）。
- 可信IP：仅 IPv4、不支持 IP 段/通配、每应用上限 120、须公网 IP（help2/pc/21711）。
- 可信域名：OAuth 回调域名**每应用只能 1 个**、需 ICP 备案、需企业已认证、WW_verify 校验（help2/pc/21316）。
- 回调：URL/Token/EncodingAESKey；GET 验证须 **1 秒内**回明文 echostr；POST **5 秒内**应答、重试 3 次；回调 URL **不支持写 IP**（90930）。
- 发消息配额：单成员 **30 次/分钟、1000 次/小时**；每日 账号上限×200 人次；接收人不在可见范围 → invaliduser（90236）。
- 网页授权：scope=snsapi_privateinfo 必须带 agentid，否则降级为 base；要求成员在可见范围内（91022）。

**MCP 规范重要变化（2026-07-28 latest）**：取消 initialize 握手、改为**每请求 `_meta`**（protocolVersion/clientCapabilities）；
**服务端不再发起 JSON-RPC 请求**（与 2025-06-18 相反）⇒ 人机交互改用 `tools/call` 返回 `resultType=input_required`
+ `inputRequests`，客户端带 `inputResponses`/`requestState` 重放（id 必须不同），老版本客户端走兼容回退。
⇒ 影响现有 hub：FastMCP 现实装属 2025-06-18 一代（initialize + 服务端 elicit），上 2026-07-28 原生客户端需按新语义补适配。
transport 只剩 stdio 与 Streamable HTTP（单端点 POST / 请求级 SSE）；授权基线 OAuth 2.1 + RFC9728/8707 + PKCE + Client ID Metadata Documents（DCR 已弃用但仍兼容）。

## 启动应用（20:52）可复用做法

`bash start-all.sh` 的后台子进程**会随调用它的 bash 任务结束被回收**（实测：脚本跑完后 7 个端口全 DOWN）。
可用做法 = 在**同一个后台任务里**先跑 `bash start-all.sh`，再挂一个长 `sleep`，任务不结束进程就活着；
但这是「会话内可用」，用户要长期跑仍需在自有终端执行 `bash start-all.sh`。
启动前必须 `unset SERVER__PORT` 并 `export SPRING_APPLICATION_JSON='{"server":{"port":8080}}'`（覆盖该死端口）。
起来后 7 端口：8080 后端 / 8000 agent / 8099 hub / 5181 H5 / 5173-5175 管理端三应用；
`/aios/h5/`、`/aios/web/` 均 200，admin 登录 token 263 字符。
注意 start-all.sh 里 hub 是 **WECOM_MOCK=1**（本地开发态），真机联调要改 `WECOM_MOCK=0`。

## 企微真机联调：两个必须记住的坑（22:50 实测）

1. **`gettoken` 不校验可信 IP，业务接口校验**。所以「gettoken errcode=0」绝不能当成「IP 已加白」——
   实测同一台机同一 IP：gettoken=0，而 agent/get、user/list 全 60020（errmsg 里带 `from ip: x.x.x.x`）。
   已做成自检工具 `scripts/wecom_ip_check.py`（环境变量传凭据，两步都打并给结论，退出码 0/1/2）。
2. **`WECOM_MOCK=1` 时 hub 身份恒为 `mock-tenant/mock-user`** ⇒ 管理端填的企微凭据落在
   `wecom_tenant_config.tenant_id='mock-tenant'`。切 `WECOM_MOCK=0` 后读的是真实 tenantId，
   **这份配置读不到，必须重填**（否则现象是「管理端显示已配置、用户端仍报待配置」）。
   已在 `start-all.sh` 把 `export WECOM_MOCK=1` 改为 `"${WECOM_MOCK:-1}"`，真机用 `WECOM_MOCK=0 bash start-all.sh`。

家宽动态 IP 实证：同一天出口从 `116.169.80.194`（上午）漂到 `116.169.10.253`（22:50）。
⇒ 家庭宽带上加白只能临时可用；长期必须固定公网 IPv4。
