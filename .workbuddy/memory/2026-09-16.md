- **新增可配置维度会造出旧状态机从未有过的组合**（此处 `configured=true` + `enabled=0`）→ 必须为该组合显式补断言，否则「视图说谎」这类缺陷任何既有套件都照不到。
- **子代理启动的长驻服务会随子代理死亡**：测试 worker 被 429 杀掉后，它拉起的桩(8090)一并消失，导致我首次跑套件全红。桩/后端**必须由主代理以后台常驻任务启动**。
- 限流期间队友不可用 → 主代理直接接手跑套件与浏览器校验，**不等待、不猜测**队友结果。
- 未采用放宽断言换取转绿：worker 如实报 `BLOCKED=24`（后端未部署），部署后重跑转真绿。

### 遗留（非缺陷，已记入 `MEMORY.md` §4）
`GET /gitee/tenant-config` 不传操作人 → `orgVerified=false` + 「未提供操作人」，「未探测」与「探测失败」在该字段上不可区分；UI 仅保存后读取，无功能影响。

## 排查：仓库地址全为 127.0.0.1、点击跳不到 Gitee（用户投诉）

### 结论：**不是代码缺陷，是部署接线（配置）问题**；但查出 2 个真实缺口
| 结论项 | 定性 | 决定性证据 |
|---|---|---|
| 四地址全本地 | **配置问题**（后端 base-url 指向本地桩） | 对照实验：**只让桩改按 `https://gitee.com` 返回，四个地址即刻全变公网，零代码改动** |
| 点击跳不到 Gitee | 配置问题的下游（跳转实现本身对） | 真点击捕获新标签页：本地→`127.0.0.1:8090`；公网→`https://gitee.com/...` |
| `web-base-url` 配了没用 | **代码缺陷（轻微）· 死配置** | 全代码库零引用（仅 `GiteeProperties:27` 声明 + yml 绑定） |
| 地址=建仓快照、**无刷新路径** | **设计缺口** | 全库仅 `GiteeRepoTaskHandler:98-100` 一处赋值；撤销 public-base 后存量行地址不变 |
| Webhook 注册成 `127.0.0.1` | **配置问题，会静默失效** | 桩侧钩子 URL 取证：`http://127.0.0.1:8080/api/v1/gitee/webhook/{id}` |

### 关键代码事实（勿再误诊）
- 地址**不是本地拼的**：`GiteeRepoTaskHandler:98-100` 把接口响应的 `html_url/ssh_url/https_url` **原样写库**；`GiteeProjectService:221-227` 原样读出；`cloneCommand = "git clone " + sshUrl`。前端**无任何兜底域名**（`grep gitee.com` 在 shell/H5 零命中）。
- 链接相关配置共 5 项：`base-url`（地址唯一来源）/ `web-base-url`（**死**）/ `redirect-uri` / `webhook-base-url` / `bind-return-url`。后三项本机均为本地地址，**生产必改**；`token-enc-key` 默认值可离线解密令牌，生产必换。

### 手法沉淀（下次遇到同类问题直接用）
**「展示值来自外部接口」这类问题，不要靠读代码下结论，要用「让桩返回生产形态」做对照实验。** 给 `gitee_stub.py` 加了 `/_stub/public-base`（默认 None=历史行为逐字节不变，纳入 `state`、`reset` 清理），使"换成真 Gitee 地址会不会变"从推断变为**可执行验证**。同理适用于任何「外部系统返回什么就展示什么」的功能。
