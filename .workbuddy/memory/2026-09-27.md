# 批次 B：机构类型收敛 + 统一社会信用代码校验（同日稍后）

## 1. 用户列的「补 2 类」背后是**三套枚举并存**（实测，不是推测）

用户规格是「机构分 政府/企业/事业单位/社会组织/其他」。实测发现：
- 后端 `OrgInstitution` 只有 `GOVERNMENT / ENTERPRISE / ASSOCIATION`；
- 前端 `InstitutionView.vue` **硬编码**下拉 `GOVERNMENT / INSTITUTION / STATE_OWNED / PRIVATE / ASSOCIATION`；
- 演示种子 `seed_multi_tenant.py` 跟着前端那套发 `STATE_OWNED / PRIVATE / INSTITUTION`。

⇒ 后果**全是不报错**的那种：库里最多的 `ENTERPRISE`（10 行）在管理端下拉里**选不到**，
编辑既有企业机构时下拉显示裸码；用户选「国有企业/民营企业」写库的 `STATE_OWNED/PRIVATE` 后端不认识、列表标签标不出来。
**判据**：一个枚举若在两处各写一份，缺陷不会以"报错"形式出现，只会让数据慢慢变成两套口径 ——
所以"补 2 类"不能只加常量，必须**收敛到一处 + 把旧取值必须被拒写成断言**（否则只是"前端不显示了、后端照收不误"）。

## 3. 两个量过的取舍（别被后人"顺手加严"）

- **不校验信用代码第 18 位校验位**：实测本库 4 条 + 种子 8 条代码**全部通不过** GB 32100-2015 校验位算法
  （都是合成演示数据）。强制校验位 = 一次性拒掉 100% 现存数据与全部种子/回归，收益为零 ⇒ 只校验长度/字符集/形状。
  这条写进了类注释，防止后人加严成"数据不可用"。
- **不加 `credit_code` 库级唯一索引**：唯一性在服务层按 `deleted_at IS NULL` 判；加库级唯一键会让
