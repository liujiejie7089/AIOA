## 三、修复 1：通讯录排除自己（`user-client/_oa_app.js` `loadOrgMembers`）

- 事实：`/v1/org/members` 返回**员工档**（`id`=员工 id、`userId`=账号 id、含 `accounts[]`），
  自己确实在列（fagai_li=userId 8 实测在 5 人列表里）。`/v1/org/profile` **不是**「我」
  （是机构统计），登录者在全域 `state.user`（`{id,username,nickname,roles}`）。
- 改法（唯一调用点）：按 `x.userId !== state.user.id` 过滤；真排除时 `res.total -= 1`，
  否则「共 N 人」与卡片数口径漂移。经典形态**没有**第二处调该接口（全仓 grep 确认）。

## 四、修复 2：项目面板接真 PM 模块（`_oa_app.js`）

- **根因**：H5「任务 → 项目」面板是 PM 模块（V71）**之前**写的占位实现 —
  拿「我发起的 + 本部门名义发起」的**审批单**按业务类型归集冒充项目，hintbar 还写着
  「后端暂无独立项目模块」。PM 上线后没人接进来 ⇒ 成员当然「收不到」项目。
- **后端可见性本身是对的**（实测）：`canSee`（唯一判定点）= 租户/机构管理员全量 +
  本部门项目 + 本人参与（BR-15）。fagai_li 原来看到 0 条是因为他不是任何项目成员且
  项目挂部门 0；把他加进 T1008 两项目后立刻可见 2 条。**先验后端再改前端，避免误修**。
- 改法：`oaRefreshView('collab')` 拉 `/v1/pm/projects?pageSize=100` 存 `S.projects`；
  `renderProjectPanel()` 重写（类型 chip / 任务 done+count / 成员 / 开发项目带仓库计数 /
  状态中文标签与 `constants/permissions.ts` 同源）；rail 计数同源；删 `projectGroups`
  与假 hintbar。空态文案说人话：「被加为项目成员、或项目挂到本部门后在此可见」。
- 成员加入**没有**消息通知链路（PM 批次 1 未含通知），「收不到」的修法就是让面板读到
  真数据 —— 没有静默假装有通知。

## 七、可复用教训

1. **先怀疑探针**：首版哨兵对「负向账号」断言的对照同事写死成「刘敏」，而负向账号正是
   刘敏本人 —— 他在自己通讯录里被排除恰恰是功能正确。对照物必须**按账号参数化**。
2. **「界面没有」≠「后端不给」**：本次「成员收不到项目」后端可见性规则（BR-15）本就支持，
   是 H5 面板从没调过 PM 接口。改前端前先拿成员账号 curl 一次 `/v1/pm/projects`。
3. **H5 登录不带 tenantName**（后端按用户名唯一性解析租户）；PM 建项目 `projectNo` 必传。
4. **遗留占位实现要定期扫**：「后端暂无 X 模块」这类 hintbar 在模块上线后会变成谎言
   （违铁律 1）。本次已在 `_e2e_oa.py` 确认无套件钉住旧文案，但**没有**套件钉住项目面板
   本身 —— 新增 `_verify_h5_pm_contacts.py` 补上这个洞。
