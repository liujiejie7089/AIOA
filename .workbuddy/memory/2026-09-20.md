### 三个关键设计决策（踩过的坑）
1. **连通性校验必须在持有密钥的一侧做**：最初写在服务端直接打供应商 —— 但服务端容器通常没有供应商 Key
   （Key 配在 agent 侧），会把「本进程没配 Key」误报成「模型连不通」。改为服务端委托 agent
   `POST /internal/v1/models/check`，校验前先 `push()` 保证 agent 用最新配置。
2. **密钥来源判定以运行时为准**：服务端读不到、但 agent 侧已加载同一环境变量时，若显示「未配置」就是假话。
   故 `apiKeySource` 第三档去问 agent `GET /internal/v1/models` 的 `api_key_configured`。
3. **禁用集合与规格注册必须解耦**（冒烟实测抓到）：原 `apply_overrides` 遇 `enabled=false` 就 `continue`，
   规格根本没注册 ⇒ 「先保存（停用）→ 再点启动」永远失败（报「模型未注册」）。已改为照样注册、只加禁用标记。
   另补：下发是全量的，不在本次列表且非内置键的即视为已删除，一并清规格与内存 Key。
4. **掩码往返**：列表只回掩码，管理员打开编辑再保存会原样回传 → 服务端必须识别含 `****` 的值并**保持库里密文不变**，
   否则真实密钥会被覆盖成 `****`。
