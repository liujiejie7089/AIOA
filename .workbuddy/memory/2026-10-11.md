## 六、★ 提交竞态（本轮实际踩到，值得进铁律）

**现象**：我 `git add` + `commit` 的那一刻，worker 正在执行我要求的「非空证明」——
它按我的指令**故意把条件翻反**（证明单测会变红），而那一次 `git add` 恰好落在翻反的间隙，
于是 `354ca1b` 把**故意错误的中间态**当成交付物固化（HEAD 里是 `if (!scoped)`，工作区是 `if (scoped)`）。
后续 `7e0a95f` 已修正。

**判据（怎么发现的）**：提交后 `git status` **不为空**（worker 又改回了正确版）→ 一 diff 就看到方向相反。
若当时没查 `git status`，这个错版会被当成「已修好」交付出去。

**铁律候选**：**worker 在跑「翻反/置空以证判据会红」这类非空证明期间，其工作区会短暂处于故意错误的状态 ——
此时不要 `git add`/`commit`**。做法：等它回报「已还原并复跑为绿」，或先让它停手，
再以自己的复核（编译 + 实跑）确认终态后提交。**每次提交后立刻 `git status --porcelain`，必须为空。**

### 9.1 上传窗口打不开 —— 两个独立的真缺陷叠加
**缺陷 A：从「异步续段」里触发需要用户手势的能力 ⇒ 被浏览器静默拦掉。**
  `oaMaybeProjectAction` 的 `UPLOAD_FILE` 分支原来调 `oaUploadProjectDoc()`，它是
  「动态造 `<input type=file>` 再立刻 `click()`」。而这条调用链是
  `oaAfterOaAnswer()` 在 `await 整段回答流式生成` + `await /v1/workers/intent` **之后**才走到 ——
  距用户点「发送」已过数秒乃至数十秒，**用户手势的瞬时激活早已失效** ⇒ `click()` 被**静默忽略**
  （不抛异常、不弹窗、控制台无报错），用户只看到一句「正在打开文件上传窗口」。
