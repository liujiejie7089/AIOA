### 本轮发现的真实缺陷（已修）
- **「删除会话」实际不生效**：`ChatConversation` / `AgentRun` 都没挂 `@TableLogic`，

  统计照旧计入，删除按钮等于失灵。已补 `.isNull(...DeletedAt)`，并把 `getOwned()` 的已删会话按不存在处理。

### 关键坑（新增）
- **写统计接口前先确认实体的删除语义**：本项目一半实体挂 `@TableLogic`（自动过滤）、
  一半靠手写 `deleted_at`（必须自己 `isNull`）。`selectCount` 不过滤就会把已删数据算进「真实统计」。
- **比对分页列表的总量要用 `total` 而不是 `len(list)`**：`/conversations` 默认 20/页，
  `len()` 恒 ≤20，拿它当总量会得出「统计虚高」的错误结论。
- **`@RestControllerAdvice(Exception.class)` 兜底会吞 AccessDeniedException**（V33 已记录）；
  本次复核确认 `NoResourceFoundException` 也已补 404。

### 本轮修的真实缺陷
1. **`ContentReviewController.review-records` 三元表达式自动拆箱 NPE**：
   `platform ? tenantId : (u.getTenantId() == null ? 0L : ...)` —— 前两个分支是 `Long`、比较/赋值途中被自动拆箱，
   平台管理员侧 `tenantId` 为 null 时直接 NPE → 审核记录接口 500。改为全程 `Long` 包装、显式判空。
2. **驳回的授权单没有处理方留痕（需求④核心）**：`granted_by/granted_at` 语义是「终态处理人/时间」，
   V36 只有 `onApproved` 写过这两列 → 历史 REJECTED 行处理人为空，审核记录展示不出「谁处理的」。
   `onRejected` 补写 `granted_by = lastTask(orderId, REJECTED).approverId`、`granted_at = decidedAt`、`auditNote = note`。
   **同时必须回查 `approval_task`**：回调拿到的 `order` 是**决策前快照**，直接读 `order.decisionNote` 会记成 null。
3. **历史遗留行数据修复（V38）**：只修代码救不了已存在的空值行 → 新增 V38 从关联单据的
   **seq 最大的已决节点**反查回填三列。踩点：驳回场景 `seq=1` 是 REJECTED、其后是 SKIPPED，
   只认 APPROVED 会取空；三重 `WHERE`（终态 + 原值空 + 有单据）保证幂等；不触碰 `approval_task`（审计链不回写）。
4. **`PermissionCatalog` / `PermissionGrantService`**：新增 `applicablePermissions()`/`rolesText()` 供
   H5 角色类型目录消费 `canApply`（把「无权限申请入口」的死胡同改成申请出口）；`mine()`/`holdings()` 补
   处理方与来源（角色内置 vs 授权发放）。
