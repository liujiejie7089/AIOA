## 后端报错清理 + 首页顶部样式 + 开通租户强制密码（14:30–15:20）

### 日志分类结论（先分类再动手，别一头扎进栈里）
`logs/boot.log` 全量聚类后只有 4 类 ERROR，其中 **2 类是真缺陷、2 类是历史假象**：

| 现象 | 判定 | 处置 |
|---|---|---|
| `No task executor bean found for async processing`（13:34 等） | 真缺陷：`@EnableAsync` 无 Executor Bean，`@Async` 退化为 SimpleAsyncTaskExecutor（每次调用一个线程、不复用） | `AsyncConfig` 补 `@Bean("taskExecutor")` ThreadPoolTaskExecutor（core4/max16/queue500/CallerRuns） |
| `ClientAbortException` 被记 ERROR + 二次 `HttpMessageNotWritableException ... preset Content-Type 'text/html'` | 真缺陷：客户端断连（刷新/切网）被当服务端故障 | `handleServer` 前置 `isClientAbort()`（按类名走 cause 链，**不 import Tomcat** —— common 模块编译期看不到 tomcat-embed）→ 499 + debug |
| `NoClassDefFoundError: RunCreatedResponse / JsonNodeType / ApplicationContext$DispatchData`（10-19 18:0x–18:3x） | **历史假象，不是代码 bug**：运行中覆盖 jar 导致类加载器拿到半个 zip | 不修；判据是「同一时间窗内出现多个互不相关的类缺失」 |
| `HikariPool - Thread starvation or clock leap (delta=10h45m)` | 假象：宿主休眠 10h45m，不是池耗尽 | 不修 |

### 本轮新发现（由「断连测试」逼出来的真缺陷）
`produces=text/event-stream` 的端点（`/api/v1/runs/{id}/events`、`/api/v1/agent/tasks`、`/resume`）抛业务异常时，
`handleBiz` 仍回 JSON ⇒ Spring 找不到可写表示 ⇒ **错误处理器自身失败**：日志 `Failure in @ExceptionHandler` +
Tomcat 再打一遍完整 ERROR 栈，客户端只拿到错误页。**这与历史那条 `HttpMessageNotWritableException` 同根因。**
修法：`GlobalExceptionHandler.respond()` 按 `Accept` 分流 —— SSE 请求回 **HTTP 200 + `event: error` + 单行 JSON**
（EventSource 对非 2xx 只会笼统报错并无限重连，200 才能把原因送到前端；管理端 `api/runs.ts` 已 `JSON.parse(event.data)` 取 `message`，H5 `_sse` 已处理 `ev.event==='error'`）。
顺带补 `handleNotAcceptable`：对 SSE-only 端点发 `Accept: application/json` 由 **500「服务内部错误」改为 406**（与既有 `MethodArgumentTypeMismatch`/`NoResourceFound` 同一原则：让错误归它的类）。

## P0–P2 实装完成（收口 @ 2026-10-20 21:2x，commit 4453544）

按 `docs/59` §10（2026-10-20 冻结）落地，**与上面的早期规划有 4 处口径变更**，以 §10 为准：

| 项 | 早期规划 | 定稿 |
|---|---|---|
| 工具名前缀 | `connector__` | **`mcp__<serverCode>__<toolName>`**（对齐 WorkBuddy/Claude Desktop） |
| 网关名 | connector-mcp-gateway | **mcp-hub**（`D:/aios/mcp-hub/`，FastMCP Streamable HTTP，:8099） |
| 内置工具调用回程 | 未定 | hub → `POST /api/v1/mcp/builtin/<code>/call` **+ 用户 token**（不走 `/internal/**` 服务令牌，避免多一个鉴权面） |
| 外部服务器 | 未定 | manifest 给**上游直连地址**，不经 hub 代理（不把解密后的 headers 复制到第二个进程） |

**三层落点**：Java `server/aios-resource/.../connector/mcp/`（9 端点 + 三闸门）→ `mcp-hub/`（无状态转发）
→ agent `ToolClient.list_mcp_tools()`（manifest → 并发 get_tools → 前缀化）。

**闸门顺序（易错）**：未信任 **优先于** 未连接 —— 都没信任的服务器被调时文案必须是「尚未信任」而不是「未连接」
（M8 就是钉这个顺序的）。

**本轮被哨兵打出来的 3 个真缺陷（都已修，且都留了回归判据）**：
1. **h2c 升级吞请求体**：JDK `HttpClient` 默认发 HTTP/2 升级，uvicorn(httptools) 不收 ⇒ hub 收到空 body，
   回「未知 transport：None」。修法：`McpProbeClient` 显式 `.version(HTTP_1_1)`。**判据不是看状态码**，
   而是看 hub 收到的 transport 字段（502 → 200 但 body 丢，只有解析 body 才看得出来）。
2. **lastError 永不消失**：MyBatis-Plus `updateById` 的 NOT_NULL 策略会**跳过 null 列** ⇒
   「探测成功后清空 lastError」写成 `setLastError(null); updateById()` 是静默无效的，界面永远挂着上次的错。
   修法：`persistProbe()` 用 `LambdaUpdateWrapper.set(..., null)`。**判据 E2b：由失败转成功后 lastError 必须为 null。**
3. **软删行永久占唯一键**：`delete` 是逻辑删除（`deleted_at`），而 `uk_mcp_server(tenant_id, code)`
   **不含** `deleted_at` ⇒ 删掉再注册同一 code 直接撞 DuplicateKey 回 **500**（E2E 第二遍必红）。
   修法：`registerExternal` 先 `selectIncludingDeleted`（`@Select` 手写，绕开 `@TableLogic`）：
   活着 ⇒ 400 明确重名；已软删 ⇒ 物理清 server + 工具目录后重新 insert。判据 **E9**。

**验收矩阵（五套全绿，命令都能直接抄）**：

1. **H5 授权成功后 MCP 区不重拉**：`refreshConnectors()` 只重置 `connectorsLoaded`，没重置 `mcpLoaded`，
   而 `loadMcp()` 有幂等闸 ⇒ MCP 卡片永远停在 `connected=false` → 「连接器未连接」。
   修在 user-client/_oa_app.js；哨兵加 P8（变异证明：撤掉那行 → P8 两条红，证据显示只重拉了 /connectors）。
2. **read_message 正文恒为 ""**：`headerField()` 用 `^(.*)$` 只吃单行，而 QQ/钉钉的
   `Content-Type: multipart/alternative;\r\n\tboundary="..."` 是折行头 ⇒ boundary 取不到 ⇒ 返回空串。
   修法：加 `unfold()`（`\r?\n[ \t]+` → 空格），在外层与每个 part 都展开。新增 `ImapBodyParseTest` 4 例；
   变异验证：撤掉 unfold → 折行头用例红。
3. **纯文本只是占位**：钉钉邮件的 text/plain 就是 "Your email client does not support HTML messages"（48 字节），
   真内容只在 HTML。修法：`isStubPlain()`（≤120 字符且含“不支持 HTML”类字样）→ 回退 HTML 段。
另：`parseFetchHeaders` 不再把原始头字节以 base64 暴露给模型（`KEY_RAW` 解析后摘除）。
