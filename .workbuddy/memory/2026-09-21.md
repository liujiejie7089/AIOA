### 二、为什么没写进去 —— `sed` 拼变量有两个陷阱（已实测复现）

现场两条 `sed -i "s|^KEY=.*|KEY='${VAR}'|"` 都报
`sed: -e expression #1, char NN: unknown option to 's'`。受控实验（本地 sed）：

| 值里的字符 | 结果 |
|---|---|
| `\|`（与分隔符同字） | **硬报错** `unknown option to 's'` ⇒ **整条命令失败、值静默没写**（屏幕上只有一行报错） |
| `&` | **不报错，但值被改坏**：`&` 展开成「匹配到的整段原文」。实测 `a&b` → `aMINIMAX_API_KEY=zzzb` |
| `/` `#` 空格 `'` | 无影响 |

⇒ **结论：绝不把用户输入的口令拼进 `sed` 的替换段。** MySQL 那次更直接 —— 只 `read -rsp` 进了变量，
**根本没有写盘命令**，口令就这么丢了。

**起点**：用户判断「没部署 Ollama 应该不影响向量库切片，数据应该落在 milvus」。核代码后**一半对一半错**：
- ✅ 对：**文本切分**确实不需要嵌入服务，`kb_chunk` 照常入库；
- ❌ 错：当时 `deploy/.env` 是 `provider=http → ollama:11434`（Ollama 未部署）⇒ `HttpEmbeddingProvider.embed()`
  **抛异常** → `KbService.embedAll` 逐切片 catch 后只告警 ⇒ **向量全缺失**（MySQL 里也没有），
  `indexChunk` 压根不会被调用 ⇒ **Milvus 一条都没有**；且检索侧 `search()` 要嵌 query，会直接报错。
  ⇒ 「切片不受影响」成立，但「数据落在 Milvus」在旧配置下**不成立**。

**顺带挖出真正的坑（本次修的重点）**：`embedding.dims` 与 `milvus.dims` 分处两个配置键，
**此前只有文档一句「两者必须一致」，没有任何机器校验**。一旦不一致：向量照写 MySQL、
`indexChunk` 发现维度不符 `log.debug`+return（Milvus 静默一条不收）、`cosine` 对维度不符返回 0
⇒ **接口全成功、永远检不到**。与 ES 骨架「静默返回空」同类，只是藏在写入侧。

**代码修复**（3 文件 + 1 新测试）：
- `MilvusConfig.assertDimsAgree(...)`：**建集合之前**硬校验 `provider.dims() == milvus.dims`，
  不一致直接启动失败；文案含两个实际维度 + 「local 写死 256 维」这一事实 + 「必须换集合名」+「不修是静默的」。
- `MilvusKnowledgeStore.indexChunk`：维度不符 `debug` → `warn`，并写明修复动作（开 `REEMBED_ON_START` 重算）。
- `EmbeddingConfig`：`provider=http` 时启动探一次真实端点，**不通只打 ERROR 不阻断启动**（避免把后端
  卡在与自身无关的上游上），文案给两条出路。
- `MilvusDimGuardTest` **6/6 通过**；`aioa-resource` 全量 **32/32 通过**（含既有 26 例零回归）。

**配置**：`.env` / `.env.production` §7 改为本次档位 `store=milvus` + `provider=local` + `dims=256` +
集合 `kb_chunk_v1_256`；http 档 5 键**保留不注释**（否则 `compose-lint` 会新增「静默吃默认值」告警）。
`AIOA_MILVUS_BACKFILL` 由「可选」升级为**首次接入必做一次**并给出日志判据。

**本机实跑（`store=mysql`/`provider=local`，:8080 活体）**：上传 → `chunkCount=1` →
`kb_chunk` 落 `provider=local / dims=256 / embedding=1024 字节` → `mode=hybrid` 命中 `score=0.1887`。
⇒ 无 Ollama 时切片+向量化+检索在 mysql 档**完全通**。

**判据（写进手册 §6 第 9 条）**：证明「数据真落进 Milvus」的权威判据是 **`mode=vector` 命中且 `score` 非 null**
（稠密腿只查 Milvus）；对照诊断：**`bm25` 有命中而 `vector` 空 = 典型「MySQL 有、Milvus 空」**
（bm25 腿在集合 BM25 建失败时回落 MySQL，单独命中不足以证明 Milvus 有数据）。
