### 一、`MySQL 口令长度=22 / Redis 口令长度=25` 之谜 —— 已证伪「口令短了」

**根因（已证实）**：那两个数是**占位符本身的长度**，口令一个字都没写进去。

- 实测 `CHANGE_ME__db-password` = **22** 字符、`CHANGE_ME__redis-password` = **25** 字符，与现场输出**逐字对上**。
- 现场 `grep -nE 'CHANGE_ME__' .env | grep -v ':#'` 输出 3 行（59/64/76）——手册原话是「应无输出」，用户没注意到。
- **交叉验证代码来源**：把现场 `grep` 打出的行号（59/60/61/63/64/76/77/78/79/112）与本地 `.env.production`
  逐行比对，**完全一致** ⇒ 服务器上那份模板就是我 `03674c9` 之后的版本，代码是最新的。
- `MINIMAX_API_KEY` 也是空。现场那条 `grep -c '^MINIMAX_API_KEY=.\+'` 返回 1 是**假通过**：
  模板该行 `=` 后面有一串**对齐空格**+行尾注释，`.\+` 匹配到的是空格。

### 二、为什么没写进去 —— `sed` 拼变量有两个陷阱（已实测复现）

现场两条 `sed -i "s|^KEY=.*|KEY='${VAR}'|"` 都报
`sed: -e expression #1, char NN: unknown option to 's'`。受控实验（本地 sed）：

| 值里的字符 | 结果 |
|---|---|
| `\|`（与分隔符同字） | **硬报错** `unknown option to 's'` ⇒ **整条命令失败、值静默没写**（屏幕上只有一行报错） |
| `&` | **不报错，但值被改坏**：`&` 展开成「匹配到的整段原文」。实测 `a&b` → `aMINIMAX_API_KEY=zzzb` |
| `/` `#` 空格 `'` | 无影响 |

⇒ **结论：绝不把用户输入的口令拼进 `sed` 的替换段。** MySQL 那次更直接 —— 只 `read -rsp` 进了变量，
**根本没有写盘命令**，口令就这么丢了。

### 三、新增两个脚本（替代 sed / 补齐体检）

- **`deploy/ops/set-secrets.py`**：按行整体重写 `KEY=…` 那一行（不做模式替换），因此对
  `$ | & # ! ' " \` 和空格全安全。自动选最稳引号（无 `'` 用单引号；有 `'` 只能双引号 + `$$` 转义）、
  **回读校验长度逐字节一致**、再用 `docker compose config --format json` 核对**容器真正收到的值**。
  支持 `--check`（只体检）/ `--only mysql,redis,minimax` / `--from-env`（配 `read -rsp`，口令不进历史不进 ps）。
  顺带把 CRLF 统一成 LF（`\r` 混进口令会多一个隐藏字符 ⇒ 鉴权失败且极难查）。
- **`deploy/ops/host-check.sh`**：部署机只读体检 —— 身份/资源、git 版本、占位符残留、口令长度、
  Docker 与镜像清单、**外网与 4 个加速器的逐个通断**、镜像齐备度。

### 四、★ 新发现的硬阻断：应用机拉不到 Docker Hub

现场：`failed to resolve reference "docker.io/minio/minio:latest" … dial tcp 31.13.94.41:443: i/o timeout`；
`nginx:1.27-alpine` / `ollama/ollama:latest` 同样超时；`ping baidu.com` 100% 丢包；
`docker run --rm mysql:8.0 …` 卡在 `Unable to find image … locally`。

- 解析到的 `31.13.94.41` 是 **Facebook 段** —— 典型 **DNS 污染**特征，**不代表一定没有外网**。
  ⇒ 所以 `host-check.sh` 把「国内站点 / 各加速器」分开单独探测：能上国内网就只需配 `registry-mirrors`。
- 完全出不去时的正路：**离线搬运**。新增 `deploy/ops/offline-images.sh`（`export` / `import` /
  `import-ollama` / `list`）。
  - 关键便利点：`docker-compose.yml` 顶层写了 **`name: aioa`** ⇒ 两台机构建出的镜像名**完全一致**
    （`aioa-server` / `aioa-agent` / `aioa-web`），所以 `docker load` 后 **`docker compose up -d` 不要加 `--build`**
    （加了会重新构建，而目标机拉不到基础镜像，必然失败）。
  - 默认档需要的 5 个镜像：`minio/minio:latest`、`nginx:1.27-alpine`、`aioa-server`、`aioa-agent`、
    `aioa-web`；可选 `ollama/ollama:latest`（**KB 语义嵌入要用**，模型 `quentinz/bge-small-zh-v1.5`）。
  - Ollama 模型单独打 `ollama-models.tar.gz`，导进命名卷 `aioa_ollamadata`（`/root/.ollama`）。

### 五、行尾隐患（顺手修掉）

本仓库 `core.autocrlf=true`：Windows 检出的 `.sh` 是 CRLF，拷到 Linux 会报
`\r: command not found` / `bad interpreter`；`.env` 混进 `\r` 会让口令多一个隐藏字符。
⇒ 新增 **`.gitattributes`**，把 `*.sh`、`deploy/ops/*.py`、`deploy/.env*`、`.env*` 锁成 **LF**。
