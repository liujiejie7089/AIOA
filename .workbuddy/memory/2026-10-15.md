## 用户回传后端 ERROR 日志：两类错误，一类是代码 bug，一类是暴露面

用户给的日志里其实是**两个互不相关**的错误，日志时间戳跨 2026-10-13 10:27 → 2026-10-14 10:22。

### 一、类 A —— `Invalid character found in method name [0x16 0x03 0x01 ...]`
- **不是 bug**。`0x16 0x03 0x01` = TLS ClientHello（TLS1.0 record）打到**明文** 8080。
- 复现：raw socket 对 `127.0.0.1:8080` 发 `bytes([0x16,0x03,0x01,0x00,0x50,...])` ⇒ Tomcat 原文一字不差地吐这句。
- 来源：8080 暴露在公网被扫描器 / 有人用 `https://mall.egoaicloud.com:8080` 探。
  实测 `http://mall.egoaicloud.com:8080/` → 502（前端代理）；`https://mall.egoaicloud.com` → 200。
- **处置（运维面，改不了代码）**：不要把 8080 明文端口暴露公网；在**前置 nginx 做 TLS 终止**，后端只对内。
- 与类 B **互不相关**（日志里从不同时出现）。

### 二、类 B —— SSE 结束刷三段 ERROR（**代码 bug，已修**）
```
org.springframework.security.access.AccessDeniedException: Access Denied
Unable to handle the Spring Security Exception because the response is already committed.
Cannot render error page for request [null] as the response may have the wrong status code.
```
- **触发点**：`GET /api/v1/runs/{runId}/events`（SseEmitter）**流一结束**。
- **根因**：`JwtAuthenticationFilter extends OncePerRequestFilter` 默认 `shouldNotFilterAsyncDispatch()=true` ⇒ 不参与 ASYNC 派发；
  而 `AuthorizationFilter` 默认参与。流结束时容器那次 **ASYNC 派发没有 SecurityContext** ⇒ 判 AccessDenied；
  但 SSE 响应早已写出（committed）⇒ 403 写不进去。
- **修法**：`server/aioa-security/.../SecurityConfig.java` 的 `authorizeHttpRequests(...)` 首行加
  `.shouldFilterAllDispatcherTypes(false)`（鉴权只在首次 REQUEST 派发发生；首个请求照常鉴权，语义不变）。
- **不改变 HTTP 行为**（SSE 仍 200、事件完整）⇒ 唯一可观测面是**服务端日志** ⇒ 判据必须读日志。
