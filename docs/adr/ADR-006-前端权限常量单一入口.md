# ADR-006：菜单 / 路由 / 接口三层权限常量同源

- 状态：已落地（`web/apps/shell/src/constants/permissions.ts`）
- 日期：2026-09

## 背景

前端有三处要用权限码：菜单是否显示、路由是否放行、按钮是否可点。三者各写一份字符串
时，一次后端权限码调整就会造成**漂移**：菜单不显示 + 路由重定向 + 接口 403，
用户看到的是「页面全空」，而三处报错日志各说各话，很难联想到是同一个根因。

## 决策

权限常量只有一份定义（`constants/permissions.ts`），菜单、路由、按钮三处都从这里取，
且与后端 `PermissionCatalog` 保持同源。角色码（如 `ROLE_TENANT_ADMIN`）也走同一份常量。

## 取舍

- 前端多了一层间接：新增权限要先在常量文件里加。这是有意的摩擦力——它让「加一个权限」
  变成一次显式、可评审的改动，而不是在某个页面里随手写一个字符串。
- 不做「后端下发权限码字典、前端动态渲染菜单」：一期菜单结构稳定，动态化带来的
  渲染与调试成本不划算。

## 后果

- 改动权限后的检查项固定为：改常量 → 全局搜旧口径 → 跑 `pnpm -r typecheck`
  → 跑受影响的两个端到端套件（类型检查只能查出「少 import」，查不出口径写错）。
