# 60 - 数字人问题诊断与优化方案（2026-10-26）

> 触发：用户截图（H5 V1.2）——①带 xlsx 附件问「请问这是什么」→ 机器人答「您指的是什么呢」；
> ②纯问候「你好」→ 回复却挂「来源：策划书.docx」引用；③底部知识库开关显示「关」。
> 本文按「症状 → 代码证据 → 根因 → 修复」组织，问题清单按 P0/P1/P2 排序。

## 一、症状 → 代码证据映射（仓库 HEAD 现状）

### 症状 1：附件内容模型「看不见」

附件链路在 HEAD 上**已完整实现**（10-12 原子落地，commit 91533f5）：

```
H5「＋」上传 → POST /v1/files/upload → createRun(attachments=[id])
→ RunService.resolveAttachments()：按 id 读盘 → KbFileParser.parse 抽正文
   （支持 pdf/docx/doc/xlsx/xls/txt/md/csv/json/log，截 VIEW_MAX_CHARS=20000 字）
→ ChatMessage.attachments 落库（历史轮由 formatAttachmentDocs 回填全文）
→ AgentRunRequest.attachment_docs 下发
→ agent aios_ai/prompt/builder.py:_build_attachment_block 注入 system 末尾
   （合计上限 _MAX_ATTACHMENT_CHARS=40000 字，硬边界【参考文档】…【以上为参考文档】）
```

⇒ 症状 1 的根因必在「部署树落后 / 运行时静默失败 / 模型关联弱」三者之一（见 P0-1/2、P1-4）。

### 症状 2：问候语拖出知识库引用

- `graph/nodes.py:236-244`：kb_on 时**每条消息都做预检索**（pre_retrieve），无闲聊/意图分流；
- `nodes.py:177`：`threshold = float(es.get("threshold") or 0.0)` —— 专家未配置阈值时
  **默认 0 分也命中**，任何输入都能拖出文档；
- citations 只要预检索命中就随响应回传 UI（`nodes.py:244`），**不管回答是否真的用了**——
  所以「你好」也会挂「来源：策划书.docx」。

### 症状 3：图片附件天然不支持

- H5 聊天附件 `accept=".pdf,.docx,.doc,.xlsx,.xls,.txt,.md,.csv,.json,.log"`（index.html:2126）
  —— 不含图片；
- `KbFileParser` 无 OCR/视觉通道 ⇒ 即便放开 accept，图片也抽不出正文。
  用户预期「文档、图片等」里的**图片**目前是产品能力空白（非 bug）。
