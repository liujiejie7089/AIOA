# 数字员工权限矩阵（V29–V32）

> 口径：角色决定「能做什么」，数据范围决定「能看到谁的」。两者必须同时校验。
> 回归套件：`scripts/e2e_worker_permission.py`（V29–V31）、`scripts/e2e_v32_org_scope.py`（V32）。

## 一、角色与数据范围

| 角色码 | 名称 | 数据范围 `data_scope` | 典型账号 |
|---|---|---|---|
| `ROLE_ADMIN` | 系统管理员 | `ALL`（跨租户） | `admin` |
| `ROLE_TENANT_ADMIN` | 租户管理员 | `TENANT`（本租户） | `jyj_admin` |
| `ROLE_ORG_ADMIN` | 企业/机构管理员 | `ORG`（本机构） | `jyfzyjy_admin` |
| `ROLE_DEPT_LEADER` | 部门负责人 | `DEPT`（本部门） | `fagai_liu` |
| `ROLE_MEMBER` | 机构成员 | `SELF`（仅本人） | `jybgs_m01` |
| `ROLE_USER` | 普通用户 | `SELF` | `zhangsan` |

## 二、权限点 → 角色（V32）

| 权限点 | 含义 | 系统管理员 | 租户管理员 | 企业管理员 | 部门负责人 | 成员/用户 |
|---|---|:--:|:--:|:--:|:--:|:--:|
| `worker:use` | 使用数字员工（对话、发起业务） | ✓ | ✓ | ✓ | ✓ | ✓ |
| `worker:create` | 创建数字员工 | ✓ | ✓ | ✓（限本机构） | ✓（**强制锁本部门**） | ✗ |
| `worker:manage` | 修改/启停/删除 | ✓ | ✓ | ✓（限本机构） | ✓（**限本部门可见**） | ✗ |
| `approval:leave` | 请假审批（绑定请假类数字人） | ✓ | ✓ | ✗ | ✗ | ✗ |
| `chat:basic` | 通用对话 | ✓ | ✓ | ✓ | ✓ | ✓ |
| `kb:read` | 知识库检索 | ✓ | ✓ | ✓ | ✓ | ✓ |
| `doc:draft` | 公文起草 | ✓ | ✓ | ✓ | ✓ | ✓ |

未知权限码一律**默认拒绝**。

> **V32 变更**：`worker:create` / `worker:manage` 由「机构管理员级」下放到**部门负责人**，
> 使「本部门数字员工由本部门负责人配置」可落地。下放的同时在 `WorkerController` 内加了三道硬约束
> （见 §三 与 §四），部门负责人**不能**借此提权成全租户可见。

## 三、数字员工的范围维度

| 字段 | 取值 | 作用 |
|---|---|---|
| `institution_id` | 机构 id / 空 | **归属**：空=租户级（全租户共享）；非空=归该机构，仅本机构与租户管理员可管理 |
| `visible_scope` | `TENANT` / `DEPT` | **可见性**：谁能在使用列表里看到它 |
| `dept_ids` | 部门 id 数组 | `visible_scope=DEPT` 时指定可见部门 |

判定规则：

- 系统管理员 / 租户管理员可见本租户全部数字员工（否则无法管理自己下发到部门的员工）。
- 企业管理员、部门负责人、成员按 `visible_scope` 过滤（`TENANT` 全员可见；`DEPT` 需部门命中）。

## 四、部门负责人的边界（V32 新增）

`ROLE_DEPT_LEADER` 是**委派型管理者**，能力被严格夹在本部门内：

| 场景 | 行为 | 落点 |
|---|---|---|
| 创建数字员工 | 可见范围**强制** `DEPT` + `dept_ids=[本部门]`，不接受前端传入 | `WorkerController.applyVisibilityScope` |
| 修改可见范围 | 只能设为本部门；传 `TENANT` 也强制回落本部门（防自我提权） | `WorkerController.setVisibleScope` |
| 修改/启停/删除 | 仅限「已分发到本部门」的员工；全租户可见或他机构的 → 403 | `WorkerController.requireOwned` + `deptScopedTo` |
| 账号未绑定部门 | 创建/设置范围一律 403，提示联系企业管理员 | `applyVisibilityScope` |
| 创建请假审批类 | 仍被 `approval:leave` 拦住（该权限仅租户管理员级持有） | `requirePermission` |

## 五、租户级资产与入驻预置（V32 新增）

- **入驻预置**：企业域新建机构时发布 `TenantProvisionedEvent`，能力域监听后把平台模板
  （`tenant_id=0 且 is_template=1`）复制一套到该租户，解决「新租户开通后列表为空、页面白板」。
- **幂等**：判据是「该租户**历史**上是否出现过任何数字员工」（`countAllByTenant` 绕过逻辑删除），
  一生只预置一次——租户把预置员工全部删除后不会被重复塞回来。
- **归属**：预置项归属留空（`institution_id = NULL`）＝**租户级公共资产**，
  不绑定触发入驻的那一家机构（否则该机构注销后资产会挂在失效机构名下）。
- **解耦**：企业域（aioa-org）与能力域（aioa-resource）之间不建横向依赖，只通过
  `aioa-common` 的领域事件通信；监听方吞异常，预置失败不影响入驻主流程。

## 六、审计变更值（V32 补齐）

- 写入 `client_activity_log`（管理端「系统管理 → 审计」可见），**不写** `audit_log`
  （那张表带 hash 链，跨模块直接插会破坏链校验）。
- `before_value` / `after_value`（TEXT，存 JSON 快照，V32 迁移新增两列）记录**改前改后各是什么**；
  快照只取配置类字段（名称/类型/运行模式/执行时刻/任务内容/状态/启停/可见范围/部门/归属），
  **不含**运行产出，避免审计表被大文本撑爆。
- 覆盖动作：`worker.create` / `worker.update` / `worker.toggle` / `worker.delete` /
  `worker.scope` / `worker.from_template` / `worker.run`。

## 七、授权流程

1. **系统管理员**：开通租户 → 建管理员账号 → 分配资源池 → 授予租户管理员角色。
2. **租户管理员**：从平台模板创建 / 新建数字员工 → 设置归属与可见范围 → 按部门分发。
3. **企业管理员**：在本机构内创建与管理（改不了其他机构的）。
4. **部门负责人**：在本部门内创建与配置（改不了本部门范围外的）。
5. **成员**：使用被授权的数字员工，看不到范围外的。

## 八、租户隔离要点

- `tenant_id` 只从 JWT 取，**永不信任前端传入**。
- 每张业务表都有 `tenant_id` 且加复合索引 `(tenant_id, ...)`。
- 跨租户访问一律 404（不暴露资源是否存在），不是 403。
- 回归测试：`scripts/e2e_worker_permission.py`、`scripts/e2e_v32_org_scope.py`。

## 九、已知限制

- `institution_id` 仅用于管理边界，不参与使用可见性（可见性由 `visible_scope` 独立控制）。
- 多 Agent 并行编排、字段级权限、跨租户共享数字员工均不在本期范围。
