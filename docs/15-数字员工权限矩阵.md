# 数字员工权限矩阵（V29–V31）

> 口径：角色决定「能做什么」，数据范围决定「能看到谁的」。两者必须同时校验。

## 一、角色与数据范围

| 角色码 | 名称 | 数据范围 `data_scope` | 典型账号 |
|---|---|---|---|
| `ROLE_ADMIN` | 系统管理员 | `ALL`（跨租户） | `admin` |
| `ROLE_TENANT_ADMIN` | 租户管理员 | `TENANT`（本租户） | `jyj_admin` |
| `ROLE_ORG_ADMIN` | 企业/机构管理员 | `ORG`（本机构） | `jyfzyjy_admin` |
| `ROLE_DEPT_LEADER` | 部门负责人 | `DEPT`（本部门） | `fagai_liu` |
| `ROLE_MEMBER` | 机构成员 | `SELF`（仅本人） | `jybgs_m01` |
| `ROLE_USER` | 普通用户 | `SELF` | `zhangsan` |

## 二、权限点 → 角色

| 权限点 | 含义 | 系统管理员 | 租户管理员 | 企业管理员 | 部门负责人 | 成员/用户 |
|---|---|:--:|:--:|:--:|:--:|:--:|
| `worker:use` | 使用数字员工（对话、发起业务） | ✓ | ✓ | ✓ | ✓ | ✓ |
| `worker:create` | 创建数字员工 | ✓ | ✓ | ✓（限本机构） | ✗ | ✗ |
| `worker:manage` | 修改/启停/删除 | ✓ | ✓ | ✓（限本机构） | ✗ | ✗ |
| `approval:leave` | 请假审批（绑定请假类数字人） | ✓ | ✓ | ✗ | ✗ | ✗ |
| `chat:basic` | 通用对话 | ✓ | ✓ | ✓ | ✓ | ✓ |
| `kb:read` | 知识库检索 | ✓ | ✓ | ✓ | ✓ | ✓ |
| `doc:draft` | 公文起草 | ✓ | ✓ | ✓ | ✓ | ✓ |

未知权限码一律**默认拒绝**。

## 三、数字员工的两个范围维度

| 字段 | 取值 | 作用 |
|---|---|---|
| `institution_id` | 机构 id / 空 | **归属**：空=租户级（全租户共享）；非空=归该机构，仅本机构与租户管理员可管理 |
| `visible_scope` | `TENANT` / `DEPT` | **可见性**：谁能在使用列表里看到它 |
| `dept_ids` | 部门 id 数组 | `visible_scope=DEPT` 时指定可见部门 |

> 判定时管理员可见全部——否则租户管理员无法管理自己下发到部门的数字员工。

## 四、授权流程

1. **系统管理员**：开通租户 → 建管理员账号 → 分配资源池 → 授予租户管理员角色。
2. **租户管理员**：从平台模板创建 / 新建数字员工 → 设置归属与可见范围 → 按部门分发。
3. **企业管理员**：在本机构内创建与管理（改不了其他机构的）。
4. **成员**：使用被授权的数字员工，看不到范围外的。

## 五、租户隔离要点

- `tenant_id` 只从 JWT 取，**永不信任前端传入**。
- 每张业务表都有 `tenant_id` 且加复合索引 `(tenant_id, ...)`。
- 跨租户访问一律 404（不暴露资源是否存在），不是 403。
- 回归测试：`scripts/e2e_worker_permission.py`，含跨租户与部门分发双向验证。

## 六、已知限制

- 部门负责人（`ROLE_DEPT_LEADER`）目前**没有** `worker:manage`，只能在业务审批链中起作用；若需「本部门数字员工由负责人配置」，把该角色加入 `worker:manage` 并在 `requireOwned` 增加部门约束。
- `institution_id` 仅用于管理边界，不参与使用可见性（可见性由 `visible_scope` 独立控制）。
- 审计写入 `client_activity_log`（管理端「系统管理 → 审计」可见），未写入带 hash 链的 `audit_log`，避免破坏链校验。
