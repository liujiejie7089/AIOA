### 3.3 对抗性验证（QA 独立设计，非工程师冒烟场景）

- **越权四态**：同机构非正职 403 · 他部门正职 403 · 跨机构 404 · 平台账号 404；**四种均断言 `approval_order`/`permission_grant` 零新增行**。
- **定向证伪「`job_title` 作权限依据」**：库中已无「`job_title` 含『负责人』但 `duty_code` 非正职」的账号（V42 已收敛），QA **刻意**临时改写 3145 的 `job_title` 后验证仍 403、`catalog` 开关仍灰，用后还原 —— 主动构造反例而非依赖现有数据。
- **知会不阻塞**：用**非** `PERMISSION_GRANT` 的业务（`QUOTA_EXPAND`）配 `cc` 并真实跑到 `APPROVED`/`finalDone`；配额副作用经接口精确回滚并断言复原。
- **去重一次命中四类**：配 `[PLATFORM_ADMIN, PLATFORM_ADMIN, TENANT_ADMIN, ORG_ADMIN, BOGUS]` → 结果恰 1 条。
- **`ccUnread` 先造未读再断言**，规避「初值为 0 直接断言」的假阳性。
- **底部角标口径**：`A3-8.4` 拆为 4 条 —— 非空洞前置（`unread_cc ≥ 1`）、精确公式、差分守卫（`tab < pending + unread_all`）、反向守卫（知会读掉后底部角标**不变**而 Tab 内未读 −1）。期望值由原始 `state` 在 Python 侧独立推导，**未复刻 H5 的过滤实现**（避免同源同错、无法证伪）。

### 3.4 QA 主动列出的「证伪失败」假设（本来怀疑是 bug、验证后不是）
① 他部门正职可代发 → 实 403；② 部门申请污染个人幂等键 → 实分账正确；③ 已读致 `scope=cc` 条目消失 → 实仍可回查；④ 重复标记 `readAt` 漂移 → 实微秒截断、不倒退；⑤ 平台账号落业务错误而非 404 → 实 404。
