## 三、异常点清单

1. **提交回执误导用户**：回执标题「费用报销提交成功」、状态「已完成」，让用户以为已提交审批；实际 `status=DONE` 表示台账归档，不是审批中。
2. **用户端「我的申请」空**：该列表读 `API.workflowMine()` → 多级审批引擎 `approval_order` 超集；表单台账不在其数据源内。
3. **管理端收不到**：审批中心待办读 `/workflow/tasks?scope=todo` → `approval_task`；同样不含表单台账。
4. **无审批状态流转**：未建审批单 ⇒ 无通过/驳回按钮、无 timeline、无通知。
5. **详情不存在**：列表无行，自然无详情入口。
6. **H5 控制台 3 条错误**：401×2（登录前预取）、404×1（非本次主链路），不影响提交但需单独排查。

## 四、根因（DB + 代码双向确认）

### 4.1 配置真源：费用报销表单被配成「纯台账」

```text
form_template WHERE code='expense_form':
  id=8  tenant_id=0   submit_policy=LEDGER  biz_type=NULL  status=ACTIVE
  id=121..131（11 个租户副本）同样是 submit_policy=LEDGER / biz_type=NULL
```

`V86__oa_module_forms.sql` 的约定写得很明确：

> `submit_policy` 仅请假 = `APPROVAL+RESUME`，其余 = `LEDGER`。

即**除请假外的全部 OA 表单在设计上都不进审批流**，费用报销只是其中最容易被用户当成「审批」的一种。

### 4.2 代码分流：LEDGER 直接置 DONE，不调审批引擎

`server/aios-resource/.../FormSubmissionService.java:202-217`：

```java
} else if (policies.contains(FormTemplate.POLICY_APPROVAL)) {
    flowOut = invokeApproval(...);            // 建 approval_order + approval_task
    sub.setStatus(FormSubmission.STATUS_APPROVING);
    sub.setApprovalOrderId(approvalOrderId);
} else if (policies.contains(FormTemplate.POLICY_LEDGER)) {
    sub.setStatus(FormSubmission.STATUS_DONE); // ← 费用报销走这里：只归档，不建单
}
```

### 4.3 三套数据源互不相通

| 数据源 | 写入路径 | 读取路径 | 本次是否落数据 |
|---|---|---|---|
| `form_submission` | `POST /forms/{code}/submit`（LEDGER） | `/form-submissions` | ✅ 1 行（id=55/56，`DONE`，`approval_order_id=NULL`） |
| `approval_order` | `invokeApproval()` / `POST /approvals` | `/workflow/mine`、管理端首页「我的申请」 | ❌ 无 |
| `approval_task` | 审批引擎建单时生成 | `/workflow/tasks?scope=todo`、红点 | ❌ 无 |

### 4.4 对照实验：另一条提交路径正常

用数字人审批卡 `POST /api/v1/approvals` 提交同标记申请（id=1121、1122），`workflow/mine` 与 `approvals/mine` **都能立刻看到**。说明前端列表本身没有问题，问题在费用报销表单走了不建审批单的 LEDGER 分支。

### 4.5 次要发现：平台租户缺 EXPENSE 审批流

`approval_flow_def` 中 tenant≥1 均有 `EXPENSE` 审批流（部门负责人 → 企业管理员），但 **tenant=0 只有 `NOTICE_PUBLISH`**。若直接把平台模板改成 `APPROVAL+EXPENSE`，`zhangsan`（tenant=0）提交会因找不到流程定义而失败。修复时必须同时补流程定义，或让平台租户回落到有定义的租户配置。

## 六、最终测试结论

**用户报障属实，且已定位到确定根因。**

费用报销提交是「假审批」：表单 `submit_policy=LEDGER` 使其只落台账、不创建审批单，而用户端「我的申请」和管理端「待我审批」都以审批单为数据源，因此两端都看不到；提交回执却显示「提交成功 / 已完成」，进一步误导用户。

这不是偶发故障或前端刷新时机问题，而是**配置 + 分流设计的结构性缺口**，稳定可复现（API 与 UI 两条路径各复现一次）。要让费用报销真正可被审批，必须改 `submit_policy` 与 `biz_type`，并处理 tenant=0 缺审批流定义的问题。

## 七、修复建议（待确认后执行）

**方案 A（推荐，改数据源头）**：新增 Flyway 迁移，把 `expense_form` 的平台行与全部租户副本改为 `submit_policy='APPROVAL'`、`biz_type='EXPENSE'`；同时为 tenant=0 补一条 EXPENSE 审批流定义；前端提交后刷新改用 `API.workflowMine()` 与列表同源。影响面：所有租户的费用报销将真正进入两级审批。
