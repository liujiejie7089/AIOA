## 0. 必须先过的闸门：安全上下文（不解决则整个功能不可用）

浏览器要拿到麦克风，只有一条路：`navigator.mediaDevices.getUserMedia()`。它有一条**硬性前置条件**：

> 页面必须处于**安全上下文（secure context）**——即 `https://` 或 `http://localhost`。

对本项目意味着：

| 访问方式 | 是安全上下文？ | 能否长按录音 |
|---|---|---|
| `https://mall.egoaicloud.com/aioa/h5/`（生产入口，见 `deploy/ENV.md:151`） | ✅ 是（443 + 证书） | **能** |
| `http://10.0.0.3:8080/aioa/h5/`（内网裸 IP 直连） | ❌ 否 | **不能**，`navigator.mediaDevices === undefined` |
| `http://localhost:5181/`（本机联调） | ✅ 是 | 能（但只在本机） |

**结论**：手机上必须访问 **HTTPS 域名**。内网裸 IP 的 HTTP 下，长按录音从浏览器层就不可能，跟后端写得多好无关（Python 后端永远碰不到手机麦克风）。

若最终无法上 HTTPS，只能降级为 §4.4 的「点击选择录音文件」——**不是长按交互**。这是本项目语音功能的**第一风险项**，排在所有技术选型之前。

## 1. 端到端链路（三层，各司其职）

```
手机浏览器(H5)                  Java aioa-server (:8080)              Python agent (:8000)
─────────────────              ──────────────────────────           ────────────────────
长按 → getUserMedia
     → MediaRecorder
     → 音频 Blob
        │ POST /api/v1/asr/transcribe (multipart, JWT)
        └──────────────────────► 鉴权 + 限额 + 审计
                                  │ POST /internal/v1/asr/transcribe (multipart)
                                  └───────────────────────────────► 离线 ASR 模型
                                                                      ↓ 转写文本
        ◄── {code:0, data:{text}} ◄───────────────────────────────────┘
     → 文本填入输入框
     → 复用既有 API.createRun(...) + API.stream(...)  →  AI 回答
```

**为什么 ASR 落在 Python agent、Java 只做转发**：

- 模型生态在 Python；Java 侧引入 ASR 运行时（Native 库 / 模型加载）成本高且没必要。
- 既有先例就是这套模式：Java `ModelConfigService` → agent `/internal/v1/models`；`WorkerIntakeService` → agent `/internal/v1/worker-intent`。**照抄即可**。
- H5 只认**同源 `/api/*`**（`user-client/serve.py` 把 `/api/*` 反代到 `:8080`；生产由 openresty `https://mall.egoaicloud.com/aioa/...` 原样转发到 `10.0.0.3:8080`）。所以对外端点必须开在 Java 上，agent 的 `:8000` **不能暴露给浏览器**（否则要处理 CORS + JWT + 端口暴露）。

> 注：`/api/**` 在 `SecurityConfig.java:93` 已经是 `authenticated()`，新增端点**自动受 JWT 保护**，不需要改安全配置。

## 2. 离线 ASR 引擎选型

内网不通外网 ⇒ 必须是**离线模型**，且模型文件随镜像/卷交付。

| 引擎 | 安装 | 中文效果 | CPU 表现 | 体积 | 备注 |
|---|---|---|---|---|---|
| **faster-whisper**（推荐·起步） | `pip install faster-whisper` | 好（small 起可用） | int8 尚可 | 模型 0.5G(small)~1.5G(medium) | API 极简；自带 `av`(PyAV) 解码 webm/mp4；`vad_filter` 现成 |
| **sherpa-onnx** | `pip install sherpa-onnx` | 好（paraformer-zh） | **最快**、内存最低 | 模型 ~200M | 无 torch/ctranslate2，纯 ONNX；适合内存紧的机器 |
| vosk | `pip install vosk` | 一般 | 快 | ~50M | 精度低，仅作兜底 |
| FunASR(paraformer) | `pip install funasr` | 最好 | 重 | >1G + torch | 依赖 torch，镜像膨胀大 |

**建议**：起步用 `faster-whisper` + `small` + `int8`；若服务器 CPU 弱或内存紧张，换 `sherpa-onnx` + `paraformer-zh`（接口契约不变，只换 `engine.py` 实现）。

**模型离线交付**（关键，否则首次调用会尝试联网下载而卡死）：

- 镜像构建期预下载到 `/models/whisper`，或挂卷 `aioa-asr-models`。
- 运行期强制 `HF_HUB_OFFLINE=1`。
- 引擎**懒加载 + 预热**：进程启动后台线程加载一次，避免"用户第一次说话等 20 秒"。

## 3. 接口契约

### 3.1 Agent 内部端点（新增）

```
POST /internal/v1/asr/transcribe        Content-Type: multipart/form-data
  form: audio=<file>   必填，音频流（webm/opus 或 mp4/aac）
  form: lang=zh        可选，默认 zh
→ 200 {"code":0,"data":{"text":"你好","lang":"zh","duration_ms":3200,"model":"small"}}
→ 400 {"code":"BAD_REQUEST","message":"音频为空"}
→ 413 {"code":"AUDIO_TOO_LARGE","message":"音频超过 10MB"}
→ 422 {"code":"AUDIO_TOO_LONG","message":"音频超过 60 秒"}
→ 503 {"code":"ASR_UNAVAILABLE","message":"ASR 模型未就绪"}

GET  /internal/v1/asr/status
→ 200 {"available":true,"model":"small","device":"cpu"}
```

> ⚠️ 现状提醒：agent 的 `GuardError` **没有专用异常处理器**（`main.py` 只有 `RequestValidationError` 与 `Exception` 两个 handler），直接 `raise GuardError` 会被兜底成 **500 INTERNAL_ERROR**。所以本端点**显式返回 `JSONResponse(status_code=..., content={"code":...})`**，不要用 GuardError。

### 3.2 Java 对外端点（新增）

```
POST /api/v1/asr/transcribe     Content-Type: multipart/form-data   （JWT：/api/** 自动要求）
  part: audio=<file>
→ 200 ApiResponse.ok({"text":"你好","lang":"zh","durationMs":3200})
→ 400 BizException.badRequest("音频为空")
→ 413 BizException(413,"音频超过 10MB")
→ 503 BizException(503,"语音识别服务不可用")     ← agent 不可达时，绝不静默成功
```

**限额常量单一入口**（吸取 `docs/42` 里 KB 大小限制"三处写死、compose 环境变量变成 no-op"的教训）：
`aioa.asr.max-bytes` / `aioa.asr.max-seconds` 在 `application.yml` 定义一次，Java 控制器读配置，agent 侧读自己的 env；**两处阈值必须一致**，并用验收 V7 断言"改配置 → 接口文案与拒绝阈值同时变"。

**录音模块**（经典基线 `_backup_index_pre_oa.html` 4339-4414 与 OA 共用同一份逻辑；第二次修订后**删除了隐藏免提**，并保留第一次修订的 `stopping/hooks/isLive` 机制）：
```js
/* 边界：录音在浏览器，识别在后端。
   纪律（pitfalls #121）：getUserMedia 必须在 pointerdown 的【同步段】发起，前面不许有 await。 */
var VoiceInput = (function(){
  var stream = null, rec = null, chunks = [], t0 = 0, tick = null;
  var hooks = null, cancelled = false, stopping = false, why = null;
  /* 兜底上限：后端 AIOA_ASR_MAX_SECONDS=60，这里留 5s 余量，避免被后端按超长拒掉 */
  var MAX_MS = 55000;
  /* 最短有效录音：小于此值视为误触，不发送（对标微信长按说话） */
  var MIN_MS = 300;

  function supported(){
    return !!(window.isSecureContext && navigator.mediaDevices &&
              navigator.mediaDevices.getUserMedia && window.MediaRecorder);
  }
  function pickMime(){
    var c = ['audio/webm;codecs=opus','audio/webm','audio/mp4','audio/ogg'];
    for (var i=0;i<c.length;i++){
      if (window.MediaRecorder && MediaRecorder.isTypeSupported && MediaRecorder.isTypeSupported(c[i])) return c[i];
    }
    return '';
  }
  function stopTracks(){
    if (tick){ clearInterval(tick); tick = null; }
    if (stream){ stream.getTracks().forEach(function(t){ t.stop(); }); stream = null; }
  }
  function reset(){ hooks = null; stopping = false; why = null; }

  /* 由「按下」事件在【同步段】调用：media 必须是这一刻已经发出的 getUserMedia Promise。
     ★ 关键：必须容忍「getUserMedia 还没回来、用户就已经松手/取消」——
       否则会出现「点一下录音，手早就松开了，它却在那之后才开始录，从此停不下来」。 */
  function begin(media, h){
    hooks = h; cancelled = false; stopping = false; why = null; chunks = [];
    media.then(function(s){
      stream = s;
      if (stopping || !hooks){          /* 还没开录就已经要求停：直接收摊，绝不启动录音 */
        var w0 = why;
        stopTracks(); reset(); h.phase(false); h.done(null, w0 || 'no-media'); return;
      }
      var mime = pickMime();
      rec = new MediaRecorder(s, mime ? {mimeType:mime, audioBitsPerSecond:32000} : undefined);
      rec.ondataavailable = function(e){ if(e.data && e.data.size) chunks.push(e.data); };
      rec.onstop = function(){
        var blob = cancelled ? null : new Blob(chunks, {type: (rec && rec.mimeType) || 'audio/webm'});
        var w = why;
        rec = null; stopTracks(); reset();
        h.done(blob, w);
      };
      rec.start();
      t0 = Date.now();
      h.phase(true);
      tick = setInterval(function(){
        var ms = Date.now() - t0;
        if (ms >= MAX_MS){ h.tick(MAX_MS); end(); return; }   /* 到顶自动结束 */
        h.tick(ms);
      }, 200);
    }).catch(function(err){
      rec = null; stopTracks(); reset();
      h.phase(false);
      h.error(err && (err.name === 'NotAllowedError' || err.name === 'SecurityError') ? 'DENIED' : 'FAILED');
    });
  }
  /* 结束并发送。录音尚未真正起来时也照样记账，由 begin 的续体收尾。 */
  function end(){
    if (!hooks) return;
    stopping = true;
    if (rec && rec.state === 'recording'){
      if (Date.now() - t0 < MIN_MS){ cancelled = true; why = 'too-short'; }   /* 误触：不发送 */
      rec.stop();
    }
  }
  /* 丢弃这一段（手势被浏览器接管 / 用户取消） */
  function abort(){ if (!hooks) return; why = 'cancelled'; cancelled = true; end(); }
  /* 是否正在录（含「已按下、getUserMedia 尚在途中」这段窗口） */
  function isLive(){ return !!hooks; }
  return { supported: supported, begin: begin, end: end, abort: abort, isLive: isLive };
})();
```

**绑定（两形态共用同一个 `bindVoice`：经典端 `bindVoice(voiceBtn, chatInput, send)`；OA 端 `bindVoice(oaMicBtn, oaInput, oaSend)`）**：
```js
function bindVoice(btn, inputEl, onText){
  if (!btn || !inputEl) return;
  if (!VoiceInput.supported()){
    btn.disabled = true;
    btn.title = '当前访问方式不支持麦克风（需 https 或 localhost 打开）';
    return;
  }
  var ph = inputEl.placeholder;
  function hint(t){ inputEl.placeholder = t; }
  function idle(){ btn.classList.remove('rec'); hint(ph); }

  var hooks = {
    phase: function(on){
      btn.classList.toggle('rec', !!on);
      if (!on){ idle(); return; }
      hint('录音中… 松开发送');
    },
    tick: function(ms){ hint('录音中 ' + (ms/1000).toFixed(1) + 's · 松开发送'); },
    error: function(kind){
      idle();
      toast(kind === 'DENIED' ? '未获得麦克风权限，请在浏览器设置里允许后重试' : '麦克风不可用');
    },
    done: function(blob, why){
      idle();
      if (!blob){
        if (why === 'too-short') toast('按住说话，松开即可发送');
        return;                                          /* 取消/未开录/误触：不发请求 */
      }
      hint('识别中…');
      API.asrTranscribe(blob).then(function(d){
        hint(ph);
        var text = String((d && d.text) || '').trim();
        if (!text){ toast('没听清，请再说一次'); return; }
        inputEl.value = text;
        onText();                                        /* 交回各形态自己的发送 */
      }).catch(function(err){
        hint(ph);
        toast('语音识别失败：' + (err.message || '未知错误'));
      });
    }
  };

  btn.addEventListener('pointerdown', function(ev){
    ev.preventDefault();
    if (VoiceInput.isLive()){ VoiceInput.end(); return; }   /* 录音中再按 = 结束并发送；绝不被 busy 拦 */
    if (state.busy) return;
    /* ★ 同步段发起 getUserMedia，前面不许有 await（pitfalls #121） */
    var p = navigator.mediaDevices.getUserMedia({
      audio:{echoCancellation:true, noiseSuppression:true, autoGainControl:true}
    });
    try{ btn.setPointerCapture(ev.pointerId); }catch(e){}
    VoiceInput.begin(p, hooks);
  });
  btn.addEventListener('pointerup', function(){
    if (!VoiceInput.isLive()) return;
    VoiceInput.end();
  });
  btn.addEventListener('pointercancel', function(){ if (VoiceInput.isLive()) VoiceInput.abort(); });
}
```

**识别成功后复用既有发送链路**（不新开对话通路）：`bindVoice` 的 `done` 回调在拿到文本后填输入框并调用传入的 `onText`（经典=`send`、OA=`oaSend`），复用既有 `createRun` + SSE 流式。因此**没有**独立的 `oaVoiceSend`——两形态只把各自的发送函数交给 `bindVoice`，逻辑唯一。

### 4.5 必须遵守的既有纪律

- **pitfalls #121**：手势 API（`getUserMedia`）不得从异步续体里调用——必须在事件回调同步段发起。这与 2026-10-11 修的"上传窗口打不开"是**同一类缺陷**。
- 录音期间 `state.busy` 为真时**仍可结束**录音（`pointerdown` 先判 `isLive()` 再判 `busy`，第二次修订），但新一轮起录仍受 `busy` 拦，避免并发两条 run。
- 录音态只通过 `.rec` 类 + `placeholder` 提示（"录音中… 松开发送"）表达，**不引入独立浮层 DOM**（第一次修订稿里的浮层/上滑取消已按设计移除）。
- 录音状态只有一个真值来源（`VoiceInput` 内部状态），按钮 `.rec` 类与提示文字只渲染，不自行判断。

## 8. 风险清单（按严重度）

1. **HTTPS 未落实 ⇒ 功能事实上不可用**。这是前置条件，不是优化项。需先确认手机端生产访问路径确实是 `https://mall.egoaicloud.com/aioa/h5/`。
2. **iOS / 微信内置浏览器的 `MediaRecorder` 差异**：Safari 只出 `audio/mp4`；微信内置浏览器对 `getUserMedia` 支持不稳定。→ 后端必须同时能解 webm 与 mp4（faster-whisper 的 PyAV 可以）；`supported()` 检测失败即降级。
3. **首帧延迟**：模型懒加载导致第一次识别很慢。→ 启动预热 + 前端显示"识别中…"。
4. **模型体积/内存**：small-int8 约 1~1.5G 常驻内存。若机器吃紧换 sherpa-onnx。
5. **音频隐私**：临时音频**用完即删**，不落持久化目录、不入知识库（与 docs/46 §5-Q2「不保留」一致）。
6. **并发**：单人边说边发不冲突；但同一用户并发两条 ASR 会抢模型 → agent 侧用单例 + 线程锁串行化（或限制并发 1），返回排队中而不是报错。
