## 2. 数据层收口（截图里真正扎眼的两件事）

### 2.1 历史会话标题是技术名

`V108` 引入 `title_source` 时给存量行打了默认 `AUTO`，于是验收脚本建的
`grade-sheet-probe` / `enum-probe`、数字人入口建的「请假助手 · 对话」全都原样留在「最近」里。

`V109__chat_conversation_title_backfill.sql`：对 `title_source='AUTO'` 且有用户消息的会话，
取**首条 user 消息**重写标题（折叠空白 + 超 30 字截断补「…」）。`MANUAL`（用户改过名的）一律不碰。

与 Java 版的唯一差异：SQL 不剥口语前缀。存量行保留用户原话更忠实；新会话走 Java 版会剥。
实测（`user_id=3240`）：`grade-sheet-probe → 我的平均绩点和成绩是多少？顺便说下我已经修了多少学分。`

### 2.2 空壳会话占满列表

截图里 8 条「请假助手 · 对话」「每日考勤 · 对话」都是 `msg_count=0` —— 用户点进数字人却一句没问。
没有用户问题，标题无从总结，留着只会把真会话挤下去。

`GET /v1/conversations` 新增 `onlyAsked`（默认 `false`，其余调用方行为不变），H5 的「最近」抽屉、
「会话记录」弹层、「我的→会话」整页都带 `onlyAsked=true`。
**数据一条没删**：按 id 仍能打开续聊，问出第一句后自然出现在列表里（T7/T7c/T8 就是这个口径）。

## 5. 一处判据自纠（记录在案）

T7b 初版写「默认列表里仍能查到空壳会话」并用全量分页判断，**首跑失败**。原因不是实现错：
`test` 账号下有 105 条会话，而空壳会话 `last_msg_at` 为 `NULL`，MySQL `DESC` 把 NULL 排最后，
它被挤出 `size=50` 第一页。改为按标题关键词精确捞（`convs_kw`），并在脚本注释写明这个坑 ——
否则这条用例测的是分页而不是语义。
