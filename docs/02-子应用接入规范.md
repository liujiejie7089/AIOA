# 子应用接入规范（V1.0）

业务系统前端嵌入 AIOA 工作台的标准方式。接入后即可被全局 AI 助手感知页面上下文，并可接收 agent 的反向动作。

## 1. 接入方式选择

| 方式 | 适用 | 能力 |
|---|---|---|
| **wujie（默认）** | 自有系统（Vue/React/老 jQuery 均可），可改少量代码 | 上下文上报、动作接收、唤起助手、保活、强隔离 |
| **iframe（逃生舱）** | 完全不可控的外部 H5、跨域不可配合系统 | 仅嵌入展示，无上下文交互 |

主应用内由 `AppHost` 组件统一渲染，差异只体现在 `app_registry.host_type`，切换不改代码。

## 2. 接入三步

### 第一步：注册应用（基座管理台或 SQL）

```sql
INSERT INTO app_registry (app_code, name, entry_url, route_prefix, host_type, icon, permission_code, enabled, sort)
VALUES ('ticket', '票务系统', 'http://localhost:5174/', '/app/ticket', 'wujie', 'ticket', 'aioa:app:ticket', true, 10);
```

### 第二步：子应用引入 SDK

```bash
pnpm add @aioa/sdk
```

```ts
// main.ts（应用入口最早期）
import { createAioaBridge } from '@aioa/sdk'

const aioa = createAioaBridge({ appCode: 'ticket' })

// 独立运行（不在工作台内）时 SDK 自动降级为 no-op，不影响系统单独使用
if (aioa.inWorkbench) {
  console.log('running inside AIOA workbench')
}
```

### 第三步：上报上下文（推荐做，决定 AI 助手"在哪问就答哪"的效果）

```ts
// 页面切换或筛选条件变化时
aioa.setContext({
  page: 'ticket-list',               // 页面标识（英文，稳定）
  pageTitle: '工单列表',              // 展示用
  entityType: 'ticket',              // 当前实体类型（可选）
  entityId: undefined,               // 当前实体 ID（详情页用，可选）
  filters: { status: 'OPEN' },       // 当前筛选/查询条件（可选）
  selection: []                      // 当前选中行 ID（可选）
})
```

## 3. SDK API

| API | 说明 |
|---|---|
| `createAioaBridge({appCode})` | 创建桥接实例，幂等 |
| `aioa.inWorkbench` | 是否运行在工作台内 |
| `aioa.setContext(ctx)` | 上报/更新页面上下文（增量合并） |
| `aioa.getContext()` | 读取当前上下文（主应用侧使用） |
| `aioa.openAssistant({preset})` | 唤起右侧 AI 助手抽屉并预填问题 |
| `aioa.onAction(type, handler)` | 接收 agent 反向动作：`openPage` / `fillForm` / `refresh` / `highlight`；未实现的动作被忽略（优雅降级） |
| `aioa.getToken()` | 获取主应用登录态 token（子应用调基座 API 用） |
| `aioa.notify(message, type)` | 在主应用右上角显示通知 |

## 4. 上下文快照与会话

用户每次提问，主应用把 `getContext()` 快照随请求上传（落 `chat_message.context_snapshot`），agent 的 perceive 阶段注入 system 提示。因此：

- `page` 字段必须**稳定**（不随语言/版本变化），用于 agent 理解位置；
- `filters` 等动态数据放扁平 key-value，避免深层嵌套；
- 敏感数据（身份证号、银行卡号）不要放入上下文。

## 5. 反向动作协议

agent 回复可携带 `actions[]`，经事件总线派发给当前子应用：

```ts
aioa.onAction('openPage', (p: { path: string }) => router.push(p.path))
aioa.onAction('fillForm', (p: { form: string; values: Record<string, unknown> }) => { /* 填充表单 */ })
aioa.onAction('refresh', () => loadList())
```

动作类型可扩展，子应用未注册 handler 的动作自动忽略。

## 6. 独立运行要求

子应用必须能脱离工作台独立打开（开发调试、应急访问）。SDK 在非工作台环境全部降级为 no-op，不得抛错。
