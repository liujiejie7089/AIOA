# 部署手册（V1.0）

## 1. 前置要求

- Docker 24+ 与 Docker Compose v2
- 私有化最小资源：server 2C4G · agent 2C4G · mysql 4C8G · 其余各 1C2G；本地模型另需 GPU（vLLM）
- 磁盘 ≥ 20GB（含镜像与 MinIO 数据）

## 2. 一键部署

```bash
cd deploy
cp .env.example .env
# 编辑 .env：至少设置 JWT_SECRET、SERVICE_JWT_SECRET、模型 API Key（云端模式）
docker compose up -d
docker compose ps        # 全部 healthy
```

入口：`http://<host>/`（nginx :80）。默认账号 `admin / Admin@123`（开发默认，生产必改）。

## 3. 服务清单

| 服务 | 端口（宿主:容器） | 说明 |
|---|---|---|
| mysql（远程 192.168.31.129） | 3306 | MySQL 8，业务库（Flyway 自动建表）；compose 不托管，由环境变量直连 |
| redis | 6379:6379 | 缓存/幂等/限流 |
| minio | 9000:9000, 9001:9001 | 对象存储（控制台 :9001） |
| server | 8080:8080 | Java 后端（Flyway 自动建表） |
| agent | 8000:8000 | Python agent |
| web | 8081:80 | 前端静态资源（shell + 子应用） |
| nginx | 80:80, 443:443 | 统一入口；**/internal 不暴露** |
| vllm / ollama | 8001 / 11434 | profile=model，本地模型 |
| prometheus/grafana/loki | 9090/3000/3100 | profile=ops，观测 |

## 4. 关键运维点

- **SSE**：nginx 已配 `proxy_buffering off` + `X-Accel-Buffering: no` + 长读超时；改反代时必须保留，否则流式变"一次性返回"。
- **密钥**：全部经 `.env` 注入；`JWT_SECRET`、`SERVICE_JWT_SECRET`、模型 API Key 禁止入库/入镜像；轮换时重启 server 与 agent。
- **数据备份**：远程 MySQL（`mysqldump` 每日）、`miniodata`；Redis 无需持久化。
- **日志**：`docker compose logs -f server agent`；profile=ops 起 Loki 后集中查询，按 traceId 串链路。
- **健康检查**：server `:8080/actuator/health`，agent `:8000/health`。

## 5. 模型双模式切换

- 云端模式：`.env` 配置 `DASHSCOPE_API_KEY`（或 `DEEPSEEK_API_KEY`），`MODEL_DEFAULT=qwen-plus`。
- 私有化模式：`docker compose --profile model up -d` 起 vLLM/Ollama，设 `MODEL_DEFAULT=local-vllm`。
- 切换 = 改 `.env` + 重启 agent，**不改代码**；fallback 链见 `agent/app/model_gateway/providers.yaml`。

## 6. 升级与回滚

- 升级：`git pull && docker compose build && docker compose up -d`；Flyway 自动执行增量迁移（V1、V2…只增不改）。
- 回滚：镜像按 git tag 构建（`aioa-server:<tag>`），回退 compose 中镜像 tag 并重启；数据库回滚需从备份恢复。

## 7. 后续 K8s 迁移要点（预留）

每服务一个 Deployment + ConfigMap/Secret；internal 走 Service 名；Ingress 关闭响应缓冲（SSE）；mysql/redis/minio 建议换云托管或 Operator。
