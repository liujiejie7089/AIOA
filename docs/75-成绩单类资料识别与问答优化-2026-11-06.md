# 成绩单类资料的识别与问答优化（知识库全流程）

> 现象（用户截图，2026-11-06）：问「我的平均绩点和成绩」，数字人回答
> **「未取得你本人的平均学分绩点数据……知识库里命中的是**栏名**（历年平均成绩、历年平均学分绩点），
> 但**没有相邻的数值**，无法可靠给出数字。如果你能提供成绩单文件/截图，我可以帮你录入并统计。」**
>
> 也就是说：**文件在库里、文字也检索到了、模型也承认看到了栏名**，就是拿不到数字。
> 本文回答三件事：**问题出在哪个环节（带实测证据）→ 怎么改（文件级）→ 改完怎么证明有效（可复现判据）**。
>
> 与 `docs/74` 的关系：74 解决的是「表格被切碎 / 聚合无解 / 排序塌陷 / 参考块恒空」这四类**通用**知识库缺陷；
> 本文处理 74 做完之后**仍然答不出**的那一类资料 —— **PDF 拍平的表格**（成绩单是典型）。
> 74 的表格链路只认 Markdown 表格（Excel 转出来的），PDF 取文本后既没有 `|` 也没有列结构，压根进不了那条链路。

三处结构性缺陷，逐条对应到「为什么 AI 只能答'没拿到数值'」：

1. **四栏并排 ⇒ 一行里混着 4 门课**。按行切出来的块里，课程与课程性质、学分、成绩的**列归属关系**靠空格数量，机器读不出来。
2. **表头拆两行 ⇒ 列名本身是碎的**（`课 程 / 名 称`、`学 成 补 重 / 分 绩 考 修`），就算切出一块也只含"半个列名"。
3. **汇总标签行与数值行分离 ⇒ 检索命中栏名时旁边没有数**。这是用户看到的直接原因，也是模型如实回答「没有相邻的数值」的原因——**它没说错，是数据真的不在那儿**。

## 2. 逐环节改造

### 2.1 解析：`GradeSheetExtractor`（新增）

`server/aios-resource/src/main/java/cn/aios/resource/support/GradeSheetExtractor.java`

- **课程记录**：一条正则锁定「名称 → 性质 → 学分 → 成绩 →（补考）」的固定顺序，性质限定为
  `2~4 个汉字 + 必修/选修`（通识必修、专核必修、复培选修…），成绩允许百分制或五级制。
  补考分要求「后面是空白或结束」——否则会把 `2025-2026学年` 截成 `202` 当补考分（原型阶段实测踩过两次）。
- **汇总记录**：找到含 `历年平均 / 总学分 / 毕业设计` 的行当作**标签行**，取它的下一非空行当**数值行**，
  两侧去掉填充词（`其中 / 包括 / 含`）后按 token 位对齐；数值比标签少时**右对齐**——
  这样首格为空的 `毕业设计(论文)题目` 不会被错配成 `80.26`。
- **回填**：`enrich()` 把两张表以 Markdown 拼到正文尾部（`### 成绩明细` / `### 成绩汇总`），
  **幂等**（已回填则原样返回），因此存量资料**无需重新上传**，点一次「重试」即可修复。
- **防误伤**：`isGradeSheet()` 要求正文同时含「成绩」「学分」且能抽出 ≥3 条课程，
  普通文本、只有「学分」二字的通知都不会被改写（单测覆盖）。

为什么回填正文而不是另存结构化表：原件字节在上传时就被丢弃（`KbController.uploadFile` 只存解析文本），
历史资料无法回溯重建；回填到 `content` 后，`retry` 与 `kb_table_query` 读的都是同一份数据，**PDF 与 Excel 汇入同一条下游链路**。

### 2.2 索引：接入 `KbService.index()`

`index()` 在切分前先 `enrich`，**并把结果写回 `doc.content`**（`kb_table_query` 读的正是这个字段，
不写回等于只修了检索、没修聚合）。随后：

- `MarkdownTable.parse` 认出两张表 ⇒ 每个数据块带 `《doc》/成绩明细｜列: 课程名称/课程性质/学分/成绩/补考｜`；
- `statsChunks` 生成统计摘要并**置于切片 0**：`数据行合计：62 条｜按「课程性质」：学基必修 15 条、通识必修 11 条…`；
- 原有落库自检（声明切片数 ≠ 实际行数就抛错）继续生效。

另外修了 `MarkdownTable.statsText` 的一处噪声：**每行都不同的列直接跳过**（键列分组只会得到
`xxx 1 条、yyy 1 条…`）。成绩汇总表（项目/数值）因此不再产生无意义的分组计数。

### 2.3 检索：修掉「不传 mode ⇒ 恒 0 条」

`ToolGatewayService.searchKb`：

```java
// 旧：args 里没有 mode 时 String.valueOf(null) == 字符串 "null" ⇒ store 认不出 ⇒ 两路都不打分 ⇒ 0 条
String mode = args == null ? null : String.valueOf(args.get("mode"));
```

改成 `strArg()`（缺省返回 `null`）并归一化 `"null"/""/auto/default` → `null`；
同时 `MysqlKnowledgeStore.normalizeMode()` 兜底：**认不出的模式一律退回 `hybrid`** 并打 warn。

这条不是洁癖：模型不传 `mode` 是**常态**，而失败时的返回是 `{"ok":true,"data":[]}` ——
调用方无从区分「库里没有」和「模式传错」，最终就表现为用户那句
「知识库明明有文件，AI 说没有」。

### 2.4 聚合：`kb_table_query` 补数值与行样本

`KbTableQueryService` 原来只回条数，回答不了「学分合计多少」「某门课多少分」。新增三块（都只对当前用户可见资料生效，口径不变）：

| 字段 | 内容 | 用途 |
|---|---|---|
| `numeric` | 每列 `{sum, avg, count}`，**仅对「整列都是数」的列**计算 | 「学分合计 134.0」「平均每门 2.161 学分」 |
| `groups[].sums` | 分组内的数值合计 | 「学基必修 15 门 / 33.0 学分」 |
| `rows` | 命中行样本（≤10 行，列名→值） | `filter="课程名称=大学物理B1"` 直接带回 `56 / 补考 62` |

口径刻意保守：**混排列不硬算**。成绩列里「优/良/中」与百分制混排，强行求平均会得到一个假分数，
所以它不进 `numeric`，模型必须走「成绩汇总」的权威口径（`80.26`）。宁可不算，也不给错数。

### 2.5 答案生成：提示词第 7 条

`agent/aios_ai/prompt/builder.py` 系统提示新增：

> 7. 成绩单 / 学业成绩表 属于表格类资料：库里有「成绩明细」与「成绩汇总」两张表时，**先引用「成绩汇总」**（标签与数值同行，是权威口径）……
> ②要算数就调 `kb_table_query` —— 查单门课传 `filter="课程名称=课程名"`，看分类传 `groupBy="课程性质"`，
> 要合计直接读返回里的 `numeric`（sum/avg）或 `groups[].sums`，**不要自己心算**。
> ③**平均学分绩点与平均成绩是两个口径**（如 2.69 与 80.26），不要把绩点当百分制分数……
> ④确实两处都没有数值时，才说「未取得该项数值」，并说明是资料里该栏为空。

第 ④ 句是给「真没有」留的正当出口 —— 修的**不是**让模型不许说没有，而是让它**先真正看到**再判断。

## 5. 已知边界（没做/做不到的，写清楚）

1. **不是通用 PDF 表格识别**。`GradeSheetExtractor` 只认「名称/性质/学分/成绩/补考」这种成绩单字段序（国内高校成绩表的主流版式）。
   其它版式的 PDF 表格仍会走原路径（拍平文本 + 按行切片），答不出来时模型会按提示词如实说「该栏为空」。
   要通用化得引入版面分析（Camelot/pdfplumber 的表格检测），属于另一个量级的改造。
2. **只对已入库正文生效**。修复靠「重试」重建索引；原件 PDF 字节上传后即丢弃，因此**改不了原件**，也不需要改。
3. **`numeric` 不做单位换算与加权**。绩点是加权平均还是算术平均由成绩单自己算，工具不反推——
   反推出来的 2.69 一旦与原表不符，比不给数字更糟。
4. **检索排序仍有优化空间**。问「平均学分绩点」时 top1 是统计摘要（不含数值）、top2 是旧碎片，
   含 `2.69` 的汇总块排第 3；topK=5 下不影响作答（三块都进参考块），但排序本身可以更准。
5. **五级制混排列不进 `numeric`** 是**有意**的保守，不是遗漏（见 §2.4）。
