## 三、三处技术陷阱（都已处理，勿重踩）

### 3.1 Flyway 历史迁移脚本**不能跟着改名**
批量替换改到了 32 个 `V*.sql`（多数只是注释里的「AIOA」），但 **Flyway 会对已执行的迁移做 checksum 校验**，
一旦内容变化，生产启动直接 `Migration checksum mismatch` 拒绝启动。

处理：把这 34 个文件（32 个 + 2 个被间接改动）**按 HEAD 逐字节还原**。
判据：`git diff --cached -M --numstat -- 'server/*/db/migration/*.sql'` 输出
`88 files changed, 0 insertions(+), 0 deletions(-)` —— 即 88 个迁移全是**纯路径改名、内容零变化**。
历史迁移里保留的旧品牌字样属「历史记录不可变」，新语义请写新迁移，不要回改老迁移。

### 3.2 运行中的后端会锁住 `server/aioa-boot/target/`
目录整体改名时报 `Permission denied`：`java.exe` 正持有 `aioa-boot-0.1.0-SNAPSHOT.jar`。
处理：不杀进程，改为**把 `pom.xml`/`src`/`uploads` 搬进 `server/aios-boot/`**，只留 `target/` 在旧目录。
收尾：停掉后端后删除空壳目录 `server/aioa-boot/`（目前仅剩 target）。

### 3.3 本环境 `git update-ref` 静默失效
`git checkout -b rename/aios` 得到的是**未出生分支**（HEAD 指向的 ref 没有写出来），
`git update-ref` 返回 0 但 `.git/refs/heads/rename/aios` 并未创建，导致 `git rev-parse HEAD` 报
`unknown revision`。手工写入 ref 文件后恢复：
```bash
mkdir -p .git/refs/heads/rename
printf '%s\n' <main-commit-sha> > .git/refs/heads/rename/aios
```
遇到「分支明明切了却说没有提交」先查 `git rev-parse HEAD`，不要怀疑工作区。

## 五、生产上线步骤（顺序不能换）

1. **停机**（后端停写，避免迁移期间丢数据）
2. 备份：`mysqldump aioa > aioa-backup-$(date +%F).sql`
3. 跑 §四 的迁移脚本 → 得到 `aios` 库
4. **更新部署机上未入库的 `deploy/.env`**：
   - `MYSQL_DB=aios`（或 `SPRING_DATASOURCE_URL` 里的库名）
   - 所有 `AIOA_*` 变量名改为 `AIOS_*`（本次改名把变量前缀也换了，旧变量名**不再被读取**）
5. `docker compose build --no-cache server agent` → `docker compose up -d`
6. 验证：
   ```bash
   docker compose ps                      # server healthy、agent Up
   curl -s http://127.0.0.1:8080/aios/api/v1/actuator/health   # 新前缀
   docker compose exec agent python -c "import aios_ai; print('ok')"
   ```
7. 旧库 `aioa` 观察 1–2 天后再 DROP。
