## 2. 分项说明

### 2.1 F4 · 四期：`ApproverResolver` 策略族

**现状证据**：改造前入参类型 → 人的映射写死在 `ApprovalFlowService.expandNodes` 的一个 `switch` 里；
`resolveDeptLeader` 等三个私有方法把「谁算部门负责人」的求值口径锁在引擎内部；
`DEPT_LEADER` 是唯一能表达「部门领导」的类型，无法表达「部门副职」「机构负责人」，
因此流程模板无法跨部门 / 跨机构复用。

**落地方案**
- 新增策略族（`cn.aioa.org.support.approver`）：
  - `ApproverStrategy`（接口 + `Candidate` 有序候选 + `Context` 求值上下文）
  - `ApproverResolver`（注册表 + 门面 + 姓名补全 + 职务名解析）
  - `DutyApproverStrategy`（抽象基类：职务存在性 + `can_approve` + 作用域 + 目标组织校验）
  - `DeptDutyApproverStrategy`（`DEPT_DUTY`）、`UnitDutyApproverStrategy`（`UNIT_DUTY`）
  - `DeptLeaderApproverStrategy`（`DEPT_LEADER`：先职务、后回落 `leader_user_id`，含跨部门兜底开关）
  - `ApproverStrategyConfig`（`ORG_ADMIN` / `TENANT_ADMIN` / `PLATFORM_ADMIN` / `SPECIFIC` 四个固定口径）
- 关键设计：策略返回**有序候选列表**而非单值 —— 这是五期会签 / 抢占的数据基础；
  解析层只管「求到谁」，消费层（`mode`）只管「用几个」。
- 安全边界：所有查人动作带 `tenant_id`；`UNIT_DUTY` 指定的机构必须属同租户，否则按「解析不到」处理
  （不泄露机构是否存在）。
- 兜底纪律沿用既有口径：解析不到 → 引擎顺延并在单据写明原因，**不静默跨部门改派**。

**验收**
| 编号 | 标准 |
|---|---|
| A4-1 | `DEPT_DUTY` + `duty_code=DEPT_PRINCIPAL` 与 `DEPT_LEADER` 解析出同一人 |
| A4-2 | `DEPT_DUTY` + `duty_code=DEPT_DEPUTY` 命中副职（原口径完全命不中） |
| A4-3 | `UNIT_DUTY` + `duty_code=ORG_LEADER` 命中机构职务成员 |
| A4-4 | 职务 `can_approve=0`（STAFF）→ 解析不到，节点顺延且单据写明原因 |
| A4-5 | `UNIT_DUTY` 指向**他租户**机构 → 解析不到（不返回他人、不报 403 泄露存在性） |
| A4-6 | 作用域错配（`DEPT_DUTY` + `ORG_LEADER`）→ 解析不到并留日志 |
| A4-7 | 换人不动流程：只改 `org_member.duty_code` 后重新提交，审批人随之改变、`steps_json` 不变 |
| A4-8 | 未注册类型 → 空候选 + 兜底改派（类型改为实际生效类型），不抛异常 |

### 2.2 F5 · 五期：处理模式 + 条件路由

**现状证据**：`isCurrentNode` 按任务 id 比较，`nextPending` 按 seq 递增 —— 每个 seq 只能有一条任务，
无法表达「一个节点多个人」；`steps_json` 无任何条件字段，只能靠 `threshold_days` 做单维跳级。

**落地方案**
- `mode`：`single`（缺省，取首候选，与改造前逐字等价）/ `parallel`（会签，全通过才推进）/
  `grab`（抢占，任一人处理即完成，其余同组置 `SKIPPED` 并写明被谁抢先）。
- 节点组：同一 `seq` 的多条任务构成「第 N 级」；`isCurrentNode` 改为**按 seq 比较**；
  `countTasksOfOrder` 改为 `COUNT(DISTINCT seq)`（对单人模式恒等，既有断言不受影响）。
- `when` 条件路由：`{"field":"days","op":"<=","value":3}`；取值先看请求内置字段
  （`days` / `bizType` / `departmentId` / `institutionId` / `applicantType`），
  再回落业务表单 `form_data` 的同名字段（如 `tokens`、`leaveTypeCode`）。
- **失败方向刻意相反**：运行期宽容（未知模式退回 single、坏条件不拦截、未知运算符保留节点 ——
  宁可多审一级不可漏审），保存期严格（`writeSteps` 校验 mode / when / cc 形态，400 报错）。
- 不变量：条件路由**永远至少留下一个生效节点**（回落第一个无条件节点 → 末级节点），并写「流程提示」。

**验收**
| 编号 | 标准 |
|---|---|
| A5-1 | `mode=single` + 多候选 → 只落 1 条任务（缺省行为，向后兼容） |
| A5-2 | `mode=grab` + 2 候选 → 同 seq 2 条 PENDING；任一人通过 → 其余 SKIPPED（含原因）+ 立即推进 |
| A5-3 | `mode=parallel` + 2 候选 → 第一人通过后**不推进**（单据仍 PENDING、`nodeDone=false`）；第二人通过才推进 |
| A5-4 | `parallel` 中一人驳回 → 整单 REJECTED（一票否决） |
| A5-5 | `when` 命中 → 节点参与；不命中 → 该节点 SKIPPED 且不入 timeline 的 PENDING |
| A5-6 | 全部条件不命中 → 回落默认分支，且「流程提示」写明回落 |
| A5-7 | 「共 N 级」按 distinct seq 计（会签节点不被算成 N 级） |
| A5-8 | 保存期：非法 `mode` / 缺 `field` 的 `when` → 400 且不落库 |

### 2.3 F3-1 · C-11 知会支持指定具体人

**现状证据**：`parseSteps` 把 `cc` 解析为 `List<String>`（角色类型），`expandCcNodes` 只认四种角色类型，
`default -> null` 使「指定某人」这种诉求直接落空。

**落地方案**：`cc` 元素支持对象形态 `{"type":"SPECIFIC","user_id":123}`（同时保留字符串形态），
按人 id 去重、排除申请人本人与已是审批人的人；`writeSteps` 校验对象必须含 `type`。

**验收**：A3-1（指定人收到 CC 任务且不阻塞）/ A3-2（重复指定同一人只生成一条）/ A3-3（指定申请人自己 → 被过滤）。

### 2.4 F3-2 · 知会覆盖业务类型补齐

**现状证据**：默认 `cc` 由 V44 回填，仅覆盖 `PERMISSION_GRANT` / `LEAVE` / `QUOTA_EXPAND` / `RESOURCE_OPEN` 四类；
其余真实存在的 bizType 无默认知会。

**落地方案**：先核查代码中全部真实 bizType 常量，再对**实际存在流程定义**的业务类型追加回填
（只填空值、不覆盖既有配置）。不得为文档里推测的、运行时不存在的字面值造配置。

**验收**：A3-4（枚举 bizType 常量与 `approval_flow_def` 实际 biz_type 取交集，逐一确认知会状态）。

### 2.5 F2-1 · E-10 部门申请对部门成员可见

**现状证据**：以部门名义提交的申请（`applicant_type='DEPARTMENT'`）只有提交人（部门正职）与审批人可见，
部门成员在清单里看不到本部门的名义申请。

**落地方案**：清单接口对「本部门成员」只读可见部门主体申请；个人主体申请的可见性不变；
跨部门 / 跨机构 / 跨租户仍 404/403。

**验收**：A2-8（本部门成员可见）/ A2-9（跨部门成员不可见）/ A2-10（个人主体申请不被扩大可见）。

### 2.6 D-1 · 登出吊销令牌

**现状证据**：`AuthController.logout` 仅记审计，`JwtAuthenticationFilter` 只验签名与过期，
令牌在 TTL 内始终有效。

**落地方案**：服务端引入令牌吊销（按 `jti` 或用户维度的失效水位），`logout` 后旧 token 立即 401；
未登出的令牌不受影响（大量既有套件复用同一 token 连续调用，不能误伤）。

**验收**：D1-1（登出后旧 access token → 401）/ D1-2（登出前正常）/ D1-3（登出不影响其他用户的令牌）。

### 2.7 D-2 · 路径参数类型不匹配 → 400

**现状证据**：`GlobalExceptionHandler` 已映射 `MethodArgumentNotValidException` / `HttpMessageNotReadableException`
等入参错误，但**未**映射 `MethodArgumentTypeMismatchException` —— `/workflow/tasks/abc/decide`
会落到 `Exception` 兜底返回 500。

**落地方案**：补映射（含 `TypeMismatchException` / `MethodArgumentTypeMismatchException`），返回 400 + 明确 message。

**验收**：D2-1（`/workflow/tasks/abc/decide` → 400，非 500）/ D2-2（合法 id 仍正常）。

## 4. 收口纪律

3. 每项完成即跑同批回归（新套件 + 相关既有套件），最后跑 `e2e_full_system` 全量收口。
4. 前端改动必跑 `vue-tsc --noEmit`。
5. 收口前 `git status --porcelain | grep -v '^??'` 确认无跟踪脏文件。
