# 91. 查询结果自动图表渲染（2026-11-21）

## 1. 需求与问题

用户截图反馈：问「工坊电商平台销量柱状图，成都市」时，agent 明明已把工具返回的真实数字
整理成规范统计表，并在正文写了「柱状图按上表数值渲染即可，横轴为平台、纵轴为 num」，
但 H5 只渲染成一张 Markdown 表格，没有真正的图表。

需求：查询返回的数据属于绘图/可视化类时，按数据结构和查询意图**自动判断并动态渲染**
对应图表（柱状/饼图等），自动映射标题、分类维度、数值、图例、坐标轴；结果变化时图表
同步更新；非绘图类保持原样；无数据/格式异常安全降级。

## 2. 方案：纯前端零依赖 SVG（不改 agent / 后端 / SSE）

关键判断：数字来源已经可靠——agent 按 `prompt/answer.py` 规则 5 把工具结果整理成
`维度层级 | 数量 | 数据来源·备注` 三列表，正文还带图表意图词。缺口只在 H5 的
`formatAnswer()` 只输出 `<table>`。因此：

- 在 `formatAnswer()` 的表格识别分支里，自动检测「首列分类 + 某列纯数值」结构；
- 命中则把表格数字映射成 SVG 图表，原始表格折叠保留在图表下方供核对来源；
- 未命中（无数值列 / 数据行 < 2 / 数值解析失败 / 分类 > 24）原样返回表格；
- `formatAnswer()` 的 5 个调用点（经典 send / OA dock / 历史回看 / 两种暂停帧）
  每次都整体重写 `innerHTML`，所以结果变化时图表天然同步重建，无残留。

**为什么不从工具结果直接画图**：那要改 agent 输出协议 + SSE + 前端，跨三层且模型可能
不遵守新协议；表格数字本身就是工具返回的真实值（铁律 7/12：不编造、可溯源），从表格
读取既满足真实性又最小侵入。

## 4. 自动判定规则

### 4.1 是否绘图（chartDetect）
- 表格有分隔行、至少 2 行数据、分类数 ≤ 24；
- 首列之外的某一列**每一行**都能解析成数字（`chartNum` 剥离千分位/单位/加粗）；
- 否则返回 null → 原表格。

### 4.2 图表类型（显式优先 + 弱信号兜底）
- 正文中出现的**显式图名按首次出现位置**取：饼图/柱状图/折线图；
  - 踩过的坑：真实回答标题写「柱状图数据」、正文又写「占比最高（27/58）」，
    若先判「占比」会把柱状图错画成饼图 ⇒ 改为显式图名优先、按位置取。
- 无显式图名时：含「占比/构成」或数值皆在 0~100 且分类 ≤ 8 → 饼图，否则柱状图。
- 未来自信扩展：折线图（`/折线|趋势/`）已实现 `chartLineSvg`。

### 4.3 自动映射
- 标题：表格上方最近的非表格文本行，去掉 `#`/`**`/末尾`（工具名/路径）` 括注与冒号；
  取不到则回退「首列 · 数值列」。
- 分类轴/数值轴：取表头对应列名（横轴：维度层级　纵轴：数量）。
- 图例：饼图右侧色块 + 百分比；柱状图靠颜色区分 + 数值标签。
- 合计行（合计/总计/小计/total）不入图，避免双计。

## 5. 异常与安全
- 无数据行、数值解析失败、分类过多、识别/渲染抛异常 → 一律回退原始表格，不出现空图。
- 所有进入 SVG 的文本（标题/类目/轴名/aria-label）先经 `esc()`，无 HTML 注入面。
- 负数、千分位、单位（人/个/%/万元）、加粗标记均可解析；数值轴刻度自动 nice 取整。

## 8. 环境坑
- H5 由 `user-client/serve.py` 静态托管，`Cache-Control: no-store`，改 `index.html` 即时生效，无需重启。
- 用户端默认 OA 形态（`.phone.oa-mode`），可见会话容器是 `#oaDockList`；经典 `#msgs` 是隐藏 DOM。
  验证脚本必须注入 OA dock 并给 `#v-home` 加 `.chatting` 才看得到气泡。
- `oaPushBub` / `oaSetChatting` 不在全局作用域，`page.evaluate` 里直接构造 `.bub` 节点 +
  `innerHTML = formatAnswer(a)` 等价且可行。
- Playwright `inner_text()` 对 SVG 节点 / 折叠 `<details>` 返回空，核对文本用 `text_content()`。
- 图表模式下原表格折叠在 `<details>` 里（不可见）：Playwright `wait_for_selector('table')`
  默认等 visible 会超时，要用 `state="attached"`（2026-11-21 历史回放验收实测）。

## 9. 历史回放同版式（2026-11-21 追加，用户截图反馈）

用户在 OA 形态打开历史对话，表格/图表/粗体全部裸露为 Markdown 原文。根因：三条历史渲染路径
只有经典 `resumeConversation → historyBubble` 走了 `formatAnswer`，另两处漏网——

| 路径 | 修复前 | 修复后 |
|---|---|---|
| 会话记录弹窗展开 `toggleHistoryDetail()` | `esc()` 纯文本 | AI 侧 `formatAnswer()` |
| OA 恢复/最近点击/刷新自动恢复 `oaResumeConversation()` | `txt()` 纯文本 | AI 侧 `formatAnswer()`（防御式） |

用户侧消息保持纯文本（与实时路径一致）。历史回放因此同样触发 §2 的自动图表判定。

连带修复的两个真缺陷（都在 `oaBoot` 链上，导致「刷新接上上次对话」从未生效）：
1. `oaBoot` 只定义、只暴露（`window.oaBoot`），全文件**无任何调用点**——`oaRestoreLastConv` 永不执行。
2. 自启动最初放在 IIFE 中部仍不生效：脚本块 2 的 IIFE 直到**文件末尾**才读 `LS_MODE` 定 `S.mode`
   并 `bind()`，中部执行时 `S.mode` 还是初始 `'classic'`，被 `oaBoot` 的「非 OA」分支提前跳过
   （console 插桩实测 `boot start, mode-pre=classic`）。⇒ 自启动必须放 IIFE 末尾 `applyMode()` 之后。
3. 结构加固：恢复调用从 `loadOaExtras().then(fillSheet; oaRender; restore)` 链里拆出独立执行——
   `fillSheet/oaRender` 任一同步抛错都会跳进空 `catch` 把整条链静默吞掉；现 catch 均带 `console.warn`。

验证（`scripts/_verify_history_replay_format.py`，9/9 PASS）：UI 真实提问 → 当场渲染表格+图表 →
`reload` 自动恢复 → 历史气泡同样渲染表格+图表、无裸 `|---|`、粗体表现与当场一字不差。
截图 `docs/screenshots/history-replay-2026-11-21/`。

已知边角（未修，当场与历史一致故不属本缺陷）：模型把粗体标题与表格粘连成一行时
（`**标题**（来源）| 表头 |`），`formatAnswer` 行内粗体不覆盖该上下文，行尾残留孤立 `**`。
