## 2. 架构决策：并入 `index.html`，不新建文件

### 2.1 否决「新建 `oa.html`」的决定性证据

`deploy/Dockerfile.server` L28：

```
COPY user-client/index.html /out/h5/index.html
```

生产镜像**只拷 `index.html` 这一个文件**（H5 是自包含单文件，零构建）。若新建 `oa.html`：
- 必须改 Dockerfile 增拷文件；
- 数字人位图必须内联（原本已内联）否则 `assets/*.webp` 404；
- 网关 `/user` → `/aios/h5/` 改写规则（`deploy/生产部署手册.md` L255）需重新核对多文件场景。

⇒ **收益（代码隔离）小于成本（部署面扩大 + 回滚变复杂）**。

### 2.2 采用方案：同文件双形态

```
index.html 单文件
├── :root 令牌（既有品牌蓝）
├── [data-mode="oa"] 覆盖：--brand:#12b39a 等
├── 既有视图 page-*（一行不改）
├── 新增视图 page-oa-home / page-oa-task / page-oa-kb / page-oa-dept（新增 id，不覆盖）
├── 既有 tabbar（classic）
└── 新增 tabbar（oa）：首页 / 任务 / 知识库 / 部门 / 我的
```

**改动面收敛为 3 处**（其余全是新增）：
1. `go()` / `switchTab()` / `setTitle()` 增加 mode 分支；
2. 两个 tabbar 的显隐（`data-mode` 控制）；
3. 「我的」页新增「界面版本」分段控件（调用 `setMode`）。

`state` 增加单字段 `mode:'classic'|'oa'`，持久化到 `localStorage.aios_mode`（与既有 `aios_session` 同一存储域，刷新不丢）。

### 2.3 为什么不动既有视图

`index.html` 4806 行承载全部已验收业务（审批双引擎、请假、权限申请、投诉建议、账单、成果、Gitee…）。OA 形态**只做新增与分流**，保证：
- 经典形态回归面 = 「切换开关 + tabbar 显隐」两处；
- 出问题可一键切回经典形态，业务不中断。

## 5. 关键交互：数字人锚点对话（用户第 5、6 条口径）

### 5.1 为什么不复用 `page-chat`

既有 `page-chat` 是**整页会话**（`flush` 满屏，tab 切走才回来）。用户要求「就在对话框里对话，**不能跳到其他地方**」，且气泡要指着数字人 —— 这是**首页内的对话坞**，与整页会话是两种形态。故：
- 对话坞复用 `API.stream` 的**同一套 SSE 处理**（把 `page-chat` 的流式渲染抽为 `renderStreamInto(target, ...)`，两处共用，避免两套口径）；
- 对话坞独立 `state.oaConvId`，与 `state.conversationId` 分账，互不干扰。

### 5.2 交互链路（全部留在首页）

```
点击数字人
  └─ 底部选择卡（数字员工 / 专家 两个分段）
       ├─ workers()  → 选中 → setOaWorker(w)
       └─ experts()  → 选中 → setOaExpert(e)
  └─ 选择卡收起 → 对话坞展开（数字人仍在首页原位）
       └─ 输入 → ensureOaConversation() → createRun → stream
            └─ 气泡逐字流式出现在数字人下方（全程不离开首页）
```

### 5.3 ~~气泡三角朝向算法（「都对着数字人」）~~ ⛔ 2026-10-11 作废（仅存档）

> **本节整节作废。** 2026-10-11 按用户口径「去掉对话框的三角」移除了气泡尾巴，故不再需要「朝数字人」的角度计算。
> 现状：`oaPushBub` 不再生成 `<svg class="tail">`；`.bub .tail` 的 CSS 与 `oaLayoutTails()` 保留但不再被调用（留作复用）。
> 判据已反转为：**坞内所有气泡都不得有尾巴**（`.bub .tail` 子节点 = 0，且 `.bub` 的 `::after/::before` 不得渲染出三角）。
> 下文算法描述保留只为追溯历史，**不得据此恢复实现**。

数字人是**坐标锚点** `A(x_A, y_A)`（首页居中偏上）。每个气泡矩形 `B`：

```
cx = B.left + B.width/2      // 气泡中心 x
cy = B.top  + B.height/2     // 气泡中心 y
dx = x_A - cx ,  dy = y_A - cy
θ  = atan2(dy, dx)           // 气泡中心 → 数字人 的方向角
```

三角沿「气泡中心 → 数字人」射线与气泡矩形边框求交点，落位于该边，并绕自身中心旋转 `θ - 90°`（三角基准朝上）：

```
t = 三角自身中心到气泡中心的距离        // 由气泡尺寸决定
tail.angle = θ - Math.PI/2
```

CSS 侧用两个变量承载，避免 JS 逐帧算布局：

```css
.bub{ position:relative }
.bub .tail{
  position:absolute;
  left:var(--tail-x); top:var(--tail-y);
  transform:translate(-50%,-50%) rotate(var(--tail-angle));
}
```

**实现时序**：气泡插入 → `requestAnimationFrame` 量测 `robotRect` / `bubbleRect` → 写回 `--tail-*`。滚动 / 尺寸变化 / 流式追加时重算（`ResizeObserver` + 节流）。

**降级策略**（必须实现，否则极端情况会错位）：
1. `prefers-reduced-motion: reduce` → 关闭数字人 `r-bob`/`r-sway`，三角仍按公式定位（静态仍正确）；
2. 视口过窄（< 360px）或气泡与数字人重叠 → 退化为**三角恒朝正上方**并居中，保证可读；
3. 数字人因滚动离开视口 → 退化为**sticky 顶部头像**，三角仍指向该头像（几何关系不变）。

### 5.4 气泡对齐口径

按用户口径「**都**对着数字人」，故**不采用** IM 常规的左右分侧（AI 左 / 用户右），而是：
- 全部气泡沿数字人下方**纵向单列**排布；
- ~~三角统一收敛指向数字人~~（2026-10-11 三角已移除）—— 气泡仍沿数字人下方**纵向单列**排布（这一条保留）。

若后续希望区分角色，用**底色 + 左侧竖色条**区分（`--brand` 底 = AI，`--surface-3` 底 = 用户）；三角已于 2026-10-11 移除，不再作为朝向载体。

### 11.3 顶栏随滚动隐藏 + 澄清卡选择后联网检索（2026-10-30 第二轮）

用户口径（原话）：

#### A. 顶栏与滚动：方向 ↔ 状态

判据只有一条，和数字人渐隐**共用**（`oaSyncDockFade`，`OA_FADE_GAP = 24`）：
`gap = scrollHeight - clientHeight - scrollTop`，`gap > 24` 即「正在翻历史」。

| 用户动作 | `gap` | `#v-home.dock-scrolled` | `#oaRoot.bar-hidden` | 页面表现 |
|---|---|---|---|---|
| 停在底部（含刚发完消息） | ≈0 | 无 | 无 | 顶栏 52px 实心 + 数字人正常 |
| 向上滚动（看历史） | >24 | 有 | 有 | 顶栏高度 0、背景/描边透明、标题 opacity 0；数字人同时渐隐 |
| 停在中间不动 | >24 | 有 | 有 | **保持隐藏**（不因「停下」而弹回，否则一停就闪） |
| 向下滚回底部 | ≈0 | 无 | 无 | 顶栏与数字人一起回来 |
| 切到任务/知识库等页 | — | 无 | 无 | `oaGo()` 末尾调 `oaSyncDockFade()` 立即还原 |

**为什么判「离底距离」而不是判「滚动方向」**：方向事件只在滚的那一瞬间成立，用户停下来
就无从判断；而「离底多远」是状态量，任何时刻都能重算，且滚到底时 `scrollTop` 恰好等于
`scrollHeight - clientHeight`（拿它跟阈值比会把「停在底部」判成「在上滑」，现象正好反）。

**为什么顶栏必须连高度一起收**：数字人是浮在内容上的装饰，只降 `opacity` 就够；
顶栏是横在内容上方的一条**实心带**，只把字变透明 = 留一条 52px 空白带，等于没隐藏。
所以 `bar-hidden` 同时给 `height:0 / padding:0 / border-bottom-width:0 / background:transparent`。
收高度不会让聊天记录跳：对话坞自己的 `scrollTop` 不变，只是可视窗口从下方多出 52px。

**只在首页生效**：`hideBar = scrolled && v-home.classList.contains('on')`。任务页/知识库页的
滚动跟「翻聊天记录」是两回事，不该把顶栏弄丢。

#### B. 联网检索：三个真缺陷（都不是措辞问题）

原现象：用户选完「就业政策」，数字人回「未能找到关于就业政策的邮件……」。查下来是 **能力缺失**，
不是它不肯查 —— 当时系统里**没有任何联网工具**，模型手里只有 QQ 邮箱/企微 MCP + 知识库，
于是把「内部没有」当成「网上没有」。补完工具后，真实操作又连踩三坑：

| # | 缺陷 | 证据 | 修法 |
|---|---|---|---|
| 1 | 系统没有联网工具 | grep 全仓无搜索类工具，`tool_definition` 40+ 条全是 `scfy_*`/`agent_health*` | 新增 `agent/aios_ai/tools/web_search.py`（`web_search` + `web_fetch`），在 `ToolClient.invoke` **最前面**拦掉，不走 Java 网关、不进 mcp-hub、不受连接器闸门影响 |
| 2 | `tool.result` 帧的 `name` 恒为 `null` | SSE 抓到 4 条 `tool.result` 全是 `{"name":null,...}` —— `task.started`/`task.skipped` 都带 `tool`，唯独 `task.completed` 漏了 | `orchestrator._run_task` 的 `task.completed` 补 `"tool": task.tool` |
| 3 | 模型不知道「今年」是哪年 | query 被写成「2024年 就业政策 变化」（实测日期 2026-10-30），整篇答成两年前的旧闻 | 提示词每轮注入【当前时间】（东八区，`datetime.now(_TZ_CN)`）；并要求检索词带当前年份 |
| 4 | 检索成功但内容跑题 | query「2026年 就业政策 变化」被 Bing 答成「2026年节假日安排」，模型把节假日条目铺满一屏 | 提示词加「结果先判是否切题 → 跑题换核心词重查（最多 2 次）→ 仍跑题就如实说没检索到，**不得**用无关结果凑数」 |
| 5 | 引用抓取失败的链接 | `web_fetch` 对某 gov.cn 链接 404，模型仍把它写成「来源」 | 提示词加「引用链接必须来自 `web_search` 实际返回的 url；`web_fetch` 失败的链接不得当来源，也不得自己拼网址」 |

**联网失败时的兜底（用户要求明确说明）**：

1. **工具层**：一切失败（网络不可达 / 反爬 / 页面无结果块 / 非法 URL / 空 query）统一
   `ok=False` + `"联网检索失败：<可读原因>"`，**绝不返回空列表冒充成功** —— 两者对用户的意义完全不同；
2. **模型层**（提示词硬规则）：收到 `ok=false` 必须如实说「联网检索没成功」+ 原因，再给替代方案
   （换关键词重试 / 请用户给具体网址 / 改用内部资料），**不得编造结果**，也不得把失败说成「网上查不到」；
3. **界面层**：回答照常渲染；能拿到部分结果时按结果作答并注明来源；`cite` 溯源由
   `kb._citations_from_tool` 从 `web_search` 结果生成（`docId=URL`、`source='web'`），
   用户点得回原文；
4. **开关**：`AIOS_WEB_SEARCH`（默认 true）、`AIOS_WEB_TIMEOUT`（默认 12s）；关掉后工具表与改造前逐字节一致。

  溯源 source=web / `task.completed` 带 tool / 开关默认开）。

**两个新增坑（写进 pitfalls，勿回退）**：
1. 选择器不能写 `.oa #oaRoot.bar-hidden .appbar` —— `#oaRoot` 自己就带 `.oa`
   （`<div class="oa" id="oaRoot">`），要找的祖先 `.oa` 在文档里不存在 ⇒ 规则整条不匹配，
   class 挂上了但样式纹丝不动（实测：`bar-hidden=true` 而 appbar 仍 52px 白底）。以 id 起头。
2. `border-bottom:1px solid` 即使颜色透明**仍占 1px** ⇒ 高度收到 0 后实测是 `1px`，
   要让高度真为 0 必须同时 `border-bottom-width:0`。

### 11.4 个人信息不得编造 · 调用原文不得外发 · 空回答不得成死胡同（2026-10-30 第三轮）

用户现场（截图）：问「我邮箱是多少」→ 答「您的企业微信邮箱是：**liuyang@yourcompany.com**
（假设公司域名为 yourcompany.com）」，随后追问「qq」→ 气泡显示「（本次未返回内容）」。

复现（真 token + 真 agent + 真模型，`logs/proof/repro_t1_email.json`）拿到三段硬证据：

```
tool.call    {"name":"mcp__wecom_cli__whoami","arguments":{}}
tool.result  {"name":"...whoami","ok":true,"summary":"... {\"bound\": true, \"userName\": \"刘洋\", \"botName\": \"刘洋的机器人\"}"}
message.delta 原样外发：<function_call>```typescript\nmcp__wecom_cli__whoami({})\n```
```

三个独立缺陷，各自根因不同：

| # | 缺陷 | 根因（不是措辞问题） | 修法 |
|---|---|---|---|
| 1 | **编造邮箱** | `whoami` **只有** 姓名/机器人名，没有任何邮箱字段；提示词只禁「编造业务数据」，没覆盖「个人身份数据」⇒ 模型拿姓名拼域名，还自承「假设」 | `prompt/builder.py` 新增【个人信息红线】：只准用工具返回的**原值**；只返回一部分就只说那部分，其余必须说「我这边没有你的邮箱登记信息」；**严禁**「姓名+猜域名」拼地址、严禁「假设域名为…/以…为例」占位；并给真实入口（我的 → 个人资料 / 管理员补录）。`whoami` 描述补一句「不返回邮箱/手机号/工号」 |
| 2 | **调用原文外发** | `_rescue_textual_calls` 只负责「让调用真的执行」，**不负责把原文收回去**；deltas 早已逐片发给前端 ⇒ 用户既看到源码又真查了一遍（上一张截图 `functions.mcp__wecom_cli__recent_group_sessions({"days": 7})` 同源） | `nodes.agent` 流式分支加**暂扣+抑制**：开头像调用就先扣住（`_looks_like_call_start`，普通中文照常逐片下发，保住 delta 与上游分片一对一）；一旦命中 `_CALL_TEXT_SIG_RE` 本轮正文停止外发；收口时 `_strip_call_text` 清理后落库。只删「工具形状」调用（`functions.` 前缀或含 `__`），**`print(1)` 这种普通代码块不动** |
| 3 | **空回答死胡同** | `finalize` 只处理了「有工具调用但无正文」，**没有处理「既无正文也无工具调用」**（模型偶发返回空）⇒ 落一条空消息，前端只能显示「（本次未返回内容）」。另外 H5 只认 delta 累积的 text，完成帧里的 `content` 被忽略 ⇒ delta 断流时界面显示空、库里其实有答案 | ① `finalize` 补分支：空正文时产出**可行动**文案（「再问一次 / 说得更具体些」）并补发 delta，同时 `logger.warning` 便于统计；② H5 两处 `onCompleted` 用完成帧 `content` 兜底；③ 占位文案改为「这一轮没有生成内容，请再问一次，或把问题说得更具体些。」 |

**验收**：
- 真实界面复测（`logs/proof/pii_email.png` / `pii_qq.png`）：**5/5 PASS** —— 不编造域名、
  如实说「没有登记」、给入口、无调用原文、第二轮 138 字非空。
- 新增单测 `agent/tests/test_pii_and_empty_answer.py`（4 项）、
  `agent/tests/test_textual_call_leak.py`（7 项）；`agent/tests` 全量 **192 passed**。

**注意**：`_strip_call_text` 第一版把 `print(1)` 当调用删了（`_CALL_EXPR_RE` 太宽），
是单测 `test_keep_normal_code_block` 抓到的 —— 清理调用文本的规则必须区分
「工具形状」（`functions.x` / `mcp__a__b`）与「普通函数调用」（`print(1)`）。

### 11.5 回答溢出约束 · 顶栏固定常显 · 「工作助手」随滚动平滑显隐（2026-10-30 第四轮）

用户三条口径（截图）：① 回答文本超出答案显示区域，须约束在容器内；② **页面最顶部区域固定不动**，
滚动会话内容时始终可见；③ 「工作助手」向上滑动浏览时平滑移到顶部渐隐，**只有一直滑回最早（首次）
对话的位置才重新出现**，过渡连贯无跳变。

#### ① 回答溢出（`user-client/index.html`）

答案里的长 URL / 无空格长串不会换行，把气泡横向撑破、文字顶到容器边界被裁 —— 看起来就是
「回答超出答案区域」。修法（三层兜底）：
- `.bub` 加 `overflow-wrap:anywhere; word-break:break-word; min-width:0`（URL 任意字符处可断）；
- `.bub .tx` 加 `min-width:0; max-width:100%`（防 flex 子项撑开父容器）；
- `.dock-list` 加 `overflow-x:hidden`（横向一律不出坞）。
代码块（`.ans-code` 已是 `pre-wrap`）与表格（`.ans-table-wrap` 自带横向滚动）不受影响。

#### ② 顶栏固定常显（**撤销第二轮的 bar-hidden**）

第二轮做过「上滑隐藏顶栏 + 背景透明」，用户实测后改为：顶栏在 flex 布局里本就不随对话坞滚动，
**恒定可见** —— `#oaRoot.bar-hidden` 的 CSS 与 JS（`oaSyncDockFade` 里的 toggle、
`oaSetChatting`/`oaGo` 的清理）整体删除。哨兵第 9 组改为断言「浏览中顶栏仍可见、
且 top 与 oaRoot 顶对齐（≤2px）」。

#### ③ 「工作助手」标题随滚动平滑显隐（判据从「离底距离」改为 **scrollTop**）

上一轮「离底 >24px 就隐、回底就现」在长会话里随手一滚就瞬跳/瞬现（用户报「不细滑」），
且「回到最新」也弹回标题，与「只有首次对话才出现」冲突。新模型：

```
t = clamp(scrollTop / OA_SMOOTH, 0, 1)     # OA_SMOOTH = 120
--hd 写在 #v-home 上，CSS 端 calc 连续插值：
  .assist{ opacity:calc(1 - var(--hd)); transform:translateY(calc(var(--hd) * -30px)) }
```

- scrollTop=0（**首次对话**/空会话）→ 标题完整可见；
- 往下浏览（scrollTop 增大）→ 120px 内连续上移 + 渐隐，**中间保持隐藏**；
- 只有滚回 scrollTop≈0 才重新出现（记录很多时必须一直滑回最早那条）。

两个刻意设计：① 只动 `.assist`，数字人（`.stage`）是会话锚点**保持常显**；
② 不收 `.assist` 高度 —— 收高度会让 dock 变高、滚动位置跳（与数字人同理），
渐隐后 `pointer-events:none` 防隐形标题拦点击。`dock-scrolled` 语义收窄为
「标题已完全隐去」（t≥0.99），供 pointer-events 与哨兵用；`oaSetChatting(false)` 时
清 `--hd`（dock 已清空、scrollTop 归零，标题必须回来）。

**验收**：`_verify_h5_inputbar.py` 第 8/9 组按新口径重写 + 新增第 10 组（溢出）→ **58/58**；
`_syntax_h5.js` 0 错误；`_check_oa_project_layout.py` 14/14。
关键实测值：半程 `--hd=0.500 / assist opacity=0.5`（连续插值非瞬跳）；中间静置 1.5s 不弹回；
顶端 `opacity=1`；顶栏恒 52px 且 top=0；长 URL 气泡 `scrollWidth==clientWidth` 无横向溢出。
