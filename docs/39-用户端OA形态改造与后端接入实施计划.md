## 2. 架构决策：并入 `index.html`，不新建文件

### 2.1 否决「新建 `oa.html`」的决定性证据

`deploy/Dockerfile.server` L28：

```
COPY user-client/index.html /out/h5/index.html
```

生产镜像**只拷 `index.html` 这一个文件**（H5 是自包含单文件，零构建）。若新建 `oa.html`：
- 必须改 Dockerfile 增拷文件；
- 数字人位图必须内联（原本已内联）否则 `assets/*.webp` 404；
- 网关 `/user` → `/aioa/h5/` 改写规则（`deploy/生产部署手册.md` L255）需重新核对多文件场景。

⇒ **收益（代码隔离）小于成本（部署面扩大 + 回滚变复杂）**。

### 2.2 采用方案：同文件双形态

```
index.html 单文件
├── :root 令牌（既有品牌蓝）
├── [data-mode="oa"] 覆盖：--brand:#12b39a 等
├── 既有视图 page-*（一行不改）
├── 新增视图 page-oa-home / page-oa-task / page-oa-kb / page-oa-dept（新增 id，不覆盖）
├── 既有 tabbar（classic）
└── 新增 tabbar（oa）：首页 / 任务 / 知识库 / 部门 / 我的
```

**改动面收敛为 3 处**（其余全是新增）：
1. `go()` / `switchTab()` / `setTitle()` 增加 mode 分支；
2. 两个 tabbar 的显隐（`data-mode` 控制）；
3. 「我的」页新增「界面版本」分段控件（调用 `setMode`）。

`state` 增加单字段 `mode:'classic'|'oa'`，持久化到 `localStorage.aioa_mode`（与既有 `aioa_session` 同一存储域，刷新不丢）。

### 2.3 为什么不动既有视图

`index.html` 4806 行承载全部已验收业务（审批双引擎、请假、权限申请、投诉建议、账单、成果、Gitee…）。OA 形态**只做新增与分流**，保证：
- 经典形态回归面 = 「切换开关 + tabbar 显隐」两处；
- 出问题可一键切回经典形态，业务不中断。

## 5. 关键交互：数字人锚点对话（用户第 5、6 条口径）

### 5.1 为什么不复用 `page-chat`

既有 `page-chat` 是**整页会话**（`flush` 满屏，tab 切走才回来）。用户要求「就在对话框里对话，**不能跳到其他地方**」，且气泡要指着数字人 —— 这是**首页内的对话坞**，与整页会话是两种形态。故：
- 对话坞复用 `API.stream` 的**同一套 SSE 处理**（把 `page-chat` 的流式渲染抽为 `renderStreamInto(target, ...)`，两处共用，避免两套口径）；
- 对话坞独立 `state.oaConvId`，与 `state.conversationId` 分账，互不干扰。

### 5.2 交互链路（全部留在首页）

```
点击数字人
  └─ 底部选择卡（数字员工 / 专家 两个分段）
       ├─ workers()  → 选中 → setOaWorker(w)
       └─ experts()  → 选中 → setOaExpert(e)
  └─ 选择卡收起 → 对话坞展开（数字人仍在首页原位）
       └─ 输入 → ensureOaConversation() → createRun → stream
            └─ 气泡逐字流式出现在数字人下方（全程不离开首页）
```

### 5.3 气泡三角朝向算法（「都对着数字人」）

数字人是**坐标锚点** `A(x_A, y_A)`（首页居中偏上）。每个气泡矩形 `B`：

```
cx = B.left + B.width/2      // 气泡中心 x
cy = B.top  + B.height/2     // 气泡中心 y
dx = x_A - cx ,  dy = y_A - cy
θ  = atan2(dy, dx)           // 气泡中心 → 数字人 的方向角
```

三角沿「气泡中心 → 数字人」射线与气泡矩形边框求交点，落位于该边，并绕自身中心旋转 `θ - 90°`（三角基准朝上）：

```
t = 三角自身中心到气泡中心的距离        // 由气泡尺寸决定
tail.angle = θ - Math.PI/2
```

CSS 侧用两个变量承载，避免 JS 逐帧算布局：

```css
.bub{ position:relative }
.bub .tail{
  position:absolute;
  left:var(--tail-x); top:var(--tail-y);
  transform:translate(-50%,-50%) rotate(var(--tail-angle));
}
```

**实现时序**：气泡插入 → `requestAnimationFrame` 量测 `robotRect` / `bubbleRect` → 写回 `--tail-*`。滚动 / 尺寸变化 / 流式追加时重算（`ResizeObserver` + 节流）。

**降级策略**（必须实现，否则极端情况会错位）：
1. `prefers-reduced-motion: reduce` → 关闭数字人 `r-bob`/`r-sway`，三角仍按公式定位（静态仍正确）；
2. 视口过窄（< 360px）或气泡与数字人重叠 → 退化为**三角恒朝正上方**并居中，保证可读；
3. 数字人因滚动离开视口 → 退化为**sticky 顶部头像**，三角仍指向该头像（几何关系不变）。

### 5.4 气泡对齐口径

按用户口径「**都**对着数字人」，故**不采用** IM 常规的左右分侧（AI 左 / 用户右），而是：
- 全部气泡沿数字人下方**纵向单列**排布；
- 三角统一收敛指向数字人 —— 视觉上是「从数字人放射出的对话流」。

若后续希望区分角色，用**底色 + 左侧竖色条**区分，不改三角朝向（`--brand` 底 = AI，`--surface-3` 底 = 用户）。

### 6.2 「新工作任务」= 派活给数字员工

链路：`workerIntent(自然语言)` → 推荐员工 → `ensureConversation(workerId)` → 首条 `createRun`。

- 与首页对话坞同源，不产生第二套会话口径；
- 未选「发起审批/请假」：那两者需要跳转到既有表单页，与「不跳转」口径冲突；
- 未选「创建数字员工」：属管理能力，普通员工无权限。

### 6.3 部门页手机号 / 邮箱：默认隐藏

后端对 `ROLE_MEMBER` 也返回 `mobile` / `email`，但**不因此就在界面上平铺**：

- 列表只显示 姓名 / 职务 / 部门 / 工号（`employeeNo`）；
- 手机号与邮箱需点击「查看」才展开，且**不写入浏览器存储**；
- 判据：接口返回「可读」≠ 界面应当「默认可见」。降级成本为零，反向（先平铺后收回）会引发投诉。
