## 1 新工作任务「未能识别类型，请手动选择」

**现象**：在「新建任务」里输一句话，提示「未能识别类型，请手动选择数字人或专家」，永远跳不到对应数字人。

**根因**（编码错配，不是识别能力不足）：
意图接口 `POST /v1/workers/intent` 返回的是 **角色码**，全项目只有 4 个
（`GENERAL` / `LEAVE_APPROVER` / `KB_ASSISTANT` / `DOC_DRAFTER`，见 `WorkerRole`）；
而 OA 模块数字员工的 `worker_type` 是 **模块码**（`OA_LEAVE` / `OA_DOC` / `OA_APPROVAL` …
共 43 个，见 `V83`）。`oaNewTask` 原来直接做

```js
String(w.workerType).toUpperCase() === String(intent.role).toUpperCase()
```

两套编码相等 ⇒ 43 个模块一个都撞不上。同一份映射早在 2026-11-04 就为
「对话里说『我要请假』」修过（`oaApprovalLaunchTarget` 里的 `formCode → OA_*`），
但「新工作任务」这条入口**没有跟着改** —— 典型的「一处修了、另一处漏了」。

**改法**（三层，判断只留一处）：
1. 抽出 `oaIntentCodes()` / `oaMatchIntentWorker()`，两个入口共用（铁律 1）。
   候选码优先级：`role` 原样 → `formCode → OA_<FORM>` → 去掉 `_APPROVER/_DRAFTER` 等后缀再补 `OA_`。
2. **服务端补候选**：`WorkerIntakeService.intent()` 新增 `workers` 字段
   （`[{id,name,workerType,score}]`，按本租户真实在册清单打分）：
   - 类型直译 100 分（`LEAVE_APPROVER → OA_LEAVE`，与前端同一套规则）；
   - 名称关键词 10 分（剥掉「数字人/助手/管理/中心」后的核心词 + 词尾 2 字，出现在用户句子里即命中）；
   - 同分时 `OA_*` 模块 +1（本环境有自建员工 `worker_type=GENERAL` 叫「每日考勤」，
     会和「考勤管理数字人」同分，不能让自建员工抢走）。
   "哪句话像哪位员工" 属于业务判断，只该在服务端算一次。
3. 前端只判「**唯一最高分**」才跳；并列或 0 分一律**不猜**，改为把用户带到数字员工列表，
   并把他刚打的那句话记下来（`setPendingTaskText`），选完人自动填回输入框。

**两个必须记住的坑**（本次实测踩到并修掉）：
- `GENERAL` 是「没识别出专用类型」的**缺省值**，不是可命中的类型码。把它当候选去精确匹配，
  任何一句识别不出来的话都会被派给 `worker_type=GENERAL` 的自建员工
  （实测：「今天天气怎么样」→ 派给「每日考勤」）。故 `GENERAL/OA_GENERAL` 一律不进候选。
- 同理，通用类型的 `roleName` 也是「通用办公助手」这个缺省值，不能当关键词信号。

**验收**（真实接口 + 真实员工数据，不 mock）：

| 输入 | 意图返回 | 结果 |
|---|---|---|
| 我要请假三天 | `LEAVE_APPROVER` + `leave_request` | 请假助手数字人（`OA_LEAVE`，111 分） |
| 帮我起草一份通知 | `DOC_DRAFTER` | 公文助手数字人（`OA_DOC`） |
| 查一下公司制度 | `KB_ASSISTANT` | 知识库问答数字人（类型精确命中） |
| 考勤异常怎么申诉 | `GENERAL` + 无 matched | 考勤管理数字人（关键词 11 分 > 每日考勤 10 分） |
| 帮我订个会议室 | `GENERAL` | 会议助手数字人 |
| 今天天气怎么样 | `GENERAL` | **不乱派**，弹选择浮层并保留原句 |

## 2 「我的」四个统计不可点

`renderMe()` 的 `oaMeData` 原先只是四段静态文字（数字有了，却无处可去）。现在每项都是入口：

| 统计 | 落点 |
|---|---|
| 待办 | `collab` + `S.rail='tasks'` |
| 审批 | `collab` + `S.rail='approvals'` |
| 会话 | `recent` |
| 知识库 | `kb` |

注意 `collab` 的四个面板靠 `S.rail` 选，**必须先设导轨再 `oaGo()`**，否则跳到协同页仍停在默认「任务」。
样式上只加按下反馈（`.me-stat:active`）与 `-webkit-tap-highlight-color: transparent`，
不新增图标、不改四列网格 —— 视觉与「纯文字」保持一致。

## 3 时间填写要日期时间选择组件

全库自查结果：表单引擎（`x-type: datetime → datetime-local`）、请假起止（`type=date`）、
提醒到期（`datetime-local`）、周报时间（`type=time`）**都已经是原生控件**，
只剩「新建日程」的 `#scStart/#scEnd` 是纯文本框 + `placeholder="2026-10-31 14:00"`
（手机上要手敲 16 个字符，还常被中文输入法塞进全角字符）。

改法：
- `type="datetime-local"`；取值是 `yyyy-MM-ddTHH:mm`，后端 `PortalService.parseTime`
  已把 `T` 归一成空格（两种写法都收），前端不再自己拼/校验格式；
- 预填「下一个整点」（本地时区拼串，不经 UTC 换算），打开就落在合适位置；
- 本地拦下「结束早于开始」（两个控件的值同为定长同格式，可直接字符串比大小），不发请求。

实测：用控件建的日程落库为 `2026-11-08 09:30:00 / 10:15:00`，端到端正确。

## 4 OA 模块按功能归纳

43 个模块原先平铺在 3 列宫格里，找东西只能扫，也看不出「报销归财务、请假归人事」。
现在按 `worker_type` 分成 8 组 + 1 个「快捷入口」（打卡）：

办文办会（7）· 日常办公（9）· 审批与督办（4）· 人事与考勤（7）·
财务与资产（7）· 项目与客户（3）· 知识与数据（2）· 平台与安全（4）

- 分组表 `OA_MOD_GROUPS` 以模块码为准，加模块只需补一行；
- **未登记的模块不丢**：落到末尾「其他」组（当前为 0 个，说明 43 个全覆盖）；
- 组内顺序仍按 `sourceTemplateId`（与《OA系统功能清单》一致），不按字母排；
- 每组标题右侧等宽数字给出数量，扫一眼可比。

## 5 手机键盘把底部导航顶上去

**根因**：Android / 微信 WebView 弹键盘会**连 layout viewport 一起缩**，而页面是
「顶栏 + 内容 + 底栏」的 flex 列布局 ⇒ 底栏被压到键盘正上方，还挤掉一截内容。

**改法**：复用已有的键盘判据（`oaBindKeyboardSafe` 里 `visualViewport` 与 `innerHeight`
的差值，>80px 才算），顺手 toggle `body.kb-on`，CSS 一条规则：

```css
body.kb-on .tabbar{ display:none !important }
```

- 判据挂 `body` 而**不是** `#oaRoot`：经典形态的 `.tabbar` 与新版的 `#oaTabs` 是同一个位置上的同一个问题，一份规则两种形态共用；
- 只切 class、不写内联样式，键盘一收立刻恢复，不记忆状态；
- iOS 上底栏本来就在键盘后面，收起它不改变可见结果。

## 顺带修掉的一条陈旧断言

`scripts/e2e_p0a_worker_intake.py` 里两处写死「六项检查」：接口其实已返回 **7 项**
（第 7 项 `DECLARED_CAPABILITY`「声明的能力自检」是后续加的），这条一直报红但与业务无关。改法不是放宽，而是**更严**：
- 核心六项断言 `keys[:6] == [...]`，第 7 项只允许 `[]` 或 `['DECLARED_CAPABILITY']`（缺项/乱序/未知项仍红）；
- 渲染行数改为**问接口要**：`len(rows) == len(precheck.checks)`，不再是魔法数字 6。
