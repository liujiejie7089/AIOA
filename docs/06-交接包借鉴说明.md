# 交接包借鉴/裁剪对照说明（V1.0）

本仓库借鉴《E:\WORK\左老师设计\开发者交接包》中 AIOA 平台（五域 41 实体 / 六横两纵）的架构思想，但目标场景不同：交接包面向"地级市政务公共服务平台 + 小程序（Python AgentScope + uni-app）"，本基座面向"公司内部 AI OA（Java + Vue + Python agent）"。

## 1. 借鉴的思想

| 交接包思想 | 本基座落地 |
|---|---|
| Agent Runtime 感知-规划-执行-反思 | LangGraph StateGraph 主循环（M2） |
| HITL 审批卡点 | hitl_approval 状态机 + 审批中心（M3） |
| 工具沙箱 + 权限白名单 | 中间层工具注册表 + 工具×角色授权（M2/M3；不做代码执行沙箱） |
| 三层记忆 | 一期只做短期会话记忆；agent_memory 留表预留 |
| 统一模型网关 + 词元计量 | model_gateway 双模式切换 + token_usage 只计量不计费 |
| 台账审计（哈希链防篡改） | audit_log + prev_hash/hash（M3） |
| P0 实体牵引、PoC 门禁方法论 | M1–M4 里程碑硬门禁 |
| 多租户三级隔离 | 降级为全表 tenant_id 预留（公司内部单租户起步） |

## 2. 裁剪掉的内容

- 商业域：会员/套餐/支付/订单/账本/资源池/专家市场/开放端门户——非公司内部场景。
- 协同域重资产：项目/计划/里程碑/文档/表单/会议/看板——本基座定位"给既有业务系统赋能"，不重建 OA 业务。
- 小程序端（uni-app）：改为 PC Web 工作台 + 微前端。
- 等保三级/信创（达梦/openGauss/麒麟）：降级保留扩展点（AuthProvider、数据源适配层），一期不强求。
- 实体规模：41 实体 → 一期约 26 张表（M1 先 15 张）。

## 3. 口径差异说明

- 交接包的"连接器"≈ 本基座的 tool_system + tool_definition（中间层工具注册表）。
- 交接包的"专家"≈ 本基座的 agent_definition（子 agent 配置化）。
- 交接包的"审批实体"≈ 本基座的 hitl_approval。
- 交接包的"台账"≈ 本基座的 audit_log；"账本"裁剪为 token_usage（只计量）。
