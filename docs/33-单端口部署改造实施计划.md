## 1. 目标

把线上入口从「边缘 nginx 双端口 + 静态外置」收敛为 **aioa-server 一个端口（:8080）同时提供 H5 / 管理端 / 接口**，
并用 `/aioa/` 统一前缀把三者挂在同一个域名下；同时把 **Ollama 从部署组成里彻底摘掉**（该项已在前序批次完成取值口径收敛，
本计划只处理部署件残留）。

三条验收线：

| 线 | 判据 |
| --- | --- |
| L1 入口唯一化 | `:8080` 一个端口能同时打开 `/aioa/h5/`、`/aioa/web/`、调通 `/aioa/api/v1/**`；不需要任何 nginx |
| L2 零回归 | 既有 58 个 `scripts/*.py` 套件在本地 `:8080` 直连**不改一行**仍全绿 |
| L3 部署件自洽 | `compose-lint.py` 0 错 0 警；`docker-compose.yml` / `ops/*.sh` / `.env*` / 手册里 **Ollama 与 nginx 相关项全部消失或标注为历史档** |

**为什么需要 `/aioa/` 前缀**：目标入口是与其它系统共用的域名（`mall.egoaicloud.com`），AIOA 拿不到根路径。
⇒ H5 不能假设自己在 `/`，接口也不能假设自己在 `/api`。

## 2. 现状（实测，非推断）

### 2.1 入口现状：两档并存

| 档 | 组成 | 静态谁托管 | 现状评价 |
| --- | --- | --- | --- |
| A 完整档 | `nginx` + `web` + `server` + `agent` | 边缘 nginx：80=`root /usr/share/nginx/html/h5`；81=`proxy_pass http://aioa_web` | 需多搬 2 张镜像（`nginx:1.27-alpine`、`aioa-web`） |
| B 后端档（本次采用） | `server` + `agent` | **无人托管** —— 手册 §5.2 是「让用户自己的 nginx 去指 `/opt/aioa/webroot`」 | 这与用户口径「不用 nginx」冲突 ⇒ 正是本计划要消灭的缺口 |

- `deploy/nginx/nginx.conf`：两个 `server` 块（80 / 81），两块都 `include /etc/nginx/api-proxy.conf`。
- `deploy/nginx/api-proxy.conf`：`/api/` 反代 + SSE 专用 location（`~ ^/api/v1/runs/[^/]+/events$`，`proxy_buffering off`）+ `/openapi/`。
- `deploy/nginx/web.conf`：**web 容器内部**的 nginx（服务 `/` 与 `/subapps/*`），与边缘 nginx 无关。

### 2.2 后端现状：**没有任何静态托管能力**

实测（全仓 grep）：

- `server/aioa-boot/src/main/resources/application.yml`：有 `server.port: 8080`，
  **无** `server.servlet.context-path`、**无** `spring.web.resources.static-locations`、**无** `spring.mvc.servlet.path`。
- 全 `server/**/*.java` 搜 `WebMvcConfigurer` / `addResourceHandlers` / `ResourceHandlerRegistry`：**零命中**。

⇒ **「后端托管前端静态」是净新增能力，不是改一个开关。**

### 2.3 前端现状：两处「根绝对」硬编码 + 一处构建基址缺失

| 位置 | 现状 | 挪到 `/aioa/` 前缀后的后果 |
| --- | --- | --- |
| `user-client/index.html`（`const API = {` 处） | `const API = { base:'/api', ... }` —— **根绝对** | 请求打到 `https://域名/api/…` ⇒ 落到共用域名的别的系统上（404 或更糟：串到别的服务） |
| `web/apps/shell/src/api/index.ts:9` | `baseURL: '/api/v1'` —— **根绝对** | 同上 |
| `web/apps/shell/vite.config.ts` | `build` 段**没有 `base:`** ⇒ 产物里资源引用是 `/assets/…` | 管理端挪到 `/aioa/web/` 后 **JS/CSS 全部 404**（页面白屏） |

**已具备的有利条件**：H5 里 `h5BaseUrl()` **已经**按 `location.pathname` 推导自身基址，
且 V62 的深链/引导块已按 `https://…/aioa/h5/` 形态断言通过
（`scripts/e2e_v62_default_ai.py` 的 B1/B3b/B9，**按用例名索引，不写行号**——行号会随改动漂移）
⇒ 这一半的前缀适配**已完成**，只需把 `API.base` 也接到同一个推导上。

### 2.4 ★ 最大回归面：44 个套件硬编码 `:8080`

```
scripts/*.py 共 58 个；含 "8080" 的 47 个；含 ":8080/api" 或 ":8080'" 的 44 个
```

这一条直接决定了下面的方案选型。

## 3. 目标拓扑

```
                         ┌──────────── 共用域名 mall.egoaicloud.com ────────────┐
                         │                                                      │
   浏览器 ──HTTPS──►  前置（用户已有，终止 TLS / 本系统不做）
                         │
                         ├── /aioa/h5/**   ──►  ┐
                         ├── /aioa/web/**  ──►  ├── aioa-server :8080（单端口）
                         └── /aioa/api/**  ──►  ┘        ├─ 静态：H5 单文件目录
                                                         ├─ 静态：管理端 dist
                                                         └─ 业务：既有 /api/v1/** 控制器
                              /api/**（无前缀） ──►  同上（**保留**：本地直连 / 既有套件 / 现场脚本）
```

要点：

1. **`/aioa/` 前缀是新增的对外入口，而不是把旧的搬过去** —— 旧 `/api/**` 继续在根路径可用。
2. 后端**不需要 nginx**：静态与接口同一个 Java 进程、同一个端口。
3. 前端**不需要构建期环境变量**：H5 由 `location.pathname` 推导；管理端由 vite `base` 固定为 `/aioa/web/`。

## 4. 方案选型（关键决策）

### 4.1 前缀实现：`context-path` vs 「双前缀并存」

| 维度 | 甲案：`server.servlet.context-path=/aioa` | 乙案：**双前缀并存（推荐）** |
| --- | --- | --- |
| 改动量 | 1 行配置 | 1 个 Filter + 2 个资源处理器 |
| 既有 44 个套件 | **全红**（要么改 44 个脚本，要么全加环境变量） | **零影响** |
| 现场既有脚本/监控 | 全失效 | 不受影响 |
| actuator | 变成 `/aioa/actuator/health`（探活配置要跟着改） | 保持 `/actuator/health`，**另加**前缀可用 |
| 语义清晰度 | 最高（唯一入口） | 略低（两个入口并存，需在文档写清「对外只说 /aioa」） |
| 回退成本 | 回退要同步回退 44 个脚本 | 删 Filter 即回退 |

**决策：乙案。** 理由：本次改造的目的是「让部署更简单、风险更低」，甲案把风险转嫁给了 44 个既有套件与现场脚本，
与目标背道而驰；乙案让这次改造**纯增量**（additive），任一步失败都能单独回退。

实现要点（乙案）：

- 一个 `OncePerRequestFilter`：命中 `^/aioa/api(/.*)?$` 时把 `getRequestURI()` 去掉 `/aioa` 前缀后 `forward`，
  使既有 `@RequestMapping("/api/v1/**")` 原样命中；同时保证 `getRequestURI()` 语义在日志/审计里仍是**原始** URI
  （避免审计记录写成剥前缀后的路径 —— 这是易漏点）。
- 静态：`WebMvcConfigurer.addResourceHandlers` 注册
  `/aioa/h5/**` → H5 单文件所在目录（`index.html` + SPA 回退到它自身）
  `/aioa/web/**` → 管理端 dist 目录（SPA 回退 `index.html`，`/aioa/web/subapps/**` 独立回退）。
- 目录来源用配置项（默认指向容器内路径），与 compose 卷挂载一致；**不存在时不能 500**，要能给出明确 404 + 日志线索。

### 4.2 管理端构建基址

`web/apps/shell/vite.config.ts` 增 `base: '/aioa/web/'`。
- 影响：dev server 也变成 `:5173/aioa/web/`（文档与套件里的 dev 地址要同步）。
- 备选：用 `loadEnv` 读 `VITE_BASE`，默认 `/aioa/web/`，本地可覆盖为 `/` —— 更灵活但多一个键；
  **建议直接固定**，少一个可漂移维度（配置项越少越不容易出现「配了但没生效」）。

### 4.3 Ollama 摘除

- compose：删 `ollama` 服务与 `ollamadata` 卷；把 `AIOA_KB_EMBEDDING_*` 的**默认值**从 `ollama:11434` 改为**留空**
  （留空 = provider=local 时不读，与 `.env` 口径一致）；头部注释删掉 `--profile model` 那段。
- `offline-images.sh`：删 `--with-ollama` 分支与 `import-ollama`（或保留但**明确标注为历史档、默认路径不再触发**）。
  建议**直接删**——保留分支等于保留「有人以为还要拉 Ollama」的歧义。
- `host-check.sh`：镜像清单去掉 `ollama/ollama:latest`。

## 7. 风险与回退

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 前缀剥离 Filter 与安全链（JWT / `@PreAuthorize`）顺序错 | 鉴权失效或 401 误判 —— **最危险的一类** | Filter 注册顺序显式声明；单测 + 套件双覆盖「带前缀与不带前缀的鉴权结果必须一致」 |
| 审计 / 日志记录到剥前缀后的 URI | 审计失真 | Filter 内保证 `getRequestURI()` 语义不变，仅 forward 内部路径；套件断言审计记录为原始 URI |
| 管理端 vite `base` 配了但产物未重建 | 白屏 | 验收里断言「静态资源 404 数为 0」；部署件禁止复用旧 `dist`（镜像每次重建） |
| 现场仍有别的系统在用 `/api/**` 根路径 | 摘掉即断服务 | 本方案**保留**根路径 ⇒ 天然规避；文档明确「对外只宣传 /aioa」 |
| 删 `_check_nginx_conf.py` 丢失既有 7 项负向断言 | 校验退化 | 若选删除，必须把等价断言迁进新套件（不能净减） |

**回退**：乙案任一块都是增量的 ⇒ ①/② 删类与配置即回退，③ 改回字面量即回退，④ 用 `git revert` 单提交回退。
