# 模型网关规范

> 对应架构第 3/4 层的「统一模型网关」：云端大模型 API 与私有化模型双模式，
> 切换配置不改代码。实现在 `agent/app/model_gateway/`。

## 1. 一个原则

**模型是配置，不是代码分支。** 业务代码只认 `model_ref` 这个字符串，至于它指向云端
DeepSeek、通义百炼，还是内网的 vLLM / Ollama，由网关解析决定，调用方零感知。

## 2. Provider 注册表

| key | driver | 默认 base_url | 默认 model | API Key 环境变量 |
|---|---|---|---|---|
| `deepseek` | openai_compatible | `https://api.deepseek.com` | `deepseek-chat` | `DEEPSEEK_API_KEY` |
| `dashscope` | openai_compatible | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | `DASHSCOPE_API_KEY` |
| `vllm` | openai_compatible | `http://127.0.0.1:8001/v1` | `Qwen2.5-7B-Instruct` | `VLLM_API_KEY` |
| `ollama` | openai_compatible | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` | `OLLAMA_API_KEY` |
| `echo` | echo | `internal://echo` | `echo` | — |

覆盖规则（优先级：环境变量 > 管理端下发 > 内置默认）：

- `{KEY}_BASE_URL` / `{KEY}_MODEL` / `{KEY}_API_KEY` 环境变量；
- 管理端「模型管理」保存后调用 `POST /internal/v1/models/apply` 热更新（**无需重启 agent**）；
- `MODEL_DEFAULT` 决定缺省 provider。

凭据只走环境变量或 `agent/.env`（不入库）。`configured_providers()` 用于运维观测，
只暴露「是否已配置」，不吐密钥本身。

## 3. 解析（`resolve`）的降级链

```
model_ref 未指定            → MODEL_DEFAULT（默认 echo）
显式指定但未知/已禁用       → 记警告 + 回退默认（不因拼错名字就让会话挂掉）
隐式默认缺 api_key          → 静默降级 echo（保证链路始终可用）
显式指定但缺 api_key        → 原样返回，由运行时产出 MODEL_PROVIDER_NOT_CONFIGURED
```

最后一条是**有意为之的区分**：用户自己点了某个模型却没配 key，应当看到明确的错误；
而系统默认模型没配 key，不应该让整个对话功能不可用。把这两种情况统一成「降级 echo」
或统一成「报错」，都会有一半场景是错的。

## 4. 调用形态

- **流式（默认，`AGENT_STREAM=true`）**：`POST {base_url}/chat/completions` +
  `stream: true` + `stream_options.include_usage`，逐片转成 `message.delta` 事件。
  `function.arguments` 是**分片到达**的，运行时按 index 累加拼接（见
  `agent_runtime._accumulate_tool_call`）。
- **非流式（`AGENT_STREAM=false`）**：整段取回后本地切片为 delta。事件契约不变，
  仅在排查流式问题时作为对照。

## 5. 用量计量

每次 run 的 `usage`（`prompt_tokens` / `completion_tokens`）**多轮累加**后写入
`message.completed` 与 `run.completed`，由后端落 `token_ledger`，作为运营计费的计量源头。

多任务计划执行（`/internal/v1/tasks`）不经过模型推理，usage 恒为 0，不产生计费。

## 6. 新增一个 provider

1. 在 `_REGISTRY_SPEC` 加一行（key / base_url / model / api_key_env）；
2. 若协议不是 OpenAI 兼容，需要同时扩展 `agent_runtime` 的请求构造与流式解析
   （当前的 delta 解析按 OpenAI 的 `choices[].delta` 结构）；
3. 环境变量名必须可按 `{KEY}_API_KEY` 推导，管理端「模型管理」才能识别。

## 7. 验证

```bash
cd agent && python -m pytest -q                 # 网关解析与降级（含未知 ref）
curl -s http://127.0.0.1:8000/health            # 探活

```
