# 同型缺陷排查：把上一轮修的三个 bug 当作模式，扫全站（2026-11-06）

> 用户诉求（原话）：「想查找没有类似的缺陷并修复」
> —— 即把上一轮的三类缺陷当成**模式**，排查是否还有同类，并把真缺陷修掉。

## 0. 三类模式（先定义，再扫描）

上一轮修的三件事，抽象出来是三个可复用的判据：

| 模式 | 判据（怎么算"同类"） | 典型症状 |
|---|---|---|
| **A 顺序/归属** | 某个产物（卡片/动作）由"当前这一轮 run"产生，却从不校验"归不归你发" | 表单先出、人后换 |
| **B 停不下来** | `await` 住一个只在"用户点按钮"时才 resolve 的 Promise，却没有外部可解口子 | 点停止无反应、输入栏卡死 |
| **C 内部标识外露** | 把 schema 键名 / 类型码 / 内部 id 拼进用户可见文案 | `reason 为必填项`、`运行不存在：e2e-form-2` |

扫描方式：按这三条各写一组 grep（`await mount*`、`fn(){...resolve...}` 的卡片、`esc(name)` / `f.name` / `+e.message`），
**每一条都回代码读上下文确认**，不靠 grep 命中就下手。

## 2. 本轮改了什么

### C1 漏填提示（最高频，必现）

`validateForm` 拿 `data-field`（= schema 的 `name`）拼文案，而 `data-field` 是**内部键**。
漏填一个必填项，用户看到的就是 `reason 为必填项`。

新增 `fieldLabelOf(ctrl)`：从控件所在 `.lf-row` 读 `<label>` 的文案（`renderFormHtml`
已用 `formFieldLabel` 渲成人话），拿不到才回落到别名表。改完实测：

```
改前：reason 为必填项；days 为必填项
改后：请假事由 为必填项；请假天数 为必填项
```

### C2 回执键名

后端的回执契约其实是 `lines: [{label, value}]`（label 已是中文），
`fields` 是旧/兼容形态，它的 key 是字段名。旧代码 `esc(k)` 直接当标签印。
现改为：认得出别名就换人话，**认不出（纯 ASCII 键名）宁可不显示**也不抖键。
> 诚实标注：按当前后端实现，`fields` 分支基本不会走到（后端只产出 `lines`），
> 这次是防御性加固，不是修一个线上已发生的现象。

### C3 未知字段类型

提示原为「不支持的字段类型「weird_type」，已跳过」，把 schema 类型码给了用户。
改为「该字段暂不支持填写，已跳过」。

### C4 / C5 内部标识符当文案

- 权限申请弹窗：`权限：创建员工（worker:create）` → `权限：创建员工`（权限码是管理端配置用的）；
- 审批轨迹：审批人姓名为空时显示 `#12` → `未具名审批人`。

### C6 停止失败的 toast

`toast('停止失败：' + e.message)` 会把 `运行不存在：e2e-form-2` 整句甩给用户。
现走 `oaHumanRunError`，并把「运行不存在」也纳入人话映射。

## 3. 判为"不是缺陷"的三处，以及理由

不做不等于没看，逐条给依据：

- **A3 `need_clarification` / `need_confirm`**：它们是**当前这位数字人**在问自己要的信息
  （"你要请几天""确认删除吗"），归属天然就是当前人；不像 `need_form` 那样是"另一个领域的产物"。
- **B3 `askHandlers`**：弹层有「取消」按钮且绑了 `Esc`，`close(null)` 会让 `doSubmit` 直接返回，
  不存在"退不出去"。且它在**提交链路**里，不在 `await` 住的卡片循环中。
- **B4 经典形态 `send()`**：`index.html` 里 `bub-stop` 只创建了**一处**（OA 的 `oaSend`），
  经典形态根本没有停止按钮 —— 所以同款死锁没有触发入口。但这本身是个取舍：经典形态
  中断不了长回答。若要补，属于新功能而非缺陷修复。

## 5. 扫描后仍留着的问题（写清楚，不假装扫干净了）

1. **请假有两条发卡路径**：agent 不返回 `need_form` 时，`oaEmitLeaveForm` 仍会发**经典卡**。
   它没有 `await`、也就没有"可停止"通道（点取消只 toast）；且字段集（5 项，无天数）与
   后端卡（6 项）不同。彻底解法是砍掉经典卡、只留后端表单 —— 影响面涉及经典形态，未动。
2. **「请假天数」仍是必填输入框**（后端 `required` 且按值入库）。
3. **大量 `toast('X失败：'+e.message)` 没有统一人话化**（至少 10 处）。
   后端文案多数本来就是人话（"你已提交过申请"），逐个改写有掩盖真实失败原因的风险；
   本轮只处理了会把**内部 id** 漏出来的那条（C6）。要做应统一在 `API.req` 的错误构造处加一层
   "已知内部错误码 → 人话"映射，而不是散在几十个 catch 里 —— 这是独立的一轮工作。
4. **`errText(..., {withId:true})` 仍会显示 errorId**。这是有意的：报障时用户能报出 id，
   比"生成失败"有用。不属于外露，属于客服能力。
