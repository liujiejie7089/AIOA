# 72 · 模型配置项矩阵与热更新（管理端 / 用户端）· 2026-11-04

> 目标：两端（管理端「平台模型」、用户端「模型账号」）用**同一套字段、同名同义**；
> 配置**不重启即生效**；非法配置**进不来、也不会把在线配置弄坏**；历史可回滚；
> 厂家发布新模型时**只改模型名**即可调用。

---

## 1. 两端结构一致性

| 层 | 表 / 载体 | 字段命名 | 说明 |
|---|---|---|---|
| 管理端平台模型 | `model_config` | camelCase（`baseUrl`/`modelName`/`topP`…） | 一条 = 一个可调用模型（全局一份） |
| 用户端模型账号 | `model_credential` | **同名同义** | 一条 = 某人的 Key + 归属（租户隔离、可共享） |
| agent 运行期 | `Provider`（dataclass） | snake_case（`base_url`/`top_p`…） | 由上面两者推送/下发后合成 |

同一份参数在三处**范围与默认值必须一致**，改动要同时改：

1. `ModelConfigController.validate`（管理端入参校验）
2. `ModelCredentialService.applyParams`（用户端入参校验）
3. `agent/aios_ai/llm/__init__.py :: PARAM_RANGES`（运行期兜底校验）

## 2. 配置项矩阵

| 字段 | 用途 | 取值范围 | 默认值 | 生效点 |
|---|---|---|---|---|
| `baseUrl` | OpenAI 兼容接入根路径（不含 `/chat/completions`） | http(s) URL | 按厂商预设 | 请求 URL |
| `modelName` | 请求体 `model`（**换模型只改这里**） | 任意非空字符串 | 按厂商预设 | 请求体 `model` |
| `apiKeyEnv` | Key 所在环境变量名 | 环境变量名 | 按厂商预设 / `API_KEY_PLACEHOLDER` | 取 Key |
| `apiKey` | 平台填写的 Key（加密入库；用户端为密文列） | 任意 | 空 = 只用环境变量 | `Provider.api_key()` |
| `temperature` | 采样温度：越低越确定 | 0 ~ 2 | `0.30` | 请求体 `temperature` |
| `topP` | 核采样：只从概率和质量前 p 的词里选 | 0 ~ 1（**0 = 不填**） | 空（不下发） | 请求体 `top_p` |
| `maxTokens` | 单次回复 token 上限 | 0 ~ 65536（0 = 不下发） | `0` | 请求体 `max_tokens` |
| `maxContext` | 上下文窗口；>0 时按预算裁剪多轮历史 | 0 ~ 1048576（0 = 不限制） | `0` | `build_messages()` 裁剪 |
| `presencePenalty` | 话题新颖度惩罚（鼓励提新内容） | -2 ~ 2 | `0` | 请求体 `presence_penalty` |
| `frequencyPenalty` | 词频惩罚（抑制复读） | -2 ~ 2 | `0` | 请求体 `frequency_penalty` |
| `timeoutSeconds` | 单次上游请求超时 | 5 ~ 600 | `120` | `httpx` 请求 `timeout` |
| `retryAttempts` | 总尝试次数（含首次）；仅对可重试错误生效 | 1 ~ 5 | `3` | `upstream._max_attempts` |
| `streamEnabled` | 是否流式；关掉走非流式（兼容不支持 SSE 的网关） | bool | `true` | `nodes.agent` 分支 |
| `enabled` | 是否启用（停用的模型不参与路由） | bool | `true` | `_DISABLED_KEYS` |
| `isDefault` | 是否默认模型（全局唯一） | bool | `false` | 默认路由 |
| `sort` | 列表排序 | int | `100` | 管理端展示/目录顺序 |

**「0 一律不下发」的原因**：多数 OpenAI 兼容网关把 `top_p=0` 当非法参数直接 400，
把 `max_tokens=0` 当「不要输出」。所以 0 / 空 = 沿用供应商默认，而不是把 0 发出去。

### 优先级（同一参数多层配置时）

```
用户账号里显式填的值  >  平台模型配置  >  agent 内置默认（0.30 / 120s / 3 次）
```

例外：`model`/`baseUrl` 由账号整体覆盖（账号指向另一家供应商时，不应被平台地址串台）。
用户端顶部选了**平台模型**时不再 autoResolve 到个人账号 —— 否则账号里的 model 会把
用户刚选的模型盖掉（界面选 A、实际跑 B）。

## 3. 加载与刷新机制（不重启生效）

```
管理端保存
  └─ ModelConfigService.upsert()      ← 校验(400) → 快照 → 写库
       └─ push()  POST /internal/v1/models/apply  {models:[...], default}
            └─ agent apply_overrides()（两阶段：暂存态 → 原子替换）
                 ├─ _REGISTRY_SPEC   （规格：base_url/model/参数）
                 ├─ _DISABLED_KEYS   （启停集合）
                 ├─ _API_KEY_OVERRIDES（内存 Key，不落盘）
                 └─ _DEFAULT_OVERRIDE （默认模型）
```

- **全量下发**：每次推送都是当前整表，不在列表里的非内置模型会被清除（= 已删除）。
- **无重启、无进程内缓存失效问题**：下一次 `resolve()` 立即读到新注册表。
- **agent 重启后**：内存态清空 → 管理端点「同步到模型服务」（`POST /api/v1/admin/models/sync`）补推，
  不需要重新编辑保存。
- **优先级修正**：`_build_provider` 对「管理端下发过的规格」打 `_from_admin` 标记，
  此时 `{KEY}_MODEL` / `{KEY}_BASE_URL` 环境变量**让位**给界面配置。
  旧实现无条件读 env，会出现「界面改成 deepseek-reasoner，保存后仍跑 deepseek-chat」。

### 用户端（账号参数）

```
H5/前端 createRun(model_ref, credential_id)
  └─ RunService.resolveCredential()  → ModelCredentialService.Resolved（含 9 个参数）
       └─ AgentRunRequest.model_credential = {providerKey, baseUrl, model, apiKey, 参数...}
            └─ gateway.resolve(credential=...) → _apply_credential()（返回新 Provider，不污染全局）
```

账号参数**只作用于本次 run 的 Provider 对象**，不写全局注册表 —— 否则 A 的配置会污染 B 的下一轮。

**界面口径（2026-11-04 产品决定）**：
- 管理端「平台模型」弹窗：9 个参数**全部平铺**，这是管理员调优的地方。
- 用户端「配置自定义模型」：只平铺用户真正要填的 7 项（名称 / 供应商 / API Key / 接口地址 /
  模型名 / 允许共享 / 备注）；温度、top_p、max_tokens、超时、重试、流式收进**默认收起的
  「高级参数」折叠块**（原生 `<details>`，不引入 JS 状态）。
- 理由是「字段结构一致」不等于「界面都摊开」：`top_p=0`、`max_tokens=0` 会被网关当非法参数，
  普通用户填错只会把模型调坏；收起后能力仍在（数据模型不变、接口照旧接受），只是默认不打扰。

## 4. 一致性、校验与回滚

### 4.1 校验（进不来）

| 层 | 时机 | 失败表现 |
|---|---|---|
| 前端表单 | 提交前 | 输入框范围限制（min/max/step） |
| 管理端/用户端 Controller | 写库前 | **HTTP 200 + 信封 `code=400`** + 明确文案（约定见铁律 29） |
| agent `apply_overrides` | 推送时 | 逐条 `rejected`，该条**保留上一次生效值** |
| `_build_provider` | 读取时 | 非法值回落默认并记 WARN |

`apply_overrides` 是**两阶段提交**：先把整批算进暂存态，再把 `_REGISTRY_SPEC` 等
一次性替换。所以一次错误推送不会把 agent 留在「一半新一半旧」的状态。

### 4.2 一致性（看得见）

- 保存回执带 `syncState`：`SYNCED`（已热更新）/ `PENDING`（已落库但 agent 未确认）。
- 列表每行显示「热更新」标记；`PENDING` 时提示点「同步到模型服务」。
- 推送 200 但 agent 返回 `rejected` 非空 ⇒ 也按 `PENDING` 处理（不能报成功）。

### 4.3 回滚（可撤回）

- 每次写操作（保存/删除/启停/设默认/回滚）**前**落一份全量快照 `model_config_snapshot`
  （JSON，Key 保持密文原值，不产生明文），保留最近 30 份。
- 回滚 = 用快照整体替换 `model_config` + 立即推送；回滚前也为「当前状态」留快照，
  所以回滚本身可再撤回。
- 事务边界：整表替换在一个事务里完成；推送失败不回滚数据库（配置已是运营要的那份），
  返回 `synced=false` 让前端提示补推。

## 5. 「换模型只需改名称」

1. 管理端「模型管理 → 编辑」，模型名下拉里选新名字（也支持手输任意模型名）；
2. 保存 → 推送 → 下一次对话即用新模型（实测：`MiniMax-Text-01` → `MiniMax-M1`，无需重启）；
3. 新增厂商同理：类型预设会带出 `baseUrl`/`apiKeyEnv`/常用模型名候选。

预设里维护了各厂商常用模型名（`ModelConfigService.PRESETS.models`，H5 侧为 `MODEL_NAMES`），
厂家上新时把它加进候选即可，不必改代码逻辑。

> **已下线**：「回声（演示兜底）」（`echo`）按运营要求于 2026-11-04 移除 ——
> 已从 `model_config`、管理端「新增模型」类型预设、用户端平台模型目录中全部去掉。
> agent 侧仅保留 `echo` 作为**进程内最后兜底**（模型缺 Key / 全部不可用时不让整条会话失败），
> 它不再出现在任何界面与目录接口里。

## 6. 用户端顶栏「平台模型」目录

- 新接口 `GET /api/v1/model-catalog`（登录用户可读）：只返回**已启用**模型的
  `{key, name, model, providerType, isDefault}`，**不含** `baseUrl` / Key / 环境变量名。
- H5 顶栏 chip 浮层分三组：自动选择 / **平台模型**（后台配置）/ 我的账号、公司账号、共享给我。
- 平台模型与账号**互斥**：选平台模型 → 清空账号（下发 `model_ref=key`）；
  选账号 → 清空 model_key（下发 `credential_id`）。
- 选择持久化在 `localStorage`（`aios_model` / `aios_cred`）；模型被下架/停用后自动回落「自动选择」。
