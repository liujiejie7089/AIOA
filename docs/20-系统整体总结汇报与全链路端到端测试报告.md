# 第一部分 · 整体总结汇报

## 1. 一句话结论

平台的**「权限 / 审计 / 审批」三件套已经相当扎实**，第 1 项（四端权限与多租户）基本达标（≈85%），
第 6 项（数字员工申请流程）经本轮 P0-a 收口后由 58% 提升至 ≈85%；
但**「表单 / 项目 / 税务风险 / 应收账单 / 商业化」五块业务域要么只有一条腿、要么尚未建立**。
全链路 E2E 实测 **通过 150 / 150**，既有回归矩阵 **全绿（557 项断言 + 42 项 agent 单测）**，
另发现 **2 项产品健壮性/安全缺口**与 **6 项数据/前端卫生问题**（均不影响主链路闭环）。

## 10. 发现的缺陷

### 10.1 产品健壮性 / 安全缺口（本次 E2E 新发现，2 项）

| 编号 | 级别 | 现象 | 证据 | 建议 |
|---|---|---|---|---|
| **D-1** | 中（安全） | **无状态 JWT 不做服务端吊销**：调用 `/auth/logout` 返回成功并留审计，但**旧 `accessToken` 在有效期内仍可继续访问**所有接口 | S1-15：登出后用旧令牌请求 `/auth/me` → **HTTP 200** | 引入 `jti` 黑名单（Redis/表）或缩短 accessToken TTL + refresh 轮换；至少对高敏接口做二次校验 |
| **D-2** | 低（健壮性） | **路径参数类型不匹配 → 500**「服务内部错误」，而非 400/404 | S5-13：`POST /org/permissions/not-a-number/revoke` → **HTTP 500** | `GlobalExceptionHandler` 增加 `MethodArgumentTypeMismatchException` → 400 |

### 10.2 数据与前端卫生问题（6 项，不影响主链路）

| 编号 | 现象 | 实测证据 | 建议 |
|---|---|---|---|
| **D-3** | H5 成员视角每次进「待办」都会产生 1 条 **403 控制台噪音**：`user-client/index.html` L1482 对 `/api/v1/approvals?scope=todo` **无条件调用**，且该接口仅租户/平台管理员可读，仅在 `catch` 中静默吞掉 | Playwright 捕获 `403 /api/v1/approvals?scope=todo` | 按角色（`state.canApprove` / 是否租户管理员）**前置判断后再请求**，或统一走 `/workflow/tasks` |
| **D-4** | 用户端 **未提供 `favicon.ico`**，控制台每次 1 条 404 | Playwright 捕获 `404 /favicon.ico` | 补 favicon 或加 `<link rel="icon" href="data:,">` |
| **D-5** | `leave_balance` **3 行孤儿数据**：`user_id` 1536/2041/2546 在 `sys_user` 中**不存在**，且 `institution_id` 写成了**部门 id** 11/13/15（非机构 id） | SQL 左连为空：3 行 | 清理；并核查当时的写入路径（机构/部门字段错位） |
| **D-6** | `org_department` 残留 **6 条名为「越权建部门」** 的测试部门（id 46/52/58/64/70/76） | SQL 计数 = 6 | 清理由越权测试产生的残留 |
| **D-7** | `leave_type` 残留 **9 条 `V33ANNUAL*`** 测试假种（tenant 4，编码带时间戳） | SQL 计数 = 9 | 清理，避免演示时假种列表被污染 |
| **D-8** | **tenant 9（某某智能科技）无任何假种、且只有 `PERMISSION_GRANT` 一种审批流** → 该租户的**请假链路不可用**（提交必报「假种不存在」） | `leave_type where tenant_id=9` → **0 行**；`approval_flow_def where tenant_id=9` → 仅 `PERMISSION_GRANT` 1 条 | 新租户入驻时**自动播种默认假种 + 四类默认审批流**（V26 已为部分租户做过 `institution_id=0` 默认流，tenant 9 被遗漏） |

> 说明：D-5～D-7 是**演示数据卫生**问题，D-8 是**新租户初始化缺口**——
> 四者都不是代码逻辑错误，但都会在演示/验收现场直接暴露。

### 10.3 docs/19 已记录、本次复核确认的缺口（不重复展开）

业务数据读取未留痕（审计只覆盖管理配置类动作）、权限回收后在途 JWT 刷新即时性存疑、
`KpiInsightService` 的提示词工程外溢在 Java（违反「AI 业务逻辑在 Python」边界）。
