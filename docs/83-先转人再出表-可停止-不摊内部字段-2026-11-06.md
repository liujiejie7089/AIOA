# 先转到对口数字人，再出表单；填表可停止；不摊内部字段（2026-11-06）

> 用户诉求（原话）：
> 「还没转到专业数字人，表单就已经出来了，应该要先进行专业数字人，
> 还有填写表单时，无法停止，同时，内部字段不能展示给用户」

截图现场三件事叠在一起：一张《请假申请》出现在「已选择数字员工『请假助手』」**之前**；
表单填到一半想中断却停不下来；核对区把 `假种 / 开始日期 / 结束日期 / 请假天数 / 请假事由 /
证明材料 —` 整张 schema 摊给用户看，还弹了一句
`生成失败：该运行当前不是等待澄清状态（CANCELLED）`。

三条分别定位、分别修。下面每条都写了「根因不是你以为的那个」。

## 1. 表单先出、人后换 —— 根因是「谁有资格发这张表」没有闸

`need_form` 帧是**当前这一轮 run 的产出**。谁在跑这一轮，表单就挂在谁名下 ——
旧实现拿到帧就直接 `mountFormCard`，从不问「这张表归不归你发」。
于是用户在文档管理数字人里说「我要请假」，agent 照样 `request_form`，前端照样渲染，
直到下一轮 `oaMaybeLeaveAction` 才把人换过去 —— 顺序就反了。

修法：挂卡之前加一道**归属闸** `oaFormOwner(form, q)`。

- 判定来源只有服务端 `POST /v1/workers/intent`（铁律 1：不另写本地词表）；
- **不能用 `oaOnly`**：请假助手是 `LEAVE_APPROVER`，不在 `OA*` 类型里，
  带 `oaOnly` 永远匹配不到它 —— 这正是「该转的人转不过去，于是旧人先把表发了」的由来；
- 归属人 ≠ 当前人 ⇒ **这一轮不挂卡**：取消该 run → `oaPickWorker(归属人)` → 用同一句话自动重发；
- 重发后（此时已在对口人上）表单才出现，用户不用重打。

两个必须有的守卫：

| 守卫 | 为什么 |
|---|---|
| **同领域不转**（`domainOf(workerType)` 去掉 `OA_` / `_APPROVER` 后比较） | 请假有两位：523 `LEAVE_APPROVER`、1316 `OA_LEAVE`。按 id 比会 1316→523→… 来回跳，用户看到数字人自己换着玩 |
| **同一句话只自动转一次**（`S.autoResentFor`） | 两边都不认这张表时，否则会无限跳转（比顺序错更难接受） |

## 2. 填表时无法停止 —— 根因是一个 `await` 死锁，不是缺按钮

`mountFormCard` 返回 Promise，只在「提交」或「取消」时 resolve，`oaSend` 里是
`await mountFormCard(...)`。用户点「停止生成」时，`oaStop()` 只 abort 了 SSE 并 cancel 了 run，
**那条 await 还在等** ⇒ while 循环出不来 ⇒ `finally` 不执行 ⇒ **`S.busy` 永远为 true** ⇒
输入栏被永久吃掉。用户感受到的就是「停不下来」。

三处一起修：

1. 新增 `cancelFormCard()`（与既有 `cancelClarCard` 同构），`oaStop()` 里一并调用，
   把未决卡以 `null` 收掉，让 while 正常 `break`；
2. 「取消」按钮不再只是把卡片从 DOM 摘掉 —— **同时 `API.cancel(runId)`**。
   旧实现让 run 留在 `WAITING_INPUT`，用户以为取消了，之后再提交就撞上
   「该运行当前不是等待澄清状态」，界面上只剩一句看不懂的后端错误；
3. 这类状态机错误统一转人话（`oaHumanRunError`）：
   `该运行当前不是等待澄清状态（CANCELLED）` → 「这一轮已经结束（你可能刚点了取消或停止），
   再发一次就能重新开始。」

**顺带修掉一个连带 bug**：用户停止后，`oaAfterOaAnswer` 里 `held=true` 的分支会
`oaEmitLeaveForm()` 当场补发一张**经典**请假单 —— 而那时 need_form 卡刚被收走，
防重闸（按 `.leave-form` 存在判断）拦不住，于是「点了停止，屏幕上又冒出一张空表单」。
现在：`stopped` / `cancelledForm` 时**不收口**。

## 3. 内部字段外露 —— 核对面板把 schema 当清单

`formSummaryHtml` 旧口径：schema 里**每个**字段列一行。于是：

- `证明材料 —`：用户根本没填，纯噪音；
- `请假天数`：按起止日期算出来的，让用户「核对」一个自己没填过的数只会困惑；
- `假种`：schema 里的 `title`，是内部叫法；
- label 缺失时旧代码回落到 `name`，直接把 `leave_type / start_date` 这种键名印在界面上。

新口径（表单控件与核对面板共用 `formFieldLabel`，唯一一处口径）：

- 只列**用户真的填了值**的字段（空值、空数组、未勾选的 boolean 都不列）；
- 系统派生字段（`days / hours / duration / total_*`）不列 —— 只影响面板，不影响提交内容；
- 内部叫法走向人话别名（`假种 / 假别 → 请假类型`），label 缺失时显示「该项」而不是键名；
- 标题从「请核对以下信息」改成「确认提交以下内容」。

改完后的真实核对区（截图 `51-form-confirm-human.png`）：

```
确认提交以下内容
请假类型    年休假
开始日期    2026-11-30
结束日期    2026-11-30
请假事由    家里有事
```

## 4. 验收

`scripts/_verify_form_order_stop_fields.py` —— **16/16**。关键判据都不自证：

- **S1** 用 `MutationObserver` 记录「表单出现那一刻 `.oa-who` 是谁」，直接证明不是先出表后换人；
- **S4** 回库核 `chat_conversation.worker_id = 523`（不是只改了界面称呼）；
- **S7** 同一时刻只允许一张请假卡（`data-code=leave_request` 且无 `id=leaveForm`），
  防经典卡与后端卡并存；
- **T1** 停止后卡片消失 + `S.busy === false` + 停止键已摘 + 输入框可用
  （**不**拿「发送键可见」当判据 —— 它本来就随输入框有无文字显隐）；
- **T2** 真的发出了 `POST /v1/runs/{id}/cancel`；
- **F1/F3** 纯函数级 + 真实面板双证，都不含 `假种 / 请假天数 / 证明材料 / leave_type`。

回归（都动过共用面）：

| 套件 | 结果 |
|---|---|
| `_verify_leave_form_split.py` | **14/14**（新增 V2c'：页面不再出现「假种」） |

`V2c` 的判据这一轮**升级而不是放宽**：原来比「页面 label == 接口 title」，
而本轮 label 已被有意改成人话（`假种→请假类型`），拿 label 比会把「对的展示」判成红。
改成比**字段名 + 顺序**（label 可能碰巧相同，`name` 相同才真正证明页面用的是接口那份定义），
并单独加一条 `V2c'` 钉住「不再出现假种」。

## 5. 没做的（诚实记账）

- **「请假天数」仍是表单里的必填输入框**。它是派生字段，理论上应由起止日期算出；
  但后端 `form_template` 把它列在 `required` 里、提交时按值入库，前端擅自隐藏会让校验失败。
  要根治得改后端（或给字段加 `x-system` 声明并由后端回填），不在本轮范围内。
  核对面板已经不列它了（用户不会再被要求「核对一个自己没算过的数」）。
- **归属闸只覆盖有明确领域/动作的话术**。闲聊（`role=GENERAL`、`action` 空、候选为空）
  一律不转；但「领域码是 GENERAL 只靠 action 命中」的情形（如报销）依赖候选唯一最高分，
  分数弱时宁可不动。
- **自动重发会产生一条重复的「我要请假」用户气泡**。它如实反映「这句话又问了新的人」，
  没有做成静默复用 —— 静默会让对话记录看起来缺了一轮。
