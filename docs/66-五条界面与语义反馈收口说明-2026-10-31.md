## 一、问题①连接器关闭语义：从「解绑」改为「本次对话不调用」

### 1.1 原实现的问题

关闭开关时前端调用 `POST /v1/connectors/{code}/disconnect` ⇒ 对企微扫码类连接器会连带删除**本机凭据**，
下次开启必须重新扫码授权 —— 与用户表达「只是这次不调用它」的意图完全相反。

### 1.2 新语义

**只屏蔽本次对话的工具调用，不改任何持久状态**：

- 连接状态、`trusted` 标记、OAuth 授权与凭据文件 **一律不动**；
- 关闭后重新开启**无需重新扫码/授权**；
- 该语义与既有的 `kb_on`（知识库开关）**完全同构**。

### 1.3 落地链路（对话级开关通用做法）

```
前端集合 mutedConnectorCodes()
   → 顶层字段 disabled_connectors（CreateRunRequest）
   → Java RunService 合并进 context 快照（落库 + 回读）
   → agent RunRequest.disabled_connectors
   → prepare 节点按 source 过滤工具清单
   → tools 节点执行前二次拦截
```

| 层 | 文件 | 改动 |
|---|---|---|
| 前端 | `user-client/index.html` | `mutedConnectorCodes()` / `isConnectorMuted()` / `setConnectorMuted()`；经典态与 OA 态**两形态同步**；`oaToggleConnector()` 不再调 `connectorDisconnect`，改为置 mute + 确认框（文案明确「不会解绑连接器，授权仍然保留，随时可以重新开启（无需重新扫码）」） |
| Java DTO | `CreateRunRequest.java` / `AgentRunRequest.java` | 新增 `@JsonProperty("disabled_connectors")` |
| Java 服务 | `RunService.java` | `start(...)` 新增第 9 参；合并进 context 快照 `context.put("disabled_connectors", ...)`；`buildAgentRequest` 回读并回填（过滤 null/blank/trim/distinct） |
| Java 控制器 | `ConversationController.java` | 透传 `request.getDisabledConnectors()` |
| agent 契约 | `aios_ai/contracts.py` | `RunRequest.disabled_connectors: list[str] \| None` |
| agent 图 | `aios_ai/graph/nodes.py` | `_connector_of_tool_name()`（解析 `mcp__<serverCode>__<tool>`）+ `_blocked_connector_calls()`；`prepare` 按 `source` 过滤（回退解析工具名）；`tools` 节点把被拦截的调用**移出执行队列但仍回注 ok=False 的 tool 消息** |

被拦截时的错误文案：

> 该连接器在本次对话中已被关闭，未执行该调用（连接器本身未被解绑，重新开启后即可使用）

### 1.4 真机端到端验证

- Java 收到 `["wecom_cli","qq_mail"]` → 落库 context 快照（`ctx.disabled_connectors = ['wecom_cli','qq_mail']`）
- agent `effective_params.disabledConnectors = ["qq_mail","wecom_cli"]`
- 浏览器行为层：**关闭连接器不发任何 disconnect 请求**；**重新开启不触发扫码/授权**（无 `/qr`、`qr-status`、`qr-bind`、`connect/credential` 请求）

## 二、问题②录音按钮尺寸不对

### 2.1 根因

通用 `.cbtn`（确认卡的文字按钮）声明了 `flex:1 1 0px; min-width:0; min-height:36px`；
`.oa .cbtn` 只覆盖了 `flex-shrink:0`，**没有覆盖 `flex-grow`** ⇒ OA 输入栏的麦克风按钮被撑成 89px 宽的椭圆。

### 2.2 修复

```css
.oa .cbtn{
  width:34px;height:34px;min-height:0;border-radius:50%;border:0;background:transparent;
  color:var(--text-2);display:flex;align-items:center;justify-content:center;cursor:pointer;
  flex:0 0 auto;padding:0;
}
.oa .tl-act .cbtn{ width:auto; height:auto; border-radius:var(--r-sm); }
```

- 显式写全 `flex:0 0 auto` + `min-height:0`（**只写 `flex-shrink:0` 不够**）；
- `.oa .tl-act .cbtn` 单独放开宽高，否则工具条上的文字按钮会被 34px 压扁。

### 2.3 目标值说明

移动端命中区规则 `.oa .cbtn, .oa .cbtn.send{width:44px;height:44px}` 是**全局**（不在媒体查询内），
最终渲染目标是 **44×44**，不是 `.oa .cbtn` 自身声明的 34px。Playwright 实测修复后为 44×44（正方形）。

## 三、问题③「46 个插件」的来源口径

### 3.1 核数

`GET /v1/plugins` 实际返回 **64 条**（platform 6 + scfy 58），全部是管理员在管理端预置的
`tool_definition` 系统内置工具 —— 用户确实从未添加过任何插件。

### 3.2 结论与改动

数字没错，**错在命名与来源未交代**。改名与补说明：

| 位置 | 原 | 新 |
|---|---|---|
| 分段按钮 | 「插件」 | 「**系统工具**」 |
| 列表顶部 | 无 | 「共 N 项，由管理员在管理端预置（不是您添加的）；数字员工可直接调用。」 |
| 空态 | 「暂无插件…」 | 「暂无系统工具：系统工具是管理员在管理端预置的、数字员工可直接调用的能力目录」 |

## 四、问题④chat_id 无效

### 4.1 根因

`recent_group_sessions` 返回的字段名是 `ref`，而 `session_messages` 的入参叫 `chat_id`；
且 `ref` 的工具描述写着「不要向用户展示」⇒ 模型既拿不到正确字段名，又被误导不给用户看具体消息。

### 4.2 修复（`mcp-hub/mcp_hub/wecom_cli/`）

- `server.py`：`_exec_recent_sessions` 返回字段改为 **`chat_id`**（保留 `ref` 作为兼容别名）；
- `catalog.py`：`recent_group_sessions` 描述补「返回的每条会话都带一个 **chat_id** 字段 —— 要看某群的具体消息时，把它**原样**作为 `session_messages` 的 `chat_id` 入参传进去」；
  `session_messages` 描述改为「`chat_id` 必须**原样取自** `recent_group_sessions` 返回的 `chat_id` 字段（不要自己拼、不要用群名替代）」。

### 4.3 真机闭环

拿到真实 `chat_id`（形如 `wrbVcoRgAAzrx2_jz2N8UG5blijiax_Q`）**原样**喂回 `session_messages`，取回 5 条真实消息。

## 五、问题⑤OA 顶部机器人区随滚动渐隐

### 5.1 机制

沿用对话坞既有的 `--hd` 连续插值渐隐机制（`oaSyncDockFade()` 写 `0..1` 到 `#v-home` 的 `--hd`，
CSS 用 `calc()` 插值 opacity / translateY），把它扩展到顶部机器人区：

```css
.oa #v-home.chatting .stage{
  opacity:calc(1 - var(--hd, 0));
  transform:translateY(calc(var(--hd, 0) * -24px));
  transition:opacity 120ms linear, transform 120ms linear;
}
.oa #v-home.dock-scrolled .stage{pointer-events:none}
```

### 5.2 实测插值

| scrollTop | 0 | 30 | 60 | 90 | 120 |
|---|---|---|---|---|---|
| opacity | 1 | 0.75 | 0.5 | 0.25 | 0 |
| translateY | 0 | -6px | -12px | -18px | -24px |

连续插值、无跳变。**不收高度**（否则对话坞被顶走 ⇒ 滚动跳位）。

### 6.2 本轮踩的坑（已入 `topics/pitfalls.md` 坑 33–39）

1. **对话级开关通用做法**：凡「只影响本次对话、不改持久状态」的开关，统一走
   `前端集合 → 顶层字段 → Java context 快照（落库+回读）→ agent 顶层字段`（与 `kb_on` 同构）。
2. **`.cbtn` 必须写全 flex**：只覆盖 `flex-shrink` 会被 `flex-grow:1` 撑开，须显式 `flex:0 0 auto`。
3. **事件帧里没有 tool_call_id**：它只存在于图状态 messages 里 ⇒ 断言直接调 `nodes.tools(state)`。
4. **`patch.object` 绑定方法多传 self**：假函数签名要写成 `async def invoke_mock(self, name, arguments=None)`。
5. **`--hd` 写在 scroll 事件监听器里**（`oaSyncDockFade` 是 IIFE 内函数、不挂 window ⇒ 不能直接调）；
   滚动容器是 **`#oaDockList`**（`#oaDock` 只是外壳）；且要先给 `#v-home` 加 `.chatting` 否则 `.dock` 是 `display:none`。
6. **用户报计数要去接口核来源**：报 46、实测 64 —— 数字没错，错在命名与来源未交代。
7. **上下游字段名必须同名**：`ref` vs `chat_id` ⇒ 模型拿不到值。
8. **e2e 要用带 pymysql 的解释器**：系统 python 缺 ⇒ 脚本里「回库核对」被**静默跳过**（会误读成全绿）。
9. **`mcp_hub_enabled` 默认 false**：MCP 工具不进清单 ⇒ 单测假红，须 monkeypatch 成 True。
